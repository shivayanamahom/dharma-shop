# Dharma Shop — задание для нового чата

Прочитай этот файл целиком, потом `/Volumes/Work/Joomla/Radical mart/Анализ RadicalMart и план своего магазина.md` (разбор RadicalMart и варианты). Отвечай пользователю по-русски. Рабочее название проекта «Dharma Shop», название и префиксы (`com_dharmashop` и т. п.) можно обсудить и поменять на этапе 0.

## Цель
Свой универсальный лёгкий e-commerce для Joomla 6+ (PHP 8.1+) в виде **базового компонента + расширений**, как RadicalMart, но свой. Поставил базу — сразу есть сайт-каталог с корзиной (список, фильтр, карточка, мета-товары, поля, корзина, заявка/заказ, письма). Всё остальное подключается плагинами, модулями и отдельными компонентами (оплата, доставка, типы полей, экспорт/импорт, аналитика, интеграции). Причина: не платить лицензию за каждый сайт; RadicalMart скоро станет платным.

## Правила (подтверждены пользователем)
1. **Не плагиат.** Из кода RadicalMart (GPL, `/Volumes/Work/Server/www/dharmatest/{administrator/,}components/com_radicalmart` и плагины) не копируем ни строки, ни структуру файлов и имён. Изучать можно поведение, меню админки и схему данных как справку. Свой авторский знак «Dharma», своя схема БД и свои имена событий.
2. **100 % нативный интерфейс Joomla:** формы только из Form XML (subform, showon, uitab, searchtools, toolbar, системные сообщения), без собственного JS/CSS в админке. На сайте: Bootstrap 5 и переопределения в шаблоне, минимум своего JS, стили на переменных темы `--dharma-*` (шаблон `dharma_starter` на базе Cassiopeia).
3. **Расширяемость:** всё, что не нужно каждому магазину, выносится в плагины/модули/компоненты. В ядре только базовые события и точки расширения.
4. Скорость и масштаб с первого дня: цена, остаток и значения полей в **настоящих индексируемых столбцах и таблицах**, а не только в JSON (в RadicalMart JSON-столбцы и `JSON_CONTAINS` — главный риск на большом каталоге).
5. Перенос данных с RadicalMart: отдельная консольная команда читает таблицы `#__radicalmart_*` и заполняет новые. Совместимость по данным, не по коду.
6. **Рабочий тестовый сайт проекта: https://test.test (`/Volumes/Work/Server/www/test`).** Это чистый Joomla 6.1.4 с шаблоном `dharma_starter`, без RadicalMart. Другие сайты (spargo.test, dharmatest.test, argo и др.) не менять без прямой просьбы; dharmatest.test с установленным RadicalMart 3.0.27 используем только для чтения (справка по меню админки, данные для теста переноса, файлы RM для изучения поведения).
7. GitHub-репозиторий создавать только после вопроса пользователю (приватный).
8. Документация для других ИИ: README, docs/ARCHITECTURE.md, docs/DEVELOPMENT.md, как в проектах `dharma_rm_export`, `dharma_rm_import`, `dharma_calc`.

## Окружение
- Joomla 6.1.4, PHP 8.4/8.5 (в Kettle у `test.test` версия PHP «active»), локальный сервер Kettle (Apache + MySQL). **Проектный сайт: https://test.test**, файлы `/Volumes/Work/Server/www/test` (чистая установка, виртуальный хост уже есть). Справочный сайт с RadicalMart 3.0.27: https://dharmatest.test (`/Volumes/Work/Server/www/dharmatest`, база `dharmatest`, копия spargo.test, на нём также наши пакеты экспорта/импорта и модуль калькулятора) — только читать.
- Скрипты для разработки (консольный запуск Joomla на тестовом сайте, установка zip, вход в админку по HTTP, доступ к базе) лежат в `/Volumes/Work/Joomla/Radical mart/Импорт-Экспорт/dharma_rm_export/dev/` (boot.php, install.php, db.sh, web-login.sh, sync.sh); переиспользуй и скопируй в `dev/` нового проекта. Путь к сайту задаётся переменной `DHARMA_SITE` (для проекта: `/Volumes/Work/Server/www/test`; по умолчанию в старых скриптах стоит dharmatest, поменяй), логин/пароль тестового пользователя — переменными окружения, секреты в репозиторий не кладём. В `configuration.php` напрямую не лезь за паролями: консольный запуск Joomla читает их сам.
- Уже готовые наши расширения (можно брать идеи и архитектуру, это наш код): `dharma_rm_export`, `dharma_rm_import` (пакеты экспорт/импорт, CSV/XLSX/YML, планировщик Joomla), `dharma_calc` (модуль калькулятора), все под `/Volumes/Work/Joomla/`. Уроки по Joomla 6 записаны в их docs.
- Подводные камни: Joomla выводит `$option` из пространства имён (задавай `protected $option`); у HtmlView 6.1 нет `getApplication()`; в CLI `live_site` попадает в маршруты; пакет должен быть из вложенных zip, иначе тип не определится; пустые папки в манифесте ломают установку; Apache (Kettle) надо перезапускать после нового виртуального хоста.

## Что берём за основу набора возможностей (меню RadicalMart пользователя)
Заказы · Корзины · Покупатели · Товары · Мета-товары · Категории · Порядок товаров · Поля · Группы полей · Статусы заказов · Способы доставки · Способы оплаты · Аналитика · Настройки.

- **Плагины:** новые типы полей, способы доставки (СДЭК, самовывоз…), оплата, уведомления (почта, Telegram), «заявка вместо оплаты», связанные товары, ресайз картинок, карта сайта.
- **Модули:** категория/категории, поиск, фильтр, корзина, популярные.
- **Отдельные компоненты:** экспорт/импорт (адаптировать наши), аналитика, интеграции (1С, YML).

## Решения пользователя (не переспрашивать)
- Это **универсальный продукт для будущих сайтов**, а не замена конкретного сайта. Размер каталога не должен иметь значения: схема и запросы рассчитываются на 100 и на 100 000+ товаров одинаково хорошо (индексы, пагинация по ключу, без выборок из JSON при фильтрации и сортировке).
- Онлайн-оплата, доставка, «заявка вместо оплаты», уведомления, типы полей и всё прочее подключается **плагинами** по необходимости; в ядре только точки расширения и базовая логика заказа.
- Число сайтов и функции RadicalMart на боевых сайтах значения не имеют: ориентир — меню RadicalMart выше как набор разделов.
- Не решено, решить с пользователем на этапе 0: название проекта и префиксы; многоязычность (по умолчанию закладываем готовность к многоязычности Joomla, без отдельной своей системы переводов).
