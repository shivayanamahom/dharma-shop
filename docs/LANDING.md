# Посадочные страницы (подборки) — архитектура и план (C85, ПРИНЯТО)

Статус: **план**, код не написан; решения пользователя по §11 получены 2026-10-09 (название «Посадочные страницы», фильтр + ручной список, редирект и оформление — настройками). Источник: запрос пользователя 2026-10-09 («отдельный компонент-сущность: результат фильтра в меню, у каждого — картинка, описание, полный текст, полноценная SEO-страница»; форма — отдельная сущность подтверждена). Зависит от фильтра (`docs/FILTER.md`, C84, этапы F1–F3 выполнены); реализация — после F7 (SEO фильтра).

## 1. Цели и границы

1. Любое состояние фильтра (категория + условия полей, цены, бренда, бейджей, наличия) можно **сохранить как страницу** со своим адресом, пунктом меню и собственным содержимым.
2. Страница — полноценная SEO-страница: заголовок, картинка, краткое и полное описание, мета-данные, дополнительные поля, хлебные крошки, структурированные данные, карта сайта.
3. Список товаров на странице строит **тот же код, что и фильтр** (`FilterQuery`, `FilterPlanner`, `productsQuery()`): скорость и поведение сортировки, пагинации, AJAX — общие. Отдельной «копии каталога» нет.
4. Размер каталога не имеет значения (требование проекта): никаких предрассчитанных списков товаров страницы; только сохранённые условия.
5. **Источник товаров (решение пользователя):** фильтр, ручной список или оба вместе (§3, §5). Не цели: мета-товары, динамические правила вне фильтра (по датам, по остаткам — только если их умеет сам фильтр).

## 2. Решение о форме (ПРЕДЛОЖЕНО)

Отдельный пакетный компонент **`com_dharmashop_landing`** (рабочее имя; пользователь может переименовать: «Подборки», «Витрины»), собственная таблица, собственные админские представления, зависимость от `com_dharmashop` (проверка при установке). Причины: не нужное каждому магазину — вне ядра (правило проекта); у сущности свой жизненный цикл; выключение компонента не ломает каталог.

Что берёт из ядра (без копирования кода): `Administrator\Filter\*` (состояние, запрос, определения, предрасчёт), `ShopServices` (цены, изображения, макеты), контексты изображений, SEO-разрешитель (`Site\Support\Seo`, как у категории/бренда), форму допполей (`FieldValues`, `EntityFields`, цель `landing`), `MoneyFormatter`.

Альтернатива (отклонена как основная): виртуальная категория внутри `com_dharmashop` через дерево `#__categories` — смешивает сохранённое условие с деревом каталога, ломает счётчики и каноническую модель «товар → категории».

## 3. Модель данных

Таблица `#__dharmashoplanding_pages` (имя уточняется):

| Столбец | Назначение |
|---|---|
| `id`, `title`, `alias` (уникален), `state` (опубликовано/снято/корзина), `access`, `ordering`, `created`, `modified`, `created_by` | обычная служебная часть Joomla |
| `catid` | категория-источник: товары берутся из неё и её подкатегорий; `0` — весь каталог |
| `source` | источник товаров: `filter` (по условиям), `manual` (ручной список), `both` (ручные сначала, затем остальные по условиям) |
| `conditions` | сохранённое состояние фильтра (при `source = manual` не используется): JSON `FilterState::toArray()` (по **алиасам** полей/значений, брендов, бейджей — как в адресе фильтра). JSON здесь допустим: таблица только хранит условия, на пути витрины JSON-функции не используются — условия разбираются в PHP |
| `conditions_hash` | `sha1` канонического вида (`FilterState::key()` + `catid`): быстрый поиск «есть ли посадочная страница с этими условиями» для canonical; индекс |
| `sort`, `product_view` | сортировка и вид по умолчанию |
| `image`, `image_alt` | картинка страницы |
| `introtext`, `fulltext` | краткое и полное описание (редактор Joomla, фильтрация текста штатная) |
| `meta_title`, `meta_description`, `robots`, `canonical` | SEO; пусто — разрешитель берёт шаблон из настроек (как у категорий) |
| `broken` | страница «устарела»: условие ссылается на удалённое поле/значение (пересчитывается при сохранении поля/значения и командой обслуживания) |
| `params` | прочее (показывать ли фильтр на странице, показывать ли подкатегории, число товаров и т. д.) |

Ручной список — таблица `#__dharmashoplanding_products (landing_id, product_id, ordering)` с первичным ключом `(landing_id, product_id)` и индексом `(landing_id, ordering)`: порядок задаёт администратор, при удалении товара строка удаляется (событие/внешний ключ-аналог); при снятии товара с публикации он просто не выводится (состав задаёт `productsQuery()`).

Допполя — общие `field_values` с целью `landing` (как у категорий C50/C59: отдельные хранилища с `landing_id`, **не** в `product_id`); поле назначается страницам в определении (`target = landing`). Поля из фильтра в условия не попадают автоматически.

Индексы: `uq_alias`, `idx_state_access_order`, `idx_hash`, `idx_cat`. Многоязычность не нужна (одноязычный магазин).

## 4. Адреса, меню, маршрутизатор

- **Тип пункта меню** «Посадочная страница» (выбор страницы из списка) и «Список посадочных страниц» (карточки страниц, как список категорий/брендов).
- Адрес страницы: адрес пункта меню; без меню — `/подборки/<алиас>` (префикс — параметр компонента). Параметры `filter[…]`, `sort`, `start` — как у категории; на самом адресе страницы фильтра нет.
- Поверх сохранённых условий посетитель применяет **дополнительный** фильтр (тот же модуль `mod_dharmashop_filter` с `category_mode=landing` — определения берутся для `catid` страницы; значения, уже зафиксированные страницей, в форме не показываются и не считаются). Дополнительные условия идут в `filter[…]`, страница с ними — `noindex, follow` (правило C84).
- Конфликт условий (дополнительное условие противоречит сохранённому для того же поля) — для одного и того же поля условия страницы **заменяются** выбором посетителя только если поле не зафиксировано страницей; зафиксированные поля в форме скрыты — конфликта быть не может.

## 5. Запрос списка

`LandingModel::productsQuery()`: берёт состояние `conditions` (из JSON в `FilterState`), складывает с дополнительным состоянием из адреса (`FilterState::merge(base, extra)`), далее — штатные `CategoryModel`-путь: `productsQuery()` + `FilterQuery::apply()` + `FilterPlanner::indexHint()` + `COUNT` с потолком + пагинация. Для этого `CategoryModel` выносит запрос в переиспользуемый сервис (либо компонент подключает `CategoryModel` с подставленным состоянием); конкретное решение — на этапе L1, без дублирования SQL.

**Ручной список:** запрос `product_id IN (SELECT product_id FROM landing_products WHERE landing_id = ?)` по первичному ключу + штатные условия видимости; порядок — `ordering` страницы, пока выбрана сортировка «как задано» (по умолчанию для `manual`), иначе обычные сортировки. **`both`:** товары ручного списка идут первыми в своём порядке, затем остальные по условиям без дублей; **лимита на число ручных товаров нет** — пагинация единая и работает так же, как у категорий: смещение сначала проходит ручную часть (индексная выборка по `(landing_id, ordering)` со смещением), затем часть по условиям (число ручных товаров `m` известно, смещение условной части = `offset − m`); форма запроса (два запроса по смещению либо `UNION` индексных выборок) выбирается замером на L1 при списках в тысячи ручных товаров; число страниц = ручные + найденные по условиям (потолок `COUNT` как у фильтра).

Скорость: страница = обычная категория с условиями; замеры F0/F8 действуют (1,5–20 мс на 100 тыс.). Предрасчёт `filter_facets` по `catid` страницы не нужен: фильтр на странице считает значения по её `catid` + сохранённым условиям через `candidateCounts`; режим `base` на странице использует базу категории (с пометкой «приблизительно»), режим `live` — точные числа.

## 6. SEO (полная страница)

- Заголовок `h1` = `title`; `introtext` над списком, `fulltext` под списком (или во вкладке — настройка), картинка с контекстом изображения `landing.page` (правило проекта: `ImageContexts::SIZES` + `COM_DHARMASHOP_IMAGE_CONTEXT_LANDING_PAGE`, вывод через `ImageUrl::resolve()`); в списке страниц — `landing.card`.
- Мета-данные и `robots` — разрешитель SEO (шаблоны из настроек магазина, поля страницы переопределяют); `canonical` — на себя (на страницу без `start`/`sort`/`filter`).
- Если существует посадочная страница с теми же условиями (поиск по `conditions_hash`), **страницы фильтра** (категория + такие же условия в адресе) получают `canonical` на неё и остаются `noindex`; редирект 301 с адреса фильтра на посадочную — настройка (по умолчанию выкл.).
- Хлебные крошки: Главная → пункт меню (или категория-источник) → страница. Структурированные данные: `CollectionPage` + `ItemList` (плагин `plg_dharmashop_structureddata` расширяется), карта сайта: страницы попадают в `sitemap` (плагин карты, если появится).
- Контейнер страницы: `<div id="dharma_shop" class="dharmaLanding">`, блоки `dharmaIntro`, `dharmaFulltext` (правило проекта; список — в `docs/LAYOUTS.md`).

## 7. Админка (100 % нативная Joomla)

- Список (`searchtools`: поиск, состояние, категория-источник, «устарела», доступ), корзина, пакетные действия (копировать, изменить категорию, опубликовать).
- Форма (`uitab`, `subform`, `showon`): вкладки «Основное» (название, алиас, состояние, доступ, категория-источник), «Условия» (форма выбора условий **теми же определениями** фильтра: поля, цена, бренд, бейджи, наличие — нативные элементы Joomla; справа число найденных товаров считается при сохранении и показывается сообщением), «Описание» (картинка, краткий и полный текст), «SEO», «Дополнительные поля», «Публикация».
- Быстрое создание из сайта/админки каталога: кнопка «Сохранить фильтр как посадочную страницу» в списке товаров магазина (админка) и ссылка в модуле фильтра для администратора (через `Joomla\CMS\Factory::getUser()->authorise`) — открывает форму с подставленными условиями. Своего JS/CSS в админке нет.
- Проверки сохранения: условия разбираются `FilterState`; неизвестные поля/значения отклоняются с сообщением; пустой результат — предупреждение (не запрет); дубликат `conditions_hash` — предупреждение «такая страница уже есть».

## 8. Сопровождение и согласованность

- При удалении/снятии поля, значения, бренда, бейджа — пометка `broken` у затронутых страниц (запрос по `conditions` выполняется командой обслуживания, не на пути витрины; точечно — событиями ядра). Страница с `broken` остаётся доступной (200) и выводит товары по уцелевшим условиям, администратору — предупреждение в списке.
- Кэш: общий `FilterCache` (группа `com_dharmashop_filter`); сохранение страницы очищает кэш определений при необходимости.
- Пакет: добавляется в `pkg_dharmashop.xml`, `build.sh`, `script.php`; деинсталляция компонента удаляет только свои таблицы и меню-пункты.

## 9. События и подстановки (регистрировать в `SHORTCODES.md` вместе с кодом)

Предварительно: `onDharmaShopLandingBeforeDisplay` (изменить данные страницы), `onDharmaShopLandingConditions` (дополнить условия, например для метатоваров), `onDharmaShopLandingSave`. Подстановки в SEO-шаблонах: `{landing.title}`, `{landing.count}` (число товаров, из кэша), `{category.title}`.

## 11. Решения пользователя (2026-10-09) и оставшиеся вопросы

1. **Название — «Посадочные страницы»** (раздел админки и компонент; префикс адреса по умолчанию — `/posadochnye`, меняется параметром; имя пакета `com_dharmashop_landing` остаётся техническим).
2. **Источник товаров — фильтр, ручной список или оба** (`source`, §3, §5). Ручной список — выбор товаров в форме (нативный модальный выбор товаров Joomla, порядок — перетаскиванием `subform`; список любой длины, форма подгружает его порциями); в админке товаров — действие «Добавить в посадочную страницу».
3. **Редирект 301 с адреса фильтра на посадочную страницу — настройка:** параметр компонента (по умолчанию выкл.) + переопределение на странице (наследовать / включить / выключить). `canonical` работает всегда.
4. **Оформление — настройка:** параметр компонента «макеты страницы: как у категории / собственные» (по умолчанию как у категории: те же карточки и сетка), переопределяется на странице; допполя — общие определения для цели `landing`.

**Пагинация и число товаров на странице — общие настройки магазина (как у категорий, решение 2026-10-09):** `list_limit` и `pagination_type` (страницы / AJAX / «Показать ещё») берутся из тех же параметров магазина, своих настроек у страницы нет (при необходимости — переопределение в параметрах пункта меню, как у категории). Лимита на размер ручного списка нет.

## 12. Риски

1. **Дубли контента:** фильтр с параметрами и посадочная страница показывают одно и то же — лечится canonical и `noindex` (§6).
2. **Устаревшие условия** при изменении каталога — `broken` и предупреждения (§8).
3. **Связность с ядром:** общий запрос выносится из `CategoryModel` — делать аккуратно, без регрессий списка категории (проверка curl/браузером на каждом шаге).
4. **Объём админской формы условий:** переиспользуем определения фильтра, не пишем второй конструктор.

## 13. Уточнение архитектуры (2026-10-12)

Основание: с момента написания плана появились группы товаров (C87), индекс выдачи групп (C89), избранное и модуль товаров; весь вывод списка (фильтр, AJAX, группы, избранное, корзина, SEO, структурированные данные) сосредоточен в `Site\Model\CategoryModel`, `Site\View\Category\HtmlView`/`ListingTrait` и модуле фильтра. Копировать его нельзя (правило проекта), поэтому страница — **виртуальная категория**:

- `Dharma\Component\DharmaShopLanding\Site\Model\LandingModel extends Dharma\Component\DharmaShop\Site\Model\CategoryModel`: `getParent()` возвращает объект, похожий на категорию (название, тексты, картинка, SEO-поля страницы), `forCategory($catid)` задаёт область запроса, `getFilterState()` складывает сохранённые условия страницы с дополнительными из адреса. Весь остальной код (`productsQuery`, `FilterQuery`, итоги, индекс групп, кэш) общий.
- `Site\View\Landing\HtmlView extends Site\View\Category\HtmlView` (ядро) с переопределением адресов формы и ссылок (`categoryRoute()`), данных SEO и хлебных крошек; шаблон `landing/default.php` выводит заголовок, картинку, краткий и полный тексты страницы и подключает общую часть списка ядра.
- Компонент автономен: без него ядро работает, как раньше. Ядру нужны небольшие явные точки расширения вместо проверок `com_dharmashop_landing` по всему коду: (1) допустимые виды списка в `FilterHelper::MODELS` и `FilterController::refresh` берутся из реестра видов; (2) контекст AJAX-карточки группы (`GroupCardContext`, `GroupcardController`) знает вид `landing` и компонент модели; (3) `ListingTrait` строит адреса через переопределяемый `categoryRoute()`; (4) `LayoutHooks` и `CatalogModules` принимают имя компонента; (5) контексты изображений `landing.page`/`landing.card` в `ImageContexts::SIZES`; (6) область SEO `landing` в `PageSeo` и подстановках.
- Источник товаров: `filter` — как у категории; `manual` — ограничение `p.id IN (SELECT product_id FROM landing_products WHERE landing_id=…)` и порядок по `ordering`; `both` — этап L2 (общая пагинация, ручные товары первыми).
- Данные: таблицы `#__dharmashop_landing_pages` (поля §3) и `#__dharmashop_landing_products (landing_id, product_id, ordering)`; допполя цели `landing` — этап L2/L3.
- Согласованность с C89: страница использует нефильтрованный путь индекса групп, пока на ней нет дополнительного фильтра; сохранённые условия страницы — обычное непустое состояние, поэтому для неё работает выдача с фильтром (коррелированные проверки заменены поиском по индексу групп).

Этап L0 (сделано 2026-10-12): решение C85 принято, каркас компонента (манифест, провайдеры, таблицы, права, языки) входит в пакет. Этап L1: модель и список по `id` (`index.php?option=com_dharmashop_landing&view=landing&id=N`), проверка совпадения со страницей категории с теми же условиями.

### 13.1 Индексация, canonical, меню (проверено 2026-10-12, этап L1)

- Посадочная страница — самостоятельная SEO-страница: **`index, follow`**, `canonical` на свой чистый адрес. Сохранённые условия страницы **не** делают её «страницей фильтра», `noindex` ставится только вариантам с выбором посетителя (`filter[…]`), с `sort`/`product_view`: они отдают `noindex, follow` и тот же `canonical` на страницу. Вторая и далее страницы пагинации — как у категории. Для этого в ядре добавлено `CategoryModel::getVisitorFilterState()`: адреса, `noindex` и канонический адрес строятся по выбору посетителя, а не по полному состоянию.
- Canonical с «страниц фильтра» (категория + те же условия в адресе) на посадочную страницу с такими же условиями (`conditions_hash`) и редирект 301 — этап L5.
- Пункт меню: тип **«Dharma Shop: посадочные страницы → Посадочная страница»** (выбор страницы из списка, поле `sql`), адрес `/<пункт меню>`, без пункта — `/component/dharmashop_landing/landing/<алиас>`. Список посадочных страниц как тип меню — этап L3.
- Проверка: `php dev/bench/landing-checks.php` (11 проверок на изолированной копии таблиц): состав, порядок и итог страницы совпадают с категорией с теми же условиями в обоих режимах выдачи, ручной список, дополнение условиями посетителя, виртуальная категория, 404 для снятой/закрытой страницы и закрытой категории-источника.
