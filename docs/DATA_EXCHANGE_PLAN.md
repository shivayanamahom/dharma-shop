# План: экспорт и импорт данных

**Статус:** план (оформлен 2026-10-13 из заметок для обсуждения; решения ниже — плановые, подтверждаются перед стартом этапа E0). **Реализовано (2026-10-13):** экспорт — этапы E1 (ядро запуска), E5 (CSV, XLSX, профили), E6 (YML) и E7 (задача планировщика), см. `ADMIN_EXPORT.md`, `DEVELOPER_GUIDE.md` («Экспорт данных»). Импорт (E2–E4), E8, E9 не начаты. Порядок работ — `ROADMAP.md`: после первого dev-релиза и проверки на чистой Joomla (решение C85, уточнение порядка работ); запись решения — C91 в `DECISIONS.md`.

Реализация — самостоятельная, по правилам `AGENTS.md`: чужой код, структура файлов и имена не переносятся. Ранее разработанные собственные пакеты обмена для другой системы использовались только как пример разделения ответственности.

## 1. Цели и границы

- Загрузить каталог из файла (первичная загрузка и регулярное обновление цен, остатков, описаний) и выгрузить каталог в файл (резервная копия, передача данных, фиды площадок).
- **Два отдельных расширения:** компонент экспорта и компонент импорта. Каждый владеет своими профилями, запусками и журналами; ядро магазина о них не знает.
- **Форматы отделены от логики магазина.** CSV встроен; XLSX, YML и другие подключаются плагинами. Формат отвечает только за чтение и запись строк; правила каталога (проверка, сопоставление, запись) принадлежат компоненту.
- **Площадки (Ozon, Wildberries и др.) — каналы, а не форматы:** у них свои API, авторизация, сопоставление категорий и характеристик, лимиты запросов и идентификаторы предложений. Каналы — отдельные плагины на общем контракте, после основных этапов.
- Запись каталога только через штатные модели и службы Dharma Shop: тогда срабатывают проверки, пересчёт цен и остатков, индекс категорий, поиск, фильтры и индексы групп. Прямые массовые SQL-записи недопустимы (производные данные расходятся).

## 2. Плановые решения

| Вопрос | Решение плана |
|---|---|
| Первый приоритет | Импорт: первичная загрузка и регулярное обновление цен и остатков; экспорт — резервная копия и выгрузка. Движок запуска общий, регулярный обмен строится на нём. |
| Формат первого релиза | CSV (UTF-8, автоопределение разделителя) встроен в компоненты; XLSX — плагином; картинки — по ссылкам и архивом; YML для Яндекс Маркета — отдельный плагин экспорта позже. Поддерживается XLSX, не старый XLS. |
| Состав первой версии | Категории (дерево), бренды, бейджи, товары с вариантами, цены, остатки, картинки, значения полей по алиасам. Определения полей, групп полей и групп товаров — вторым этапом; в первом поля и опции берутся из существующих, недостающие значения создаются только при включённой настройке профиля. |
| Ключ сопоставления | Внешний идентификатор через таблицу `#__dharmashop_external_ids` (источник, тип записи, внешний ключ); запасной ключ — артикул варианта. По названию сопоставлять только по явному выбору пользователя. |
| Площадки | Этапы по каналу: остатки и цены → публикация карточек → заказы. Общий контракт каналов, каждая площадка — плагин. |
| Расписание | Первый запуск файла всегда с просмотром отчёта и подтверждением. Автоматическое применение — только для ранее одобренного профиля, с ограничением доли изменений, без удаления и снятия с публикации записей, которых нет в файле; отчёт отправляется по почте. Запуск — штатный планировщик Joomla. |

## 3. Архитектура

- **Компоненты:** `com_dharmashop_export`, `com_dharmashop_import` (имена рабочие). Таблицы: профили, запуски, строки журнала; профиль сохраняется снимком в запуске (повторяемость).
- **Плагины форматов:** группы `dharmashopexport` и `dharmashopimport`; события регистрации форматов (`…FormatsCollect`) и контракты `Writer` / `Reader` (потоковое чтение и запись, без загрузки всего файла в память).
- **Типы записей** (категории, бренды, бейджи, товары, цены, остатки, картинки, позже поля и группы) — реализации интерфейса «тип записи»: схема колонок, проверка строки, сопоставление, запись через службу магазина. Первые типы встроены; расширение плагинами — отдельное решение после первых этапов.
- **Каналы:** группа `dharmashopchannel`, общий контракт (авторизация, сопоставление, лимиты, очереди); отдельные плагины площадок.
- **Права:** отдельные действия (`dharmashop.export.run`, `dharmashop.import.run`, `dharmashop.import.apply`) — по модели C90; применение импорта отделено от просмотра.
- **Справка:** статьи для администраторов в раздел «Помощь» (`ADMIN_*.md`, список в `dev/generate-help-site.py`), `HELP.md`, `DEVELOPER_GUIDE.md`, `TRIGGERS.md` — вместе с каждым этапом.

## 4. Модель каталога и порядок загрузки

Каталог не плоская таблица: категории, бренды и бейджи — разные типы таксономии; определения полей, группы полей и варианты выбора — справочники, на которые ссылаются значения; товар связан с основной и дополнительными категориями, брендом, бейджами, ценами, остатками и изображениями; группа объединяет самостоятельные товары (оси выбора, собственные таксономия и медиа); цены, остатки, фасеты и индексы — производные данные.

Порядок применения: категории, бренды, бейджи и определения полей с опциями → товары и группы → связи и значения → цены, остатки, изображения → проверка и пересборка производных индексов штатными механизмами (`Indexer`, `StockService`, `FacetIndexer`, `GroupIndex`).

## 5. Безопасность и возобновление

- **Проверка отдельно от применения.** Предварительный отчёт: новые, обновляемые, пропускаемые записи, конфликты и ошибки с номером строки и полем.
- **Режимы** создания, обновления и пропуска; пустая ячейка = «не менять», очистка значения — явный маркер. Записей, которых нет в файле, по умолчанию не снимать с публикации и не удалять.
- **Порционность и возобновление:** размер порции, фиксация прогресса, продолжение после ошибки, повторное применение того же файла не дублирует записи (идемпотентность по ключу строки и хэшу файла).
- **Картинки:** защищённая загрузка в хранилище магазина (тип, размер, alt/title, порядок), без произвольных путей; по ссылке — защита от SSRF (HTTPS, список хостов, без редиректов, лимиты), как у видео.
- **Файлы:** лимиты размера и числа строк, защита от архивных бомб, проверка кодировки.
- **Экспорт и формулы:** значения, начинающиеся с `=`, `+`, `-`, `@`, в CSV и XLSX экранируются (защита от внедрения формул в таблицах).
- **Журнал** запусков и строк; персональные данные в журналах не накапливаются; права на просмотр отчётов — отдельным действием.

## 6. Этапы и проверки

| Этап | Содержание | Проверка |
|---|---|---|
| **E0** | Решения (C91): подтверждение плановых решений, схема таблиц профилей, запусков, журнала, контракты `Reader`/`Writer`/«тип записи», события; проверка `#__dharmashop_external_ids` | запись в `DECISIONS.md`, `ARCHITECTURE.md` |
| **E1** | Ядро запуска: профиль, снимок, порции, прогресс, возобновление, журнал, права; пустые компоненты в пакете | модульные проверки на изолированных таблицах (`dev/bench`) |
| **E2** | Импорт CSV: категории, бренды, бейджи; предпросмотр и отчёт | примеры ошибок (кодировка, дубли, разрыв дерева), идемпотентность |
| **E3** | Импорт товаров, вариантов, цен, остатков, значений полей; картинки (ссылки, архив) | пересчёт индексов, равенство результата «вручную / через импорт», защита картинок |
| **E4** | Применение с подтверждением, повторные запуски, возобновление после обрыва, лимиты | обрыв посередине, повторный файл, откат порции |
| **E5** | Экспорт CSV и плагины XLSX; профили выгрузки (сущности, колонки, фильтры) | круговая проверка «экспорт → импорт → то же состояние», экранирование формул |
| **E6** | YML-плагин экспорта (фид площадки) | валидация фида, соответствие цен и наличия витрине |
| **E7** | Расписание: штатный планировщик, одобренные профили, лимиты изменений, отчёт по почте | запуск без участия, отказ при превышении лимита |
| **E8** | Определения полей, групп полей и групп товаров в формате обмена | круговая проверка структуры |
| **E9** | Каналы площадок: остатки и цены → карточки → заказы | отдельный контракт и тесты по каждому каналу |

Масштаб проверяется на 100 тыс. товаров (время, память: потоковое чтение, не более одной порции в памяти), безопасность — отдельным аудитом по списку раздела 5.

## 7. Вопросы, которые остаются открытыми

1. Откуда запланированный импорт получает файл (папка на сервере, ссылка, загрузка администратором) и кто проверяет его до применения.
2. Какие внешние ключи доступны источникам пользователей и что использовать, если их нет (артикул, составной ключ).
3. Нужен ли обмен посадочными страницами и настройками магазина или только каталогом.
4. Какие типы записей и коннекторы расширяются плагинами, а какие остаются встроенными после E8.
