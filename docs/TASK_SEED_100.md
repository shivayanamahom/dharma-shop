# Задание для второго ИИ: 100 реальных товаров и проверочные скрипты

Работа идёт **параллельно** с основным ИИ в одной рабочей папке. Ваша зона — только данные и скрипты проверки. Код компонента вы **не трогаете**.

## Сначала прочитайте

`AGENTS.md` (жёсткие правила), `docs/DEVELOPMENT.md` (стенд, `dev/*`), `docs/ARCHITECTURE.md` §5 (схема), `docs/SECURITY.md`. Отвечайте по-русски.

## Границы (обязательно)

- **Можно менять и создавать только:** `dev/seed/**`, `dev/smoke/**`, `docs/SEED.md`.
- **Нельзя:** `com_dharmashop/**`, `files_dharmashop_layouts/**`, `plg_*`, остальные `docs/*.md` (кроме `docs/SEED.md`), `AGENTS.md`, `script.php`, манифесты, `build.sh`. Ничего не форматируйте и не «чините» вне вашей зоны: заметили ошибку в коде — запишите в `docs/SEED.md` раздел «Замечания для основного ИИ» и всё.
- **Git:** коммитьте только свои пути: `git add dev/seed dev/smoke docs/SEED.md && git commit -m "..." -- dev/seed dev/smoke docs/SEED.md`. Никаких `git add -A`, `git commit -a`, `reset`, `stash`, `checkout`, `rebase`. Основной ИИ коммитит свои файлы отдельно.
- **Не запускайте** `dev/sync.sh`, `dev/install.php`, `dev/uninstall.php`, `build.sh`: основной ИИ сам раскладывает код на сайт, чужая раскладка в этот момент может перетереть его работу.
- **Тестовый сайт только `https://test.test`.** Не трогайте настройки компонента (`#__extensions.params`), существующие записи пользователя и его файлы (см. ниже).
- **Файлы в `images/`:** удаляйте только те, что создали сами, по точным путям из своего манифеста. Никаких `rm -rf` по папкам и `find -delete`.
- **Секреты** только из окружения (`dev/.env`, `dev/web-login.sh`), в файлы и ответы не писать.

## Что уже есть на сайте (не ломать)

Данные пользователя: категории 13 «Столы», 16 «Обеденные столы», 12 «Без категории»; бренды 14, 17; бейдж 15; товары 1–4 (товар 4 — с загруженными вручную изображениями, и открыт пользователем). Ваши данные создаются **отдельным деревом**, существующее не изменять и не удалять.

## Задача A: 100 товаров

Создайте через **штатные формы админки по HTTP** (чтобы отработали проверки, индекс, галерея, порядок): `dev/web-login.sh`, затем POST форм как в `dev/save-product.sh` и `dev/save-category.sh` (посмотрите, как там берётся токен и поля; формы — `com_dharmashop&task=product.edit` / `category.edit`). Прямые INSERT в БД не использовать.

Тема каталога — мебель и интерьер (реальные названия, русские). Пометки для безопасной очистки:
- артикулы товаров начинаются с `DS-` (например `DS-STL-0012`);
- у созданных категорий, брендов и бейджей в поле «Заметка» (`note`) значение `seed-100`.

### Структура

- **Категории (≈10, вложенные, 2 уровня, один раздел с 3 уровнями):** например «Мягкая мебель» → «Диваны», «Кресла»; «Столы и стулья» → «Обеденные группы», «Письменные столы», «Барные стулья»; «Хранение» → «Шкафы», «Комоды»; «Освещение»; «Текстиль и декор». Одну категорию оставьте **пустой** (без товаров), одну — **снятую с публикации** с товарами внутри.
- **Бренды (≈6, один вложенный):** реальные или правдоподобные названия. Бейджи (≈4): «Хит», «Новинка», «Распродажа», «Эко» с разными цветами.
- **Товары (100):** основная категория, у ≈30% — 1–2 дополнительные, у ≈70% — бренд, у ≈25% — один-два бейджа.

### Разнообразие данных (специально для проверки пагинации и сортировок)

- Цены от 490 до 189 900; **не менее 15 товаров с одинаковой ценой** (проверка ничьей при сортировке по цене); **5 товаров без цены** («по запросу»).
- Скидки: у ≈12 товаров сумма (`500`), у ≈12 процент (`10%`, `15%`, `25%`), у 3 — скидка с датами «по» в прошлом, у 2 — «с» в будущем.
- Остатки: ≈70% с учётом остатков и положительным остатком, 15 — нулевой остаток (нет в наличии), остальные без учёта остатков.
- Единицы измерения разные (шт, комплект, пог. м, м², набор), у части заданы шаг/минимум количества.
- Название: от коротких до очень длинных (≥120 символов), у 5 — с кавычками, `&`, `<b>` в тексте (проверка экранирования), у 5 — с кириллицей и латиницей вперемешку.
- Краткое описание — 1–3 предложения (HTML-редактор: можно `<p>`, `<strong>`), полное — 3–6 абзацев; «Текст для поиска» — синонимы.
- Состояния: 90 опубликовано, 5 снято, 3 в архиве, 2 в корзине (должны сохраниться; в корзину отправьте штатным действием).
- SEO у 10 товаров (title, description, h1, крошки), у остальных пусто.
- **Изображения:** у 60 товаров 1–5 изображений, у 40 без изображений. Реальные фото брать из интернета нельзя (запрещено скачивать без разрешения), поэтому **сгенерируйте** картинки локально (PHP GD или Python Pillow): единый цвет/градиент, надпись с названием, размеры вперемешку (квадрат 800×800, 1200×800, 600×900). Загружайте штатным загрузчиком (`media.upload`, токен формы, как в `dev/security-upload.sh`), допустимые форматы и лимит смотрите в ответе загрузчика. Пути ответов записывайте в манифест.

### Порядок работы

1. Сначала скрипт `dev/seed/seed.sh` (или `.py`/`.php`, на ваш выбор, но запуск из корня репозитория, окружение из `dev/.env`) **идемпотентный**: повторный запуск не создаёт дубликатов (проверяет по `DS-` артикулам и пометке `seed-100`).
2. Скрипт пишет `dev/seed/manifest.json`: id созданных категорий, брендов, бейджей, товаров, пути всех загруженных файлов. Этот файл — единственный источник для очистки.
3. Скрипт `dev/seed/clean.sh`: удаляет **только** записи и файлы из манифеста (товары через штатное удаление: сначала корзина, затем «Очистить корзину»; файлы по точным путям; затем категории). Ничего другого.
4. После запуска сверьте SQL-запросами (`dev/db.sh`): сколько товаров по состояниям, нет ли «сирот» в `#__dharmashop_product_categories`, `#__dharmashop_variants`, `#__dharmashop_field_media`, у каждого товара ровно одна прямая основная строка (`is_main = 1`), `products.cover` совпадает с первым изображением галереи. Результат запишите в `docs/SEED.md`.

## Если данные создаются напрямую через БД (решение пользователя)

Допустимо вместо форм, но тогда **вы отвечаете за согласованность**. Обязательно:

1. **Таблицы на каждый товар:** `#__dharmashop_products` (`catid` — основная категория, `state`, `alias` уникален внутри основной категории, `created`, `created_by`, `price_min`/`price_max`/`in_stock`/`variants_count` заполните сами или оставьте пересчёту, `cover`/`cover_alt` = первое изображение галереи), `#__dharmashop_variants` (один вариант, `is_default = 1`, `sku`, `state = 1`, `stock_tracked`, `backorder`, `stock_total`, `in_stock`), `#__dharmashop_variant_prices` (`price_list_id = 1`, `price`, `discount`, `discount_percent`, `discount_start/end`, `price_final`), при учёте остатков — `#__dharmashop_stock_levels`; галерея — `#__dharmashop_field_media` (`field_id = 0`, `variant_id` NULL, `ordering` с 0); привязки — `#__dharmashop_product_categories` (прямые строки: основная с `is_main = 1`, дополнительные, бренд, бейджи, все `direct = 1`).
2. **Категории, бренды, бейджи** — таблица `#__categories` (`extension` = `com_dharmashop`, `com_dharmashop.brand`, `com_dharmashop.badge`) через `Joomla\CMS\Table\Category` (дерево lft/rgt, пути, права) — не прямым INSERT. Пример: `dev/make-category.php`.
3. **После вставки обязательно пересчитайте** всё штатным кодом (CLI через `dev/boot.php`, службы компонента):
   `$shop = Factory::getApplication()->bootComponent('com_dharmashop')->getServices();` затем `$shop->maintenance()->run('products')` (цена, наличие, правила оформления) и `$shop->maintenance()->run('index')` (родительские строки и копии столбцов индекса); команду повторяйте, пока `done` не станет `true`. Запустите до проверки.
4. **Проверьте сверкой SQL**, как в разделе «Порядок работы», п. 4; плюс: `product_categories.state/price_sort/in_stock/title_sort/created` совпадают с товаром, у родительских строк `direct = 0`.
5. Манифест и очистка работают так же: чистить можно только записи и файлы из манифеста; удалять товары удаляйте вместе с вариантами, ценами, остатками, галереей и строками индекса (никаких «сирот»).

## Задача B (после A): проверочный скрипт по сайту (только чтение)

`dev/smoke/site.sh` (запросы по `https://test.test/index.php/...`, без изменения данных): для каждой категории из манифеста открыть страницу, проверить код 200, наличие `<h1>`, canonical, отсутствие PHP-ошибок и буквальных `{...}` в `<title>`/`<h1>`; пройти постраничную выдачу по ссылкам «Следующая страница» до конца, **сравнить число товаров с SQL**, убедиться, что нет дублей и пропусков (особенно при сортировке по цене и при одинаковых ценах). Сортировки: `sort=order|title|price_asc|price_desc|new`. Вывод: таблица «категория — ожидалось — получено — OK/FAIL». Запускать скрипт можно сколько угодно: он безопасен.

Замечание: основной ИИ сейчас меняет сайтовую часть (ЧПУ и AJAX-переключение сортировки и вида). Адреса и параметры могут измениться; сначала сверяйтесь с `docs/SEED.md` и последним `git log`, а скрипт делайте настраиваемым (базовый URL и шаблон адреса — в начале файла).
