# Доставка: раздел, типы-плагины и правила для новых типов (C80)

Дата: 2026-10-08. По запросу пользователя: «Доставка» — отдельный раздел меню; способ создаётся выбором типа; каждый тип — отдельный плагин группы `dharmashopshipping` со своим макетом на сайте (переопределяется в шаблоне). Оплата строится по тем же правилам (отдельный раздел `payments`, группа `dharmashoppayment`) — этот документ и контракт служат образцом.

## 1. Что где лежит

| Что | Где |
|---|---|
| Таблица способов | `#__dharmashop_shipping_methods`: `title`, `alias`, `plugin` (id типа = element плагина), `description` (для покупателя), `params` (JSON настроек типа), `is_default`, `state`, `access`, `ordering` |
| Контракт типа, реестр, службы | `com_dharmashop/admin/src/Shipping/`: `TypeInterface`, `TypeRegistry`, `Method`, `Context`, `Quote`, `Selection`, `ShippingService`, `ShippingInputException`; служба — `ShopServices::shipping()` |
| Раздел админки | виды `shippings`/`shipping`, модели, `ShippingController`/`ShippingsController`, `forms/shipping.xml`, `forms/filter_shippings.xml`; право `dharmashop.shipping.manage` (плюс обычные `core.create/edit/edit.state/delete`) |
| Пункт меню админки | плагин `plg_system_dharmashopmenu` (группа «Заказы/Корзины/Покупатели | Товары… | Поля… | Статусы заказов, Доставка, Настройки») |
| Типы | `plg_dharmashopshipping_standard` («Стандартная доставка»), `plg_dharmashopshipping_courier` («Курьер»), `plg_dharmashopshipping_pickup` («Самовывоз») — в общем пакете, включаются при установке; каждый дорабатывается отдельно |

## 2. Поведение

- В разделе «Доставка»: список (поиск, фильтры состояния и типа, порядок перетаскиванием, публикация, удаление), «Создать» → выбор **типа** в форме → общие поля (название, псевдоним, описание для покупателя, состояние, по умолчанию, доступ, порядок) и настройки типа из формы плагина (`showon` по выбранному типу). Тип после сохранения не меняется. Способ, чей плагин отключён или удалён, виден в списке с пометкой и покупателям не показывается.
- Один плагин обслуживает любое число способов (несколько пунктов самовывоза = несколько способов типа «Самовывоз»).
- Если нет ни одного опубликованного способа с рабочим типом — оформление заказа идёт как раньше, без шага доставки. Если способы есть — выбор обязателен; если ни один не подходит для заказа (ограничения по сумме) — кнопка «Оформить» скрыта, показано предупреждение.
- Цену и доступность считает **сервер** по `Context` (итог заказа без доставки после скидок, позиции, контакты). Из браузера принимаются только id способа и введённые поля; цена из формы не читается. Повторная проверка — при создании заказа в той же транзакции (`OrderService::create` → `ShippingService::resolve`).

## 3. Контракт типа (`TypeInterface`)

Тип — класс, который плагин регистрирует по событию `onDharmaShopShippingTypesCollect` (аргумент `registry: TypeRegistry`; повтор id или неверный файл настроек — исключение):

| Метод | Назначение |
|---|---|
| `id()` | идентификатор = element плагина, `[a-z][a-z0-9_]{0,49}` |
| `label()`, `description()` | языковые ключи названия и описания типа |
| `settingsPath()` | Form XML настроек: `<fields name="params"><fields name="<id>"><fieldset name="type_<id>">` — поля лежат в **своей группе `params[<id>]`** (имена разных типов не пересекаются), каждое с `showon=".plugin:<id>"`; `normalizeSettings` получает только свою группу, в БД (`params`) хранится плоский JSON этих настроек |
| (форма типа, вкладки) | Form XML типа содержит два fieldset: `type_<id>` — вкладка «Основное» (поведение, поля, подписи) и `price_<id>` — вкладка **«Цены»**: всё, что связано с ценой и суммой заказа (цена, «бесплатно от суммы», минимальная/максимальная сумма, будущие таблицы цен) |
| (форма типа, блоки) | В «Основном» каждый fieldset `type_<id>` и `type_<id>_<имя>` (например, `type_pickup_map` — блок «Карта») выводится отдельным блоком `options-form` с заголовком из `label` и виден при выбранном типе |
| (форма типа, вкладка карты) | Необязательный fieldset `map_<id>` формы типа выводится на отдельной вкладке «Настройка карты» (для типов без него вкладка показывает пометку) |
| `normalizeSettings(array)` | проверка и очистка настроек при сохранении; ошибка — `\DomainException` с языковым ключом. В `params` хранить значения **в виде, пригодном для поля формы** (скаляры/строки; многострочные списки — строкой, не массивом) |
| `quote(Method, Context): ?Quote` | цена (`0` = бесплатно), срок, признак `free`; `null` — недоступен для этого заказа |
| `describe(Method, Quote): array` | постоянные сведения о способе: строки `[label, value]` (адрес пункта, телефон, часы работы) |
| `validateInput(Method, Context, array): array` | данные покупателя: `data` (машинные), `rows` (подпись/значение для показа), `errors` (`ключ поля => языковой ключ`) |
| `render(array): string` | HTML варианта на странице оформления (макет плагина) |

Плагин не пишет в БД и не читает сеть при расчёте; всё необходимое берёт из `Method`/`Context`.

## 4. «Общая система»: куда попадает информация плагина

Тип отдаёт сведения единым видом — **строки `{label, value}` обычным текстом** (без HTML, экранируется при выводе). Источник — `describe()` (постоянные) и `validateInput().rows` (введённые покупателем). Дальше они одинаково попадают в:

1. **Страницу оформления.** В варианте (макет плагина) и в **боковой панели** «Способ доставки»: название, срок, строки `describe`, затем введённые значения. Боковая панель обновляется при выборе способа и при вводе без перезагрузки (checkout.js; поля с `data-summary-label`).
2. **Снимок заказа** `orders.shipping_data` (JSON): `type`, `title`, `price`, `free`, `term`, `rows`, `data`; `orders.shipping_title` — название; цена — строка итогов `order_adjustments` (`type = shipping`, `code = shipping:<id способа>`).
3. **Админку** (карточка «Доставка» заказа), **страницу заказа покупателя** и **письма** (блок `{SHIPPING}`: способ с ценой, срок, строки). Все три показывают **только снимок**, плагин типа для этого не нужен, поэтому старые заказы читаются даже после удаления плагина.

Новый тип ничего не добавляет в эти места сам: достаточно вернуть правильные `rows`.

## 5. Правила макета типа (`tmpl/default.php`)

- **Обязательное правило: любой вывод на сайте — только через макет плагина**, подключаемый `PluginHelper::getLayoutPath('dharmashopshipping', '<id>', 'default')`, чтобы каждый тип можно было переопределить в шаблоне: `templates/<шаблон>/html/plg_dharmashopshipping_<id>/default.php`. HTML в PHP-классе типа не собирается. Проверено на test.test: файл-переопределение в `dharma_starter/html/plg_dharmashopshipping_courier/` подменяет вывод варианта.
- Радиокнопка: `name="shipping_method"`, `value="<id способа>"`, атрибуты `data-shipping-radio`, `data-price-text` (текст цены/«Бесплатно»), `data-total-text` (итог с этим способом) — их выдаёт ядро в `displayData`.
- Карточки выбора (`[data-shipping-point-card]`) подсвечиваются ядром (`checkout.js`: класс `border-primary` у карточки выбранного радио).
- Выбор внутри способа (например, пункт выдачи): радио `shipping[<id способа>][<ключ>]` с `data-shipping-point`; чтобы выбор и сведения попали в боковую панель, у элемента задают `data-summary-label`, `data-summary-value` (готовое значение) и/или `data-summary-rows` (JSON-список `{label, value}`); блок сведений выбранного значения — `data-shipping-extra data-shipping-point-detail="<значение>"` (виден, только если выбран и способ, и значение). Общая карта способа — `iframe[data-shipping-map]` в блоке `data-shipping-map-wrap` (`data-map-url` у выбранного элемента задаёт её адрес) либо контейнер `[data-pickup-map]` со скриптом карты (`data-config` — JSON от сервера).
- Поля покупателя: имена `shipping[<id способа>][<ключ>]`, у каждого `data-summary-label="<подпись>"`; блок с полями и картой — внутри контейнера `data-shipping-extra` (скрывается у невыбранных способов; у выбранного показан).
- Только классы Bootstrap 5, без своего CSS и inline-стилей; значения в вывод — через `htmlspecialchars`. Внешние виджеты (карта) — `loading="lazy"`, `referrerpolicy="no-referrer"`, показ только у выбранного способа.
- `displayData`: `method`, `quote`, `selected`, `id`, `values`, `errors`, `info`, `image_url`, `price_text`, `total_text`, `free_text`.
- Изображение способа (картинка или SVG-иконка) задаётся в первой вкладке формы способа (`shipping_methods.image`, загрузчик с папкой `shipping`); ядро отдаёт `image_url` через `ImageUrl::resolve($path, 'shipping.option')` (контекст размеров 96 × 96, реестр — `docs/IMAGE_RESIZE.md`), макет выводит `<img>` рядом с названием. Любой новый вывод изображения в типе — только через свой контекст (правило проекта).

## 6. Безопасность и надёжность

- Все значения покупателя проходят `validateInput` (длины, список допустимых значений, формат); в снимок попадают очищенными. Ошибки возвращаются по ключу поля и показываются под полем.
- Нельзя доверять цене/доступности из запроса, имени типа из запроса (тип берётся из строки способа) и скрытым полям.
- Настройки типа валидируются при сохранении (`normalizeSettings`), при чтении — с запасными значениями (старые записи не должны ломать оформление).
- Права: раздел — `dharmashop.shipping.manage`; доступ способа покупателям — уровень доступа записи.
- Языковые ключи плагина — `PLG_DHARMASHOPSHIPPING_<ID>_*` (ru-RU и en-GB), плагин сам загружает язык (`$autoloadLanguage`).

## 7. Что умеют первые типы

- **Стандартная доставка** (`standard`) — «обычный» способ: покупатель вводит данные, менеджер потом уточняет детали заказа (настраиваемая подпись, по умолчанию «Менеджер свяжется с вами и уточнит детали доставки», попадает в боковую панель, заказ и письма). Курьерская доставка — отдельный тип «Курьер». Возможности: фиксированная цена; «бесплатно от суммы заказа» (итог после скидок ≥ порога); минимальная/максимальная сумма заказа; срок; **конструктор полей покупателя** (подпись, тип: строка/многострочное/телефон/список, обязательность, ширина, подсказка, варианты списка) — по умолчанию «Город» и «Адрес».
- **Курьер** (`courier`): доставка до двери; цена, «бесплатно от суммы», ограничения по сумме, срок, подпись («Курьер позвонит вам перед доставкой») и конструктор полей (по умолчанию город, улица и дом, квартира, подъезд, этаж, домофон, комментарий курьеру). Расчёт по зонам и весу — позже.
- **Самовывоз:** один способ — несколько пунктов выдачи (складов) в повторяемой форме; у пункта название, адрес, телефон, e-mail, часы работы, дополнительные сведения, свой срок готовности и координаты склада в виде, как их даёт Яндекс: `[55.753994, 37.622093]` (широта, долгота; допустимы также запись без скобок и десятичная запятая). **Карта — отдельная вкладка «Настройка карты», одна на способ; только Яндекс Карты, JavaScript API 3.** Вид: «Яндекс Карты» или без карты. Настройки: **ключ API** (публичный, ограничьте его по адресу сайта в кабинете Яндекса), тип метки (булавка, точка, круг, метка с названием склада), цвет меток и цвет выбранной (15 цветов), центр карты (формат координат Яндекса; пусто — по пунктам), масштаб (0 = показать все пункты), пропорции блока (Bootstrap `ratio`: 21:9, 16:9, 4:3, 1:1 — высота от ширины, без inline-стилей). Карту строит скрипт плагина `pickup-map.js` (свой код на API 3: метки — свои элементы на SVG и классах Bootstrap; в API 3 порядок координат [долгота, широта], перестановка делается в скрипте); скрипт подключается только когда карта нужна, карта создаётся, когда блок попадает в окно; без ключа показывается простой виджет Яндекса без настроек меток. OpenStreetMap не поддерживается (решение пользователя). На оформлении сверху карта, под ней карточки пунктов (Bootstrap `card`, радио внутри карточки): клик по метке выбирает карточку, клик по карточке центрирует метку на карте и выделяет её рамкой (`border-primary`); выбор попадает и в боковую панель. Метка кликабельна на карте по ключу (JS API 3); в простом виджете без ключа выбор делается карточкой. Покупатель выбирает пункт при оформлении (при одном пункте он выбирается сам); в боковую панель, заказ и письма попадают название и сведения выбранного пункта. Цена, «бесплатно от суммы» и ограничения по сумме — общие, на вкладке «Цены».

## 8. Идеи следующих типов и правил (не сделано)

Доставка по весу/объёму, таблица цен по городам/регионам, наложенный платёж как наценка, расчёт через API перевозчиков (СДЭК, Почта России) отдельными плагинами, пункты выдачи из справочника с выбором на карте, ограничение способа по категориям товаров или группам пользователей.
