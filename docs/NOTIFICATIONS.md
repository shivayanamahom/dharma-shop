## Настройки

Настройки магазина → **Уведомления**. Плагин «Dharma Shop — Уведомления по email» установлен и включён; **отправка в настройках магазина по умолчанию выключена**. Пользователь выбирает адреса/события и включает её. Установка и обновление не рассылают старые заказы.

- Администрация: незаблокированные пользователи Joomla с «Получать системные письма» (sendEmail=1), дополнительные адреса до 50, разделённые строками/запятыми/точками с запятой. Повторы объединяются, каждому отдельное письмо без раскрытия остальных получателей. Невалидные дополнительные адреса отклоняются при сохранении и не используются на отправке.
- Покупатель: contact_email сохранённого заказа, независимо от email аккаунта. Без email письмо покупателю пропускается с предупреждением в журнале.
- Четыре переключателя: новый заказ администрации/покупателю (Да), смена статуса администрации (Нет)/покупателю (Да). Общий переключатель отправки — Нет.
- В письме покупателю можно включать состав, контакты и ссылку. Администрации всегда передаются состав и контакты. Внутренние заметки и история сотрудников не отправляются. С C77 согласия передаются отдельным блоком в обе аудитории, даже если контактные поля выключены.
- Ссылка администрации ведёт в админку с проверкой ACL, покупателя с user_id — на собственный заказ. Гостю отправляется сам состав без постоянной ссылки: доступ вне сессии C75 пока не реализован.
- Необязательный Reply-To; если пусто — email из данных магазина, затем Joomla. Отправитель и SMTP из общих настроек Joomla, отдельного SMTP/паролей плагин не хранит.

## Тексты писем

Система → Шаблоны писем, расширение **Dharma Shop — Уведомления по email**. Четыре шаблона:

- `plg_dharmashopnotify_email.order.new.admin` / `.new.customer`;
- `plg_dharmashopnotify_email.order.status.admin` / `.status.customer`.

Установщик добавляет отсутствующие шаблоны и HTML к прежнему стандартному тексту без HTML. Пользовательские тема/текст/HTML сохраняются; список тегов расширяется с сохранением параметров. RU/EN. С C77 канал всегда формирует HTML + текстовый дубль, не меняя com_mails.mail_style и оформление других писем. Нативные записи и редактор MailTemplate остаются. HtmlTemplate наследует API Joomla, использует её транспорт, получателей/Reply-To, индивидуальный SMTP при включённой альтернативной конфигурации, BCC и вложения; событие onMailBeforeRendering сохраняется. Глобальная HTML-оболочка com_mails для этого канала заменена макетом плагина. Данные пользователя экранируются; доверенными считаются только блоки, созданные собственным экранирующим макетом. Однопроходные подстановки не разворачивают коды внутри пользовательских значений. Теги — SHORTCODES.md: SITENAME, ORDER_NUMBER, ORDER_DATE, STATUS, STATUS_MESSAGE, TOTAL, ITEMS, CONTACTS, ORDER_LINK. STATUS_MESSAGE — необязательный текст статуса для покупателя. Цены/количества/контакты читаются из снимка, без каталога. Учитывается замена нулевой цены и валюта старого заказа.

## События и сохранение

`NotificationService::notify(historyId, retry=false)` собирает readonly `OrderNotification` (order/items/adjustments/contacts, historyId, reason created/status) и dispatch `onDharmaShopOrderNotify` группе `dharmashopnotify`, аргументы notification/settings/retry. Событие конкретной истории использует её статус, а не текущий статус заказа при позднем повторе. Изменение контактов покупателя не меняет снимок.

`OrderService::create` запускает уведомления только после commit нового заказа; идемпотентный повтор checkout возвращает существующий результат без писем. `OrderStatusService` блокирует заказ, сверяет ожидаемый прежний статус и допустимый переход, пишет историю/статус одной транзакцией; после commit — событие и уведомления. Повтор прежнего статуса ничего не отправляет. Нейтральные переходы реализованы, эффекты остатков запрещены до отдельного шага.

`onDharmaShopOrderAfterCreate` / `onDharmaShopOrderStatusChanged` группы dharmashop также работают после commit, с ID заказа/истории. Исключения обработчиков журналируются и не отменяют сохранённый заказ. Telegram-плагин может подписаться только на канальное событие, использовать собственные настройки и тот же журнал доставки.

## Журнал и повтор

`#__dharmashop_notifications` принадлежит компоненту: уникальная доставка по history_id/channel/audience/recipient_hash, адрес, случайный claim_key, attempts, error_code (класс исключения), даты. State 0 — начато без зафиксированного результата; 1 — принято почтовым транспортом; 2 — ошибка. Ошибка SMTP не откатывает заказ и не возвращает покупателю ошибку сохранения.

В истории заказа видны счётчики и кнопка **«Повторить неудачные уведомления»**. Только POST/CSRF/orders.manage и история именно этого заказа. Повторяются только существующие state=2 для действующих сейчас правил/получателей; новые адреса не добавляются задним числом. Успешные state=1 и неопределённые state=0 не повторяются. Неопределённый результат требует проверки почтового журнала, чтобы не создать дубликат. Счётчик «принято почтой» не доказывает получение письма в ящике.

Первая реализация синхронная после commit; фоновой очереди, автоматических повторов и восстановления прерванного процесса нет. Ошибки канала изолируются от транзакции заказа; плагин должен изолировать ошибки собственных получателей. Общий журнал приложения com_dharmashop содержит наши ID/классы ошибок без контактов и SMTP-реквизитов.

## Данные магазина и оформление (C77, 2026-10-08)

Настройки → Магазин → **Данные магазина**: название, логотип, email, телефон, адрес. Всё необязательно; пустое название наследует sitename. Данные попадают в шапку/подпись писем, имя — также в прежний SITENAME для совместимости тем. Логотип — абсолютная HTTP(S)-ссылка после очистки Joomla media metadata, локальный путь приводится к адресу сайта; скриптовые схемы не используются. Отправитель и SMTP остаются Joomla, отдельный Reply-To имеет приоритет над email магазина.

Макеты плагина: `tmpl/mail.php` — оболочка, `tmpl/blocks.php` — номер/дата/статус, таблица товаров/корректировок, контакты, сообщение, кнопка, доставка/оплата/согласия. Таблицы и inline-стили предназначены для почтовых клиентов, не добавляют CSS на сайт/в админку. HTML-часть четырёх шаблонов использует новые теги; при пользовательском тексте без HTML он сохраняется и оборачивается в письмо как экранированный текст.

**Согласия:** из `contacts.consents` сохранённого заказа, независимо от текущих настроек checkout. Передаются текст + link_label, безопасная ссылка документа, фактическое accepted (Да/Нет), accepted_at только если имеется и согласие принято. Необязательное неотмеченное согласие явно показывает Нет. В старом заказе без снимка согласий блок отсутствует. Отправка не создаёт новых согласий и не меняет старые.

Доставка/оплата: пока показываются только непустые shipping_title/payment_title из снимка заказа. Секретные данные и произвольные shipping_data/payment_data не включаются. Формы адреса и реквизитов будут подключаться при реализации методов.
