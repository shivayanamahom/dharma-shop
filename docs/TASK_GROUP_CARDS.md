# Задача: два режима карточки группы товаров

Дата: 2026-10-09. Заказчик: пользователь. Статус: реализовано в коде 2026-10-10; функциональная приёмка впереди.

## Цель и границы

В смешанном списке каталога одна карточка группы соседствует с обычными товарами. Общий переключатель сетка/список/таблица работает для обеих сущностей. Режим карточки группы настраивается глобально, независимо от настройки «Товары / Группы товаров и товары».

Сохранить самостоятельные товары и один служебный SKU на товар. Группа не покупается и не получает собственный остаток. FilterQuery/FilterPlanner, FacetEngine/FacetIndexer и модуль фильтра остаются Claude. Не менять их файлы и алгоритмы.

## 1. Общие настройки

В разделе настроек отображения добавить нативный блок **«Группы товаров»** с настройкой **«Режим карточки»**:

- **Простой** (по умолчанию, совместимость с текущим каталогом).
- **Выбор варианта без перехода** (AJAX).

Настройка действует на переопределяемые макеты группы grid/list/table. HTML первой загрузки готов на сервере; переключение вида и динамическая пагинация повторно подключают поведение карточек.

## 2. Простой режим

- Фото группы; если его нет — фото первого доступного варианта с учётом наследования.
- Цена от минимальной до максимальной среди доступных вариантов текущей выдачи. Сохранить правила «бесплатно / цена по запросу».
- Кнопка с количеством: «N вариантов» (русские формы 1/2/5), ведущая на первый доступный вариант. Число совпадает с составом карточки и её условиями видимости.
- Поля выбора выводятся только по настройкам соответствующих полей. Они показывают доступные значения, без выбора и без загрузки всех карточек вариантов.

«Первое» в каталоге — действующий представитель группы, выбранный сервером в соответствии с сортировкой/поиском/фильтром. Не подменять его скрытым или не подходящим под выдачу товаром.

## 3. Настройки полей «Список» и «Цвет»

В существующем блоке вариативности добавить независимые настройки карточки группы:

- **Выводить в карточке группы**.
- **Переключатель в карточке группы** (активный AJAX-выбор): не выводить / список / радиокнопки; для цвета дополнительно образцы цвета. По умолчанию не выводить.
- **Формат значения**: использовать существующие варианты текст / образец / образец с подписью там, где они применимы.
- Подпись поля включается отдельно, в соответствии с существующим устройством настроек отображения.

Не переиспользовать параметры обычной карточки товара, полной страницы и фильтра: владельцу нужны независимые настройки. Настройки актуальны для list/color с включённой вариативностью, хранятся обычными params определения поля; значения и поиск сочетаний остаются индексными.

Простой режим показывает статические значения в выбранном формате. AJAX-режим показывает переключаемые элементы. Подбор ограничивается всеми видимыми полями. Скрытые значения — предпочтения: сохраняются по возможности, иначе выбирается существующий доступный вариант по видимым полям; при равенстве — меньший ID. Полное сочетание найденного товара проверяется по hash. Уточнение пользователя 2026-10-10 заменяет первоначальное правило фиксированных скрытых осей.

## 4. Режим «Выбор варианта без перехода»

- Изначально выбран первый доступный товар-представитель; его изображение/галерея, цена и кнопка «В корзину» соответствуют одному и тому же товару/SKU.
- Название, фото и цена принадлежат выбранному товару; ссылка ведёт к нему (уточнение пользователя 2026-10-10).
- При выборе значения поля отправляется запрос за одним выбранным вариантом. Обновляются фото (либо слайды штатной галереи/Swiper, если она используется), актуальная цена со скидкой, доступность, ссылка и форма покупки.
- Не загружать HTML, фотографии, галереи, цены и SKU всех вариантов заранее. В исходном документе только один вариант на группу и компактные значения осей. Нет скрытого массива всех карточек.
- Сервер подбирает точное сочетание group_id + combo_hash, проверяет состав группы, публикацию/ACL товара, категорий, группы и полей; исходные условия выдачи должны учитываться при доступности выбора.
- Невозможное сочетание не меняет выбранный товар и не позволяет добавить другой SKU. Показать понятное сообщение/недоступность выбора, сохранить последний успешный выбор.
- Во время загрузки блокировать повторную покупку; показывать состояние загрузки. Быстрые переключения отменяют устаревший запрос или игнорируют его ответ. Несколько карточек независимы.
- При ошибке сети оставить последнюю успешную карточку и дать повторить действие. Без JS сохраняется переход к выбранному/первому товару.
- Покупка использует существующие сервис/форму корзины с реальной ценой, наличием и правилами товара; группа не становится товаром корзины.

## Фактическая реализация, 2026-10-10

- Глобальный group_card_mode=simple|ajax; у полей list/color — независимые настройки простого вывода и активного выбора. Нативные XML/showon, RU/EN, серверная нормализация. Термин интерфейса — «вариант».
- GroupListing пакетно загружает настройки/доступные значения осей и выбранные значения только представителей страницы; CategoryModel обогащает только их цены/галереи. Наследование изображений группы разрешается пакетно. На карточку не приходится отдельного запроса корзины.
- groupcard.select получает подписанный контекст исходной выдачи и выбранные значения. Точное сочетание разрешает GroupService, затем проверяются текущие публикация/ACL, таксономия, поиск/фильтр. Скрытая ось после уточнения пользователя является предпочтением, а не ограничением. Нет записи в каталог/корзину и предварительной выгрузки всех вариантов. Ответ содержит одну карточку выбранного товара в прежнем виде grid/list/table.
- Делегированный group-card.js отменяет старый запрос, блокирует покупку, сохраняет последнюю успешную карточку при ошибке и повторно запускает штатное поведение после замены. Галерея/Swiper, цена со скидкой и корзина взяты из общих частей товара. Без JS доступна ссылка на выбранный вариант.
- Переопределяемые части attributes/choice зарегистрированы в файловом манифесте; контексты изображений group.teaser.grid/list/table и group.choice сохранены. FilterQuery/Planner, FacetEngine/Indexer и модуль фильтра не изменялись.

Критерии §6 остаются непроверенными до функциональной приёмки. Нагрузочные замеры этим шагом не выполняются.
