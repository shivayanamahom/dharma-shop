# Задача: два режима карточки группы товаров

Дата: 2026-10-09. Заказчик: пользователь. Статус: описание зафиксировано до реализации.

## Цель и границы

В смешанном списке каталога одна карточка группы соседствует с обычными товарами. Общий переключатель сетка/список/таблица работает для обеих сущностей. Режим карточки группы настраивается глобально, независимо от настройки «Товары / Группы товаров и товары».

Сохранить самостоятельные товары и один служебный SKU на товар. Группа не покупается и не получает собственный остаток. FilterQuery/FilterPlanner, FacetEngine/FacetIndexer и модуль фильтра остаются Claude. Не менять их файлы и алгоритмы.

## 1. Общие настройки

В разделе настроек отображения добавить нативный блок **«Группы товаров»** с настройкой **«Режим карточки»**:

- **Простой** (по умолчанию, совместимость с текущим каталогом).
- **Выбор исполнения без перехода** (AJAX).

Настройка действует на переопределяемые макеты группы grid/list/table. HTML первой загрузки готов на сервере; переключение вида и динамическая пагинация повторно подключают поведение карточек.

## 2. Простой режим

- Фото группы; если его нет — фото первого доступного исполнения с учётом наследования.
- Цена от минимальной до максимальной среди доступных исполнений текущей выдачи. Сохранить правила «бесплатно / цена по запросу».
- Кнопка с количеством: «N вариантов» (русские формы 1/2/5), ведущая на первое доступное исполнение. Число совпадает с составом карточки и её условиями видимости.
- Поля выбора выводятся только по настройкам соответствующих полей. Они показывают доступные значения, без выбора и без загрузки всех карточек исполнений.

«Первое» в каталоге — действующий представитель группы, выбранный сервером в соответствии с сортировкой/поиском/фильтром. Не подменять его скрытым или не подходящим под выдачу товаром.

## 3. Настройки полей «Список» и «Цвет»

В существующем блоке вариативности добавить независимые настройки карточки группы:

- **Выводить в карточке группы**.
- **Вид элемента выбора**: список или кнопки выбора (для цвета — видимый образец).
- **Формат значения**: использовать существующие варианты текст / образец / образец с подписью там, где они применимы.
- Подпись поля включается отдельно, в соответствии с существующим устройством настроек отображения.

Не переиспользовать параметры обычной карточки товара, полной страницы и фильтра: владельцу нужны независимые настройки. Настройки актуальны для list/color с включённой вариативностью, хранятся обычными params определения поля; значения и поиск сочетаний остаются индексными.

Простой режим показывает статические значения в выбранном формате. AJAX-режим показывает переключаемые элементы. Скрытые оси сохраняют значение текущего исполнения; сервер не должен молча подбирать произвольный товар вместо точного сочетания.

## 4. Режим «Выбор исполнения без перехода»

- Изначально выбран первый доступный товар-представитель; его изображение/галерея, цена и кнопка «В корзину» соответствуют одному и тому же товару/SKU.
- Название группы сохраняется; ссылка карточки ведёт к выбранному исполнению.
- При выборе значения поля отправляется запрос за одним выбранным исполнением. Обновляются фото (либо слайды штатной галереи/Swiper, если она используется), актуальная цена со скидкой, доступность, ссылка и форма покупки.
- Не загружать HTML, фотографии, галереи, цены и SKU всех исполнений заранее. В исходном документе только одно исполнение на группу и компактные значения осей. Нет скрытого массива всех карточек.
- Сервер подбирает точное сочетание group_id + combo_hash, проверяет состав группы, публикацию/ACL товара, категорий, группы и полей; исходные условия выдачи должны учитываться при доступности выбора.
- Невозможное сочетание не меняет выбранный товар и не позволяет добавить другой SKU. Показать понятное сообщение/недоступность выбора, сохранить последний успешный выбор.
- Во время загрузки блокировать повторную покупку; показывать состояние загрузки. Быстрые переключения отменяют устаревший запрос или игнорируют его ответ. Несколько карточек независимы.
- При ошибке сети оставить последнюю успешную карточку и дать повторить действие. Без JS сохраняется переход к выбранному/первому товару.
- Покупка использует существующие сервис/форму корзины с реальной ценой, наличием и правилами товара; группа не становится товаром корзины.

## 5. Реализация и скорость

1. Изучить текущие GroupListing/GroupCardRenderer, макеты group-card, ProductModel, селектор групп, корзину, WAM и события динамического списка.
2. Добавить глобальную настройку и параметры полей с RU/EN переводами и серверной нормализацией.
3. Подготовить данные карточек пакетно; простой режим не должен запускать запросы на каждую группу/ось.
4. Выделить общий серверный подбор/рендер одного исполнения, доступный первоначальному HTML и AJAX; SQL в макетах запрещён.
5. Подключить небольшой скрипт витрины через WAM, делегирование событий/повторную инициализацию после замены списка. Собственного CSS и административного JS не требуется.
6. Все части карточки и элементы выбора переопределяемы; зарегистрировать новые ID в LAYOUTS.md, изображения — через ImageUrl и именованные контексты. Использовать штатный Swiper и действующую корзину.
7. Обновить документацию/журнал, собрать пакет и адресно синхронизировать собственные файлы на test.test. Не запускать dev/sync.sh и не перезаписывать работу Claude.

## 6. Критерии приёмки (сценарии для последующей проверки)

- [ ] Общий режим и настройки полей сохраняются; все подписи переведены.
- [ ] Простой режим: фото, диапазон, кнопка с верным числом, переход к представителю; 1/2/5 вариантов.
- [ ] AJAX: первое исполнение готово без клика; смена цвета/списка обновляет одно исполнение и его корзину.
- [ ] Сочетания нескольких осей, скрытая ось, отсутствующее/неопубликованное/закрытое исполнение не приводят к покупке неверного SKU.
- [ ] Скидки, нулевая цена, отсутствие фото/наследование, один товар в группе.
- [ ] Сетка/список/таблица, несколько групп с обычными товарами, переключение вида/динамическая пагинация, повторный блок той же группы.
- [ ] Быстрые клики/ошибка сети/отключённый JS сохраняют рабочую ссылку и корректный выбранный товар.
- [ ] В исходном HTML/JSON нет полной выгрузки всех исполнений; число запросов первоначального списка не растёт на каждую карточку.
- [ ] Переопределения макетов и обработка изображений сохранены.

Функциональные/нагрузочные проверки запускать по отдельному запросу пользователя. Синтаксические проверки не подтверждают эти сценарии. Не отмечать пункты выполненными до фактической реализации/проверки; этап закрывает пользователь.
