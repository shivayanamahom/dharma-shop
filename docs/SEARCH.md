# Поиск товаров (предложено как C78; номер и запись в DECISIONS — после согласования порядка ведения решений)

## Что сделано

- **Индекс** `#__dharmashop_search` (схема не менялась): `title_norm` — нормализованное название, `body` — артикулы вариантов (всегда) и, по настройкам «Поиск» во вкладке «Каталог», «текст для поиска» (синонимы, по умолчанию да), описание, значения строковых и списочных полей, названия категорий и бренда (по умолчанию нет). **По умолчанию ищется название и артикул** (плюс ручные синонимы карточки). После смены настроек — «Перестроить индекс». Нормализация (`Administrator\Search\SearchText`): нижний регистр, «ё» → «е», всё кроме букв и цифр — пробелы; один код на запись индекса и на запрос.
- **Индексатор** `Administrator\Catalog\SearchIndexer`: диапазон товаров несколькими запросами (без запроса на товар), `INSERT … ON DUPLICATE KEY UPDATE` пачками. Вызывается при сохранении карточки товара (после записи полей), при пакетной обработке и в `Indexer::rebuildRange` (команда «Перестроить индекс», `rebuildAll`). Удаление строки — при удалении товара. Для тестового сайта: `php dev/reindex-search.php`.
- **Запрос** `Site\Search\ProductSearch`: слова запроса ≥ 3 символов — FULLTEXT в булевом режиме по началу слова (`+слово*`, все слова обязательны); короче 3 символов (InnoDB их не индексирует) — начало слова в названии среди найденных (или только оно, если все слова короткие); артикул (одно слово из букв, цифр и `. _ - /`) — префикс по уникальному индексу `variants.sku`, такие товары выше всех. **Релевантность:** оценка FULLTEXT + 100 за каждое слово запроса в названии (по началу слова) + 50, если название начинается с запроса целиком; артикул — 1000; при равных оценках — новее выше. Сортировки по цене, названию, новизне и «ручной порядок» стабильны (второй ключ — id), страницы не дублируют и не теряют товары. Подзапрос `product_id, score` присоединяется к обычному запросу списка (видимость, категории и доступ — те же, что в каталоге). Значения всегда параметрами; в булев запрос попадают только буквы и цифры. Длина запроса ≤ 100.
- **Раскладка и транслитерация** (настройка включена по умолчанию, `SearchText::variants`): каждое слово запроса ищется ещё и в другой раскладке («ыфьыгтп» → samsung) и в транслитерации в обе стороны («самсунг» → samsung, «parma» → парма; «кс» → x: «галакси» → galaxy, «ксиаоми» → xiaomi). Товар должен содержать каждое слово хотя бы в одном из вариантов (`+(вариант* вариант*)`).
- **Запись «на слух» (2026-10-09, без словарей):** `SearchText::phoneticVariants` — правила произношения в обе стороны, а не списки слов: кириллица → латиница («ай» → ay/ai/i/y, «ф» → f/ph, «в» → v/w, «ей» → ey/ei, «х» → h/kh, «у» → u/oo: «айфон» → iphon, «хуавей» → huawei, «дайсон» → dyson, «гугл» → googl); латиница → кириллица (ph → ф, i → и/ай, y → и/ай, конечная e не читается, c → к/с/ц, ch → ч/ш/к/х, диакритика сворачивается: «iphone» → айфон, «chanel» → шанел, «nike» → найк, «bosch» → бош). Работает для любых товаров (духи, арматура, запчасти), без индекса и словарей, только на стороне запроса: варианты ищутся по началу слова, их число ограничено (до 10 на слово, всего до 14), порядок — от самых вероятных. Ограничение: правила не знают исключений, где чтение не следует из написания («сяоми» ↔ xiaomi, «ванплас» ↔ OnePlus, «блютус» ↔ Bluetooth) — такие слова магазин добавляет правилами синонимов (ниже); в будущем — «Вы искали» с добавлением правила в один клик.
- **Синонимы запроса** (настройка, по правилу в строке «слово = вариант, вариант»): запрос с левым словом дополнительно ищет варианты справа; для того, чего транслитерация не угадает («айфон = iphone», «гугл = google»).
- **Мягкий режим** (настройка, по умолчанию да): если запрос ничего не нашёл, слова от 5 букв ищутся без двух последних («самсун», «samsug», «iphne»). Один дополнительный COUNT только при пустом результате. Ошибки в середине или в начале слова («samsnug», «ipone») не исправляются. **Решение пользователя (2026-10-08): остановиться на мягком режиме.** Если понадобится — словарь слов индекса (отдельная таблица `#__dharmashop_search_words`, расстояние Левенштейна среди слов с тем же началом) и подстановка ближайшего слова; это изменение схемы, делать после согласования с Codex.
- **Адрес поиска — `?filter[search]=…`** (как на Parmaled: `/katalog?filter[search]=свет`). Это общий формат параметров фильтра каталога: условия будущего модуля фильтра (цена, поля, наличие) пойдут в тот же массив `filter[…]` и вместе с поиском сохраняются при смене сортировки, вида и страницы (`listing.js` переносит все `filter[…]`, ссылки страниц их содержат). Старый `?q=` читается для совместимости, но не генерируется.
- **Поиск на любой странице списка** (`CategoryModel`, `ProductSearch::fromInput`): каталог, категория, бренд, бейдж. Сортировка «По релевантности» (по умолчанию при запросе), обычные сортировки и вид сохраняют запрос (`listing.js` переносит `filter[…]`, ссылки страниц содержат `filter[search]`), плитки подкатегорий скрыты; без отдельной строки «найдено» и кнопки сброса — страница открывается как обычный отфильтрованный список, пустой результат — «Ничего не найдено…»; `noindex, follow`.
- **Страница «Поиск»** (вид `search`, тип пункта меню «Результаты поиска», настройки отображения — как у категории) — запасной вариант, если в меню нет страницы каталога.
- **Подсказки** `SearchController::suggest` (`task=search.suggest&format=json&q=…&limit=…` — внутренний запрос подсказок, GET, только чтение): товары (название, фото, категория, артикул, цена с учётом замены нулевой цены, наличие), основные категории найденных товаров с числом (ссылка — категория с тем же `filter[search]`), общее число. Предел `limit` — 20.
- **Модуль `mod_dharmashop_search`:** серое поле без рамки, лупа справа (из коробки). Настройки: страница результатов (по умолчанию — страница каталога, иначе «Поиск»), подсказка в поле, минимум символов, задержка, число товаров, подсказки вкл/выкл, фото, категория товара, артикул, найденные категории, цена и наличие, кнопка «Все результаты», кнопка поиска (текст, значок), классы поля и кнопки. Без JavaScript форма обычным GET уходит на страницу результатов.

## Как устроен модуль (без inline-кода)

Скрипт `search.js` подключает Web Asset Manager; настройки — data-атрибуты формы, тексты — `Joomla.Text`. Разметку подсказок скрипт берёт из `<template data-dharmashop-search-template="item|category|all|message">` в `tmpl/default.php` и подставляет значения в элементы `[data-field]` через `textContent`; поэтому вид меняется переопределением `templates/<шаблон>/html/mod_dharmashop_search/default.php` без правки JS. Подсвечивается совпадение (DOM-методами, без innerHTML). Клавиатура: ↑/↓, Enter, Esc. Стили — один небольшой файл `media/mod_dharmashop_search/css/search.css` (минимальная ширина и высота списка подсказок: утилит Bootstrap для них нет; переменные `--dharma-search-results-min`, `--dharma-search-results-max-height`); остальное — классы Bootstrap. Это второе (после мини-корзины, C67) отступление от «на сайте только Bootstrap»: требуется подтверждение пользователя в AGENTS/DECISIONS.

## Ограничения и дальше

- InnoDB не знает морфологии: ищем по началу слова («телефон» найдёт «телефоны», но не наоборот; транслитерация, исправление раскладки и запись «на слух» — на стороне запроса, ошибки в середине слова и исключения произношения ловят только синонимы).
- Слова короче 3 символов: проверка по названию (при запросе только из коротких слов — просмотр индекса по `title_norm`; на очень больших каталогах дорого, замеры — отдельным шагом).
- Ещё нужно: замеры на 100 тыс. товаров, интеграция с Умным поиском Joomla (`finder`), транслитерация, «Вы искали», поиск внутри фильтра.
