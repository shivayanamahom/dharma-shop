# Dharma Shop — журнал решений

Статусы: **ПРИНЯТО** — решил пользователь (не переспрашивать); **ПРЕДЛОЖЕНО** — предложение архитектора, пока не подтверждено; **ОТКРЫТО** — нужно решить.
Каждое новое решение дописывайте в конец своего раздела с датой. Текущее состояние работ — в `ROADMAP.md`.

## A. Цель и границы (ПРИНЯТО, из START_HERE.md)

| № | Решение |
|---|---|
| A1 | Продукт — **универсальный лёгкий e-commerce для Joomla 6+**: базовый компонент + плагины, модули, отдельные компоненты. Продукт для будущих сайтов, а не замена конкретного сайта. |
| A2 | Поставил базу — сразу есть каталог-витрина с корзиной: список, фильтр, карточка, варианты, поля, корзина, заявка/заказ, письма. |
| A3 | **Размер каталога не имеет значения:** схема и запросы рассчитаны на 100 и на 100 000+ товаров одинаково (индексы, пагинация по индексу, без выборок из JSON при фильтрации и сортировке). |
| A4 | Онлайн-оплата, доставка, «заявка вместо оплаты», уведомления, типы полей — **плагины**. В ядре только базовая логика заказа и точки расширения. |
| A5 | Число сайтов и функции RadicalMart на боевых сайтах значения не имеют. Ориентир по составу разделов — меню RadicalMart: Заказы · Корзины · Покупатели · Товары · Мета-товары · Категории · Порядок товаров · Поля · Группы полей · Статусы заказов · Способы доставки · Способы оплаты · Аналитика · Настройки (см. C4: «Мета-товары» заменены вариантами). |
| A6 | Причина проекта: не платить лицензию за каждый сайт; RadicalMart скоро станет платным. |

## B. Правила разработки (ПРИНЯТО)

| № | Решение |
|---|---|
| B1 | **Не плагиат.** Ни строки кода, ни структуры файлов и имён RadicalMart. Свой знак «Dharma», своя схема БД, свои имена событий. |
| B2 | **100 % нативный интерфейс Joomla** в админке: Form XML (subform, showon, uitab, searchtools), штатный тулбар и сообщения; свой JS/CSS только в одобренных исключениях C13 (загрузчик) и C72 (поиск настроек, только JS без CSS). На сайте: только классы Bootstrap 5, без отдельного CSS компонента и собственных inline-стилей (уточнение 2026-10-07); переопределения в шаблоне `dharma_starter`, минимум JS. |
| B3 | Всё, что нужно не каждому магазину, — в плагины/модули/компоненты. В ядре только базовые события. |

| B5 | Перенос данных с RadicalMart — отдельная консольная команда, читает `#__radicalmart_*`. Совместимость по данным, не по коду. |

**C80 — Доставка: раздел, типы-плагины и общие правила для плагинов (ПРИНЯТО по запросу пользователя, 2026-10-08).** «Доставка» — отдельный раздел меню админки (затем «Оплата» по тем же правилам); способ создаётся выбором типа, каждый тип — отдельный плагин группы `dharmashopshipping` с макетом на сайте, переопределяемым в шаблоне. Тип регистрируется событием `onDharmaShopShippingTypesCollect` и реализует `TypeInterface` (настройки, расчёт, сведения, проверка ввода покупателя, макет). Информация плагина — строки `{label, value}` обычным текстом — одинаково попадает в боковую панель оформления, снимок заказа `shipping_data`, админку, страницу заказа и письма; показ из снимка не зависит от плагина. Цену и доступность считает сервер; из браузера принимаются только id способа и поля. Первые типы: «Стандартная доставка» (цена, бесплатно от суммы заказа, ограничения по сумме, срок, конструктор полей покупателя) и «Самовывоз» (пункт выдачи с контактами, часами, описанием и картой). Подробно — `docs/SHIPPING.md`.

**C82 — Цена 0 — бесплатно (ПРИНЯТО по запросу пользователя, 2026-10-09).** Пустая цена в форме товара всегда сохраняется как 0 (товар покупается). Правило «цена 0 — бесплатно» (`products.price_zero_free` NULL/0/1; в категории — `order_price_zero_free`; наследование товар → категория → родители, встроенное «нет», общей настройки магазина нет) заменяет «Цену по запросу» на «Бесплатно» на витрине, в корзине, заказе и письмах; признак записывается в строку заказа (`order_items.params.zero_free`). Нужно для бонусных товаров, выдаваемых бесплатно (скрытая категория, цена 0).

**C83 — Оплата: раздел, типы-плагины, правило «оплата для доставки» (ПРИНЯТО по запросу пользователя, 2026-10-09).** «Оплата» — отдельный раздел меню с тем же принципом, что «Доставка» (C80): способ создаётся выбором типа (плагины группы `dharmashoppayment`: «Стандартная оплата» — вне сайта, «Тестовая оплата» — песочница шлюза). Тип решает, что будет после заказа (`Initiation`: ничего / страница оплаты сайта / переход на шлюз) и обрабатывает обратные вызовы (`handle` → `Outcome`); ядро применяет итог (статус оплаты заказа, `payments`, статус «после оплаты», событие). Правило «какая оплата доступна для доставки» — `shipping_methods.payment_ids` (поле в боковой колонке формы доставки). Цена способа оплаты (наценка) в ядре не вводится. Подробности — `docs/PAYMENTS.md`.

**C81 — Склады как отдельная сущность (ПРИНЯТО по запросу пользователя, 2026-10-08).** Склады — справочник магазина с разделом «Склады» в меню админки (таблица `#__dharmashop_warehouses`: адрес, контакты, часы работы, дополнительная информация, срок готовности самовывоза, координаты в формате Яндекса, изображение, состояние, доступ, порядок). Способы доставки не хранят склады у себя, а выбирают их из справочника (самовывоз — пункты выдачи, курьер — откуда считать расстояние); справочник понадобится и другим частям магазина. Подробно — `docs/WAREHOUSES.md`.

Дополнение C79 по прямому запросу пользователя: общий кеш `v2/<aa>/<bb>/…` без папок контекстов. Контекст выбирает настройки; один исходник с одинаковыми эффективными размерами, режимом, форматом и качеством использует один файл/URL/lock во всех местах. Формат нормализуется после fallback, для PNG качество постоянно (lossless). Прежний v1 и оригиналы не удаляются автоматически.

Дополнение C79 по прямому запросу пользователя: в «Товары → Команды» — подготовка одного/всех контекстов порциями через действующий плагин и очистка общего кеша после предварительного подсчёта и подтверждения. Исходники сохраняются, обработка продолжается по сессионному курсору; удаление только известных производных текущей папки v1/v2 с блокировками. Подробнее IMAGE_RESIZE.md.
