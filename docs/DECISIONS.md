# Dharma Shop — журнал решений

Статусы: **ПРИНЯТО** — решил пользователь (не переспрашивать); **ПРЕДЛОЖЕНО** — предложение архитектора, пока не подтверждено; **ОТКРЫТО** — нужно решить.
Каждое новое решение дописывайте в конец своего раздела с датой. Текущее состояние работ — в `ROADMAP.md`.

## A. Цель и границы (ПРИНЯТО, из START_HERE.md)

| № | Решение |
|---|---|
| A1 | Продукт — **универсальный лёгкий e-commerce для Joomla 6+**: базовый компонент + плагины, модули, отдельные компоненты. Продукт для будущих сайтов, а не замена конкретного сайта. |
| A2 | Поставил базу — сразу есть каталог-витрина с корзиной: список, фильтр, карточка, варианты, поля, корзина, заявка/заказ, письма. |
| A3 | **Размер каталога не имеет значения:** схема и запросы рассчитаны на 100 и на 100 000+ товаров одинаково (индексы, пагинация по индексу, без выборок из JSON при фильтрации и сортировке). |
| A4 | Онлайн-оплата, доставка, «заявка вместо оплаты», уведомления, типы полей — **плагины**. В ядре только базовая логика заказа и точки расширения. |
| A5 | Число сайтов и функции RadicalMart на боевых сайтах значения не имеют. Ориентир по составу разделов — меню RadicalMart: Заказы · Корзины · Покупатели · Товары · Мета-товары · Категории · Порядок товаров · Поля · Группы полей · Статусы заказов · Способы доставки · Способы оплаты · Аналитика · Настройки (см. C4: «Мета-товары» заменены вариантами). |
| A6 | Причина проекта: не платить лицензию за каждый сайт; RadicalMart скоро станет платным. |

## B. Правила разработки (ПРИНЯТО)

| № | Решение |

| B2 | **100 % нативный интерфейс Joomla** в админке: Form XML (subform, showon, uitab, searchtools), штатный тулбар и сообщения; никакого своего JS/CSS. На сайте: Bootstrap 5, переопределения в шаблоне `dharma_starter`, минимум JS, стили на переменных `--dharma-*`. |

## E. Архитектурные решения (подтверждены принятием схемы, C5)

| № | Решение | Альтернатива и причина отказа |
|---|---|---|
| E1 | **Категории — штатные Joomla** (`#__categories`, `extension='com_dharmashop'`). | Своя таблица со своим nested set: больше кода, нет выигрыша. |
| E2 | **Товар + варианты** (C3). | Одна таблица с видами `kind` (как мета-товары): особые случаи в корзине и заказе, производные данные. |
| E3 | **Поля — свои таблицы** с индексируемыми столбцами `option_id`/`num`/`str`. | Штатные Custom Fields: значения текстом, нет числового индекса, на 100 тыс. товаров фильтр не масштабируется. |
| E4 | **Витринный индекс** `product_categories` с родительскими категориями и денормализованными столбцами сортировки. Цена решения: пересборка при перемещении категорий (`reindex`). | `catid IN (...)` + `DISTINCT` по товарам: filesort и дубли. |
| E5 | **Цены в отдельной таблице** по прайс-листам, эффективная цена `price_final` в столбце; цена «по запросу» = `price IS NULL`. Вычислять скидку на лету нельзя — ломает индекс. | Столбцы цены в товаре: мультивалютность и оптовые цены потом потребуют миграции. |
| E6 | **У товара нет своего `access` и дат публикации в v1.** Доступ — через категорию. | Индекс листинга с `access IN (...)` теряет порядок. Добавим при реальной потребности. |
| E7 | **Корзина и заказ — строки в БД**, не JSON; итоги — отдельными строками (`order_adjustments`); снимок названия/артикула/цены в позиции. | JSON в заказе: нельзя искать и считать SQL. |
