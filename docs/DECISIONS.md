# Dharma Shop — журнал решений

Статусы: **ПРИНЯТО** — решил пользователь (не переспрашивать); **ПРЕДЛОЖЕНО** — предложение архитектора, пока не подтверждено; **ОТКРЫТО** — нужно решить.
Каждое новое решение дописывайте в конец своего раздела с датой. Текущее состояние работ — в `ROADMAP.md`.

## A. Цель и границы (ПРИНЯТО, из START_HERE.md)

| № | Решение |
|---|---|
| A1 | Продукт — **универсальный лёгкий e-commerce для Joomla 6+**: базовый компонент + плагины, модули, отдельные компоненты. Продукт для будущих сайтов, а не замена конкретного сайта. |
| A2 | Поставил базу — сразу есть каталог-витрина с корзиной: список, фильтр, карточка, варианты, поля, корзина, заявка/заказ, письма. |
| A3 | **Размер каталога не имеет значения:** схема и запросы рассчитаны на 100 и на 100 000+ товаров одинаково (индексы, пагинация по индексу, без выборок из JSON при фильтрации и сортировке). |
| A4 | Онлайн-оплата, доставка, «заявка вместо оплаты», уведомления, типы полей — **плагины**. В ядре только базовая логика заказа и точки расширения. |
| A5 | Число сайтов и функции RadicalMart на боевых сайтах значения не имеют. Ориентир по составу разделов — меню RadicalMart: Заказы · Корзины · Покупатели · Товары · Мета-товары · Категории · Порядок товаров · Поля · Группы полей · Статусы заказов · Способы доставки · Способы оплаты · Аналитика · Настройки (см. C4: «Мета-товары» заменены вариантами). |
| A6 | Причина проекта: не платить лицензию за каждый сайт; RadicalMart скоро станет платным. |

## B. Правила разработки (ПРИНЯТО)

| № | Решение |
|---|---|
| B1 | **Не плагиат.** Ни строки кода, ни структуры файлов и имён RadicalMart. Свой знак «Dharma», своя схема БД, свои имена событий. |
| B2 | **100 % нативный интерфейс Joomla** в админке: Form XML (subform, showon, uitab, searchtools), штатный тулбар и сообщения; никакого своего JS/CSS. На сайте: Bootstrap 5, переопределения в шаблоне `dharma_starter`, минимум JS, стили на переменных `--dharma-*`. |
| B3 | Всё, что нужно не каждому магазину, — в плагины/модули/компоненты. В ядре только базовые события. |
| B4 | Цена, остаток и значения полей — в **настоящих индексируемых столбцах и таблицах**, не в JSON. |
| B5 | Перенос данных с RadicalMart — отдельная консольная команда, читает `#__radicalmart_*`. Совместимость по данным, не по коду. |
| B6 | Рабочий тестовый сайт — **https://test.test** (`/Volumes/Work/Server/www/test`, чистая Joomla 6.1.4). `dharmatest.test` (RadicalMart 3.0.27) — только чтение. Остальные сайты без прямой просьбы не трогаем. |
| B7 | GitHub-репозиторий — приватный. Создан 2026-10-06 по прямому разрешению пользователя (см. G1). |
| B8 | Документация для других ИИ: `AGENTS.md`, `README.md`, `docs/ARCHITECTURE.md`, `docs/DEVELOPMENT.md`, `docs/ROADMAP.md`. |
| B9 | Перед крупными шагами — согласование с пользователем. Работаем **поэтапно**, после каждого этапа показ и приёмка (см. ROADMAP.md). |
| B10 | **Чистая комната (2026-10-06).** Модель, схема, имена и код — свои. Исходники RadicalMart не читаем и не переписываем; от него берём только схему таблиц (для переноса данных) и поведение в админке как справку. Цель — чтобы код не выглядел как у авторов RM, а функционал был не хуже и продуманнее. |
| B11 | **Версии (2026-10-06):** в разработке версия не меняется, остаётся `0.1.0`; без автосинхронизации версий и без «бампов» в каждом коммите. Версию повышаем только при релизе, по просьбе пользователя. |

## C. Решения пользователя в чате 2026-10-06 (ПРИНЯТО)

| № | Решение | Следствия |
|---|---|---|
| C1 | **Название: «Dharma Shop», компонент `com_dharmashop`.** | Таблицы `#__dharmashop_*`; пространство имён `Dharma\Component\DharmaShop`; плагины `plg_dharmashop*_*`; модули `mod_dharmashop_*`; события `onDharmaShop*`; языковые ключи `COM_DHARMASHOP_*`; пакет `pkg_dharmashop`. |
| C2 | **Многоязычность: магазин одноязычный, переводятся только языковые файлы.** | В таблицах **нет столбца `language`**. Интерфейс переводится штатными `.ini`. Если многоязычный каталог понадобится, это будет миграция схемы (столбец + Associations), а не настройка. |
| C3 | **Модель «товар → варианты» вместо «мета-товаров»** (термин RadicalMart). Товар — карточка, вариант — то, что продаётся; у любого товара минимум один вариант; корзина и заказ ссылаются на вариант. | Одна таблица товаров без поля `kind`; нет производных значений мета-товара; раздела «Мета-товары» в админке нет. |
| C4 | **В интерфейсе «Поля» и «Группы полей»** (привычнее, чем «Характеристики»). Поле — общее понятие: кроме коротких данных это галерея, файлы, видео, таблица характеристик и другие типизированные блоки. | Типы полей имеют способ хранения `option`/`number`/`string`/`text`/`media`; галерея — тип поля, а не отдельная сущность товара. |
| C5 | **Утверждена схема архитектора** (товар/вариант/цены по прайс-листам/остатки по складам с журналом/статусы с переходами) и порядок этапов 0–5. | См. ARCHITECTURE.md. Прайс-листы и склады в интерфейсе v1 не выводятся. |
| C7 | **Типы категорий (2026-10-06):** «категория» бывает разных типов — **просто категория, бренд и бейджи**. | Реализовано как три секции штатных категорий Joomla (`com_dharmashop`, `.brand`, `.badge`), привязка товара в общем индексе витрины; бренд — один на товар, бейджей несколько; см. ARCHITECTURE.md §5.1. |
| C6 | **Ведение процесса:** планы и прогресс хранятся в репозитории, чтобы подключать других ИИ. | `AGENTS.md`, `docs/ROADMAP.md`. |

## E. Архитектурные решения (подтверждены принятием схемы, C5)

| № | Решение | Альтернатива и причина отказа |
|---|---|---|
| E1 | **Категории — штатные Joomla** (`#__categories`, `extension='com_dharmashop'`). | Своя таблица со своим nested set: больше кода, нет выигрыша. |
| E2 | **Товар + варианты** (C3). | Одна таблица с видами `kind` (как мета-товары): особые случаи в корзине и заказе, производные данные. |
| E3 | **Поля — свои таблицы** с индексируемыми столбцами `option_id`/`num`/`str`. | Штатные Custom Fields: значения текстом, нет числового индекса, на 100 тыс. товаров фильтр не масштабируется. |
| E4 | **Витринный индекс** `product_categories` с родительскими категориями и денормализованными столбцами сортировки. Цена решения: пересборка при перемещении категорий (`reindex`). | `catid IN (...)` + `DISTINCT` по товарам: filesort и дубли. |
| E5 | **Цены в отдельной таблице** по прайс-листам, эффективная цена `price_final` в столбце; цена «по запросу» = `price IS NULL`. Вычислять скидку на лету нельзя — ломает индекс. | Столбцы цены в товаре: мультивалютность и оптовые цены потом потребуют миграции. |
| E6 | **У товара нет своего `access` и дат публикации в v1.** Доступ — через категорию. | Индекс листинга с `access IN (...)` теряет порядок. Добавим при реальной потребности. |
| E7 | **Корзина и заказ — строки в БД**, не JSON; итоги — отдельными строками (`order_adjustments`); снимок названия/артикула/цены в позиции. | JSON в заказе: нельзя искать и считать SQL. |
| E8 | **Письма — штатные шаблоны Joomla** (`com_mails`). Telegram и прочее — плагины `dharmashopnotify`. | Свой редактор писем нарушает B2. |
| E9 | **Поиск:** таблица `search` с FULLTEXT + префиксный поиск по артикулу; Умный поиск Joomla — плагином `finder`. | `LIKE '%…%'`: полный скан. |
| E10 | **Перенос с RM — консольный плагин** вне ядра, идемпотентный (`external_ids`). | Перенос внутри компонента тащит RM-специфику в ядро. |
| E11 | **Состав пакета** `pkg_dharmashop` из вложенных zip: ядро + system-плагин + задачи + стандартные доставка и оффлайн-оплата + модули. Остальное — отдельными пакетами. | — |
| E13 | **ПРЕДЛОЖЕНО (2026-10-06, по замерам этапа 0): счётчики значений фильтра на лету не считаем** (50–100 мс на поле на 100 тыс. товаров). По умолчанию показываем фильтр без счётчиков; счётчики включаются настройкой и берутся из кэша по ключу «категория + выбранные значения» либо из предрасчёта «без фильтра» (таблица, обновляется `reindex`). Решить на этапе 2. | Счётчики на лету при каждом показе: 0,5–0,8 с на запрос при 8 полях. |
| E14 | **ПРЕДЛОЖЕНО (2026-10-06, по сравнению с RM): модули выборки товаров ходят только по индексу витрины**, без обращений к таблице товаров с сортировкой/фильтром; вклад магазина в обычные страницы сайта измеряется. | Запрос по всей таблице товаров на каждой странице (как у RM: 133 мс на 50 тыс.). |
| E15 | **Бренды и бейджи как секции категорий Joomla** (C7): нативный интерфейс, права и дерево бесплатно; привязка в `product_categories`; дополнительные поля формы — через `prepareForm()` компонента. Бренд — один на товар (поле формы — одиночный выбор), бейджи — множественный. | Свои таблицы брендов и бейджей: свой интерфейс и свои запросы, нарушает B2. |
| E16 | **Сохранение товара без транзакции вокруг карточки** (причина — `LOCK TABLES` в `Table::store`): проверки до записи, транзакция только вокруг зависимых данных, компенсация при сбое (ARCHITECTURE.md §5.13). | Одна общая транзакция — не работает (неявная фиксация). |
| E12 | **Остатки по складам** (`stock_levels`, резерв) и журнал движений (`stock_movements`); статусы заказа с разрешёнными переходами (`status_transitions`). В v1 один склад, склады в UI — этап 4. | Одно число остатка: аудит и мультисклад потом требуют миграции. |
