# Макеты Dharma Shop

## Единые настройки отображения

Общие параметры оформления сгруппированы во вкладке «Отображение» настроек компонента: списки категорий/брендов/бейджей, карточка товара в списке, страница товара. Карточка в списке и полная страница товара имеют отдельные настройки скидки и таймера; переименование fieldset не меняет имена параметров.

Наследование параметров списков товаров: общие настройки → родители → текущая категория/бренд/бейдж → пункт меню. Пустое значение означает «наследовать». Пункт меню и запись категории, бренда или бейджа могут задать макет страницы и карточек, режим состава списка, вид и колонки, количество фото, кнопку корзины, скидку и таймер. Для всех трёх страниц доступны отдельные формы пункта меню. В частности, `category_listing_mode` теперь передаётся модели до загрузки товаров, поэтому локальный режим «Товары / Группы товаров и товары» применяется на самой странице.

Для страницы товара макет, галерея и параметры скидки/таймера разрешаются по цепочке: общие настройки → товар → принадлежащий ему пункт меню. Пункт меню имеет приоритет, пустые поля оставляют уровень наследования без изменений. Эти параметры доступны в форме товара и пункте меню на вкладке «Отображение».

Страница избранного наследует сетку от общих настроек, а её пункт меню может задать обычное или адаптивное число колонок. При адаптивном режиме используются Bootstrap-брейкпоинты XS, SM, MD, LG, XL и XXL; стандартный режим сохраняет одну колонку на узком экране и исходную настройку на широком. Устаревший параметр `favorites_columns` продолжает работать как базовое число колонок.

Общий перенос явно заданных параметров выполняет `Site\Support\DisplaySettings`; `ListingTrait` отдельно сохраняет нулевой `list_limit` как маркер наследования.

## Фильтр и внутренние позиции (2026-10-12)

Позиции Joomla: `dharmashop-products-top` под подкатегориями; `dharmashop-products-left` и `dharmashop-products-right` по сторонам товаров. Их добавляет system plugin dharmashoppositions в штатное поле позиции модуля. Учитываются назначения меню/ACL/публикация. CatalogModules выводит их в category/brand/badge/search. На широком экране боковая колонка занимает 3/12, основная — оставшиеся 12/9/6; на узком экране колонки последовательные. Формат horizontal задаётся в модуле отдельно от позиции.

Макеты controls: `mod_dharmashop_filter/layouts/mod_dharmashop_filter/control/`. Путь переопределения: `templates/<шаблон>/html/layouts/mod_dharmashop_filter/control/<имя>.php`.

| Файл | Назначение |
|---|---|
| checkboxes, radio, select | Флажки, один выбор, список |
| buttons, swatches, images | Кнопки, цвет/текстура, изображения |
| options | Общая разметка флажков/кнопок, поиск и «ещё» |
| range | Композиция шкалы, числовых полей и быстрых интервалов |
| range-slider, range-inputs | Одна шкала с двумя бегунками / два числовых поля |
| switch | Наличие/акция |

В displayData передаются section и module (ID). Section содержит name/title/kind/control/options; у option — value/label/checked/disabled/count/color/image; диапазон получает bounds/value/step/slider/presets. SQL в layouts не выполняется. Переопределение всей формы: `templates/<шаблон>/html/mod_dharmashop_filter/default.php`.

Пример оформления только флажков: скопировать options.php в переопределение, изменить классы label (например добавить `fw-semibold`), остальные wrappers оставить. buttons/radio/swatches/images также используют options; для отдельного оформления проверять `$control`. Для числового фильтра без шкалы можно переопределить range.php:

```php
<?php
defined('_JEXEC') or die;
$layout = new Joomla\CMS\Layout\FileLayout('mod_dharmashop_filter.control.range-inputs');
$layout->addIncludePath(JPATH_ROOT . '/modules/mod_dharmashop_filter/layouts');
echo $layout->render($displayData);
```

Сохранять names/values/label-for/id, disabled/checked и экранирование; для JS — data-dharmashop-filter, data-filter-options/option/label/search/more, data-dharmashop-slider/min/max, data-from/to и data-slider-track. Для выбранного числа в dropdown — data-filter-selected-count внутри .dharmaFilterSection. Без JS все значения/числовые поля остаются доступны. ImageUrl контексты: field.color.filter и field.option.filter.

## Контексты изображений C79

Макеты получают URL через `Administrator\Image\ImageUrl::resolve($path, $context)`. Плагин `dharmashop/imageresize` подбирает размеры из настроек магазина; без него используется оригинал. Стили и данные снимков заказа не меняются. Полный реестр и инструкция расширения — [IMAGE_RESIZE.md](IMAGE_RESIZE.md).

Общая точка `product-card/default.php` передаёт `imageContext`: `product.category.grid/list/table`, на странице поиска — `search.grid/list/table`. Бренды/бейджи используют те же товарные контексты. Вызывающий модуль может явно передать `module.products.grid/list/table` (зарезервированы для будущего модуля). Большая галерея, миниатюры и ссылка лайтбокса — `product.main`, `product.thumb`, `product.lightbox`; картинка раздела и карточка раздела — `category/brand/badge.header` и `.card`. Остальные: `cart.page`, `cart.module`, `cart.toast`, `search.module`, `field.option`, `admin.product`, `admin.category`, `email.product`, `email.logo`.

Переопределения шаблона должны сохранять вызов `ImageUrl::resolve`; HTML-адрес экранировать. Нулевая сторона — авто, две нулевые — оригинал. Настройки не меняют размеры CSS-блоков, только получаемый файл.

Здесь описаны папки PHP-макетов сайта и то, какие из них выбираются в админке. Варианты не перечисляются вручную: имя каждого файла `.php` в папке слота автоматически появляется в соответствующем выпадающем списке. Например, файл `default.php` отображается как `default.php`, а в настройке хранится `default`.

## Правила

Поля поддерживают `field.show_title` (по умолчанию true), подготовленный из `params.show_title_card/page`. Интро наследует page. Общий `fields/default` визуально скрывает выключенный заголовок и отдаёт значению всю ширину; для файлов, галерей и видео заголовок размещается над карточками. Табличный список сохраняет семантический заголовок колонки, скрывая его текст. `fields/files.php` использует `field.file_settings`; `fields/gallery.php` — `field.gallery_settings.gallery_layout=grid/slider`, `gallery_columns_xs/sm/md/lg/xl/xxl=1…6`, `gallery_lightbox` и `gallery_caption`; `fields/video.php` использует `field.video_settings` и общий контракт `FieldGallery` для Swiper/Fancybox. Оба вида видео (grid/slider) и карточка `video/item.php` переопределяются отдельно в `templates/<template>/html/layouts/components/dharmashop/fields/video/`.

1. `administrator/components/com_dharmashop/tmpl` содержит экраны админки и никогда не используется как список витринных макетов.
2. Страницы лежат в `com_dharmashop/site/tmpl/` и устанавливаются в `/components/com_dharmashop/tmpl/`. Подключаемые карточки лежат в `files_dharmashop_layouts/layouts/` и устанавливаются в `/layouts/components/dharmashop/` (C32).
3. Для каждой записи показывается только `.php` из папки своего слота. Не нужно вручную добавлять название в XML формы или языковые файлы.
4. Пустой выбор товара использует общий выбор магазина. Пустой выбор категории наследуется от родителя, затем от общих настроек магазина.
5. Удалённый файл не сбрасывает уже сохранённый выбор: прежнее имя показывается с пометкой «файл не найден», пока администратор не выберет другой файл.
6. Папки и формы должны использовать собственные имена Dharma Shop. Чужие исходники и имена не копируются.

## Подтверждение и свой заказ (C75)

Контейнер подтверждения `#dharma_shop.dharmaCheckoutComplete`, блоки `dharmaCheckoutSuccess` / `dharmaCheckoutReceipt`. Контейнер заказа `#dharma_shop.dharmaOrder`; блоки `dharmaOrderItems`, `dharmaOrderContacts`, `dharmaOrderSummary`. Оболочка заказа подключает отдельные части items/contacts/summary; сетка Bootstrap 8/4, на узком экране одна колонка. Без CSS/inline-стилей, заголовок fs-4, итог fs-5, остальные элементы fs-6/small. Переопределения в `templates/<template>/html/com_dharmashop/order/` и `checkoutcomplete/`. Данные снимка экранируются; описание товара и служебные заметки не выводятся.

## Выбор раздела в пункте меню

### Принятое общее оформление товаров (C33)

Для товаров бренда и бейджа по умолчанию используются шаблон «Товары категории» (`category_layout`) и карточка товара (`product_card_layout`). По C34 подключена базовая страница `tmpl/category/default.php`; три карточки grid/list/table пока пустые. Переключатель «Использовать оформление списка товаров» для бренда/бейджа ещё впереди, по умолчанию он будет включён. При отключении раздел сможет использовать собственные файлы, начальное оформление которых берётся из нашего базового списка; эти файлы создаются при реализации, не копируются автоматически на каждом запросе.

Общий выбор файлов относится к оформлению; категория, бренд и бейдж сохраняют собственные товары, заголовок, тексты и SEO. Список самих категорий использует свои `categories_layout` и `category_card_layout`. Существующие заготовки списков брендов/бейджей не считаются реализацией этого решения; состав их экранов и моделей определяется отдельно.

### Поле выбора

В выборе раздела пункта меню `categories`, `category` и `brands` используется нативный список Joomla с поиском (`joomla.form.field.list-fancy-select`). Во всех трёх включён `show_root=true`: вариант «Корень» соответствует `id=0`, для товаров категории означает весь каталог. Бейджи плоские, выбора родителя в их меню нет. C34 подключил корень товаров категории; брендовый вид остаётся заготовкой.

## Каркас списка товаров C34 и ресурсы C35

`Site\Model\CategoryModel` наследует проверку категории, корня и прямых подкатегорий от CategoriesModel. `Site\View\Category\HtmlView` получает данные, параметры и SEO, `tmpl/category/default.php` выводит: h1 → основное изображение категории (настраивается отдельно, по умолчанию скрыто) / интро → подкатегории → панель сортировки и вида → итоги (если включены) → контейнер товаров → переход порциями → полное описание. Четыре события Category сохранены вокруг заголовка и всего контента. Подкатегории подключают наш готовый category-card, их ссылки ведут на товары выбранной подкатегории внутри пункта меню.

`product_view=grid/list/table` выбирает соответствующий `components.dharmashop.product-card.<mode>`. Grid уже показывает минимальные данные по C38; list/table пока пусты. Для grid/list страница создаёт внешнюю `.col`, карточка возвращает свой блок без `.col`; для table страница создаёт responsive-таблицу и tbody, карточка должна вернуть tr. Grid использует Grid::classes(params, category), list — row-cols-1. Старое значение настройки `default` читается как grid. Значение без посетительского выбора наследуется от меню/категории/родителей/магазина; новые глобальные настройки по умолчанию grid. Имена файлов по-прежнему сканируются автоматически, arbitrary безопасный файл настройки допускается, но посетительский переключатель содержит только три режима.

Панель — GET-форма с `sort`, `product_view` и текущим `start`. `listing.js` (`com_dharmashop.listing`, WAM) меняет вид фрагментом `format=raw`, сохраняет текущую страницу и догруженные порции more/infinite. `product_view` хранится в sessionStorage вкладки (`dharmashop.productView`), не добавляется в адрес при переключении и переходах JS; прямые GET-ссылки остаются совместимыми. Сортировка начинает первую страницу, её значение в адресах пагинации передаётся только при отличии от `data-default-sort` формы. После замены приходит `dharmashop:updated`. Без JS есть «Применить» и обычные ссылки. Своих CSS/inline-скриптов нет.

Товары читаются страницами до 200 (`list_limit` из настроек) со смещением `start`; навигация — штатная `Joomla\CMS\Pagination\Pagination` (макет `joomla.pagination.links`, переопределяется в шаблоне `html/layouts/joomla/pagination`), блок выводится внутри `default_items.php` (C44). Страница списка и фрагмент `format=raw` отдают одну навигацию.

SEO и социальные плагины работают через PageSeo. JSON-LD товарного ItemList/Product/Offer добавляется вместе с содержимым и маршрутами карточек, сейчас семантика фиктивных карточек не генерируется. Бренды, бейджи и страница товара остаются следующими отдельными задачами.

## Начальный вид товаров и изображения подкатегорий C36

В блоке настроек «Товары категории» добавлены `category_default_view` (grid/list/table, default grid) и `subcategory_show_image` (1/0, default 1). В категории и меню `view=category` поля имеют пустое наследуемое значение; приоритет menu → запись → родители → магазин. ## Точки расширения страниц C31 (2026-10-07)

В `tmpl/categories/default.php` четыре вызова `LayoutHooks::render`: `beforeTitle` перед условием вывода h1; `afterTitle` после условия; `beforeContent` перед изображением/интро/сеткой; `afterContent` после полного описания, перед закрытием section. ### История: уточнение пути layouts для Joomla 6 (до C32)

Этот раздел фиксирует прежнее обсуждение; актуальные пути заданы C32 ниже.

Пользователь уточнил корректность `/components/com_dharmashop/layouts`. Сверен **код установленной Joomla 6**: `libraries/src/Layout/FileLayout.php::getDefaultIncludePaths()` добавляет `JPATH_SITE/components/<component>/layouts` при `client=0`. Перед ним идут `templates/<template>/html/layouts/<component>` и переопределение родительского шаблона. Наш вызов FileLayout задаёт `component=com_dharmashop`, `client=0`, basePath=null; стандартный порядок поиска сохраняется. Папка верна, перенос не выполнялся. В самой установке Joomla такие папки есть и у `com_contact`, `com_fields`, `com_menus`.

`tmpl/<view>/*.php` — макеты страниц MVC; `layouts/*` — независимые подключаемые фрагменты JLayout (карточки). Переопределение карточки: `templates/<template>/html/layouts/com_dharmashop/category-card/default.php`. Общий `/layouts` в корне Joomla — отдельный путь для общих макетов, не обязательное место макетов собственного компонента. [Документация Joomla о Layouts](https://manual.joomla.org/docs/4.4/general-concepts/layouts/) описывает тот же механизм; подтверждение для нашего Joomla 6 — его локальный исходный код.

### Общая библиотека layouts C32 (2026-10-07)


Пользователь принял перенос: общие фрагменты теперь в `/layouts/components/dharmashop/`, собственные слоты `category-card`, `product-card`, `brand-card`, `badge-card` сохранены. Страницы остаются в `/components/com_dharmashop/tmpl/<view>/`. ID карточки `components.dharmashop.category-card.default`; переопределение — `templates/<template>/html/layouts/components/dharmashop/category-card/default.php`. Вызов FileLayout использует стандартный поиск общих макетов (`component=none`, `client=0`, basePath=null): переопределение шаблона, родительский шаблон, общая библиотека. SQL, события, Bootstrap-разметка и содержимое четырёх файлов не менялись.

Селектор `LayoutField` и проверка наличия макета во frontend-виде читают новые пути относительно JPATH_ROOT. Значения параметров (`default` и другие имена без расширения) прежние, миграция БД не нужна. Исходники карточек вынесены в `files_dharmashop_layouts/layouts/`; нативное файловое расширение устанавливается первым вложенным ZIP пакета через `fileset` с `target` относительно JPATH_ROOT. Манифест перечисляет конкретные поставляемые файлы, а не владеет целой общей папкой.

При первом обновлении `script.php::preflight` сохраняет старую папку компонента в собственный случайный каталог `tmp_path/dharmashop-layouts-*`: Joomla удаляет её при сравнении старого и нового манифеста компонента. `postflight` переносит сохранённые файлы в общую библиотеку, включая дополнительные макеты и изменённые default.php. Если общая библиотека существовала до переноса, её файлы имеют приоритет; при различающихся версиях снимок остаётся для восстановления. При ошибке установки снимок также остаётся. Ссылки и специальные файлы останавливают перенос до удаления старой папки.

Переопределения каждого шаблона из `html/layouts/com_dharmashop/` копируются в `html/layouts/components/dharmashop/`, только если соответствующего нового файла нет; старые переопределения сохраняются. После успешного переноса без конфликтов временный снимок удаляется. Последующие обновления без старой папки используют обычное обновление файлов Joomla; пользовательские изменения поставляемых макетов следует держать в переопределениях. Первый переход выполнять установкой пакета, а не `dev/sync.sh`.

## Уведомление о добавлении в корзину (2026-10-08)

Отдельный макет `files_dharmashop_layouts/layouts/cart/toast.php` устанавливается в `layouts/components/dharmashop/cart/toast.php`. В настройках «Корзина → Уведомление о добавлении» выбираются `cart_notification_type` (`toast` / `none`, по умолчанию toast) и `cart_notification_seconds` (0–300, по умолчанию 5; 0 — вручную). `cart-toast.js` подключается только для toast; отдельный Bootstrap Toast, без собственного CSS. Новое добавление заменяет предыдущий тост; hover/focus приостанавливает автозакрытие, кнопка закрывает вручную. Сохраните `data-dharmashop-cart-toast-host`, `data-dharmashop-cart-toast` и `data-bs-dismiss="toast"` в переопределении. Автооткрытие мини-корзины остаётся отдельной настройкой модуля.

Если размеры изображений уже сохранены, новый контекст добавляется строкой «Корзина — уведомление о добавлении» во вкладке «Изображения». Удалённые/отсутствующие строки автоматически не восстанавливаются; без строки остаётся исходный URL, как у других контекстов.

Уточнение 2026-10-08: внизу тоста тонкая линия 2 px (`border-top border-2 border-primary`, `data-dharmashop-cart-toast-progress`). Она плавно сокращается к левому краю через Web Animations API; CSS-файл/inline-стили не добавлялись. Один отсчёт в `cart-toast.js` управляет линией и закрытием, начинается после `shown.bs.toast`, при hover/focus сохраняет оставшееся время и продолжается с него. При 0 секунд линия не выводится. По прямому запросу пользователя линия всегда убывает плавно (`linear`), без ветки `prefers-reduced-motion`; без Web Animations API автозакрытие продолжает работать. ## Административный пикер товаров (2026-10-09)

## Общие переключатели вариантов (2026-10-10)
