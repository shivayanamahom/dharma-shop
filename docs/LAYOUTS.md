# Макеты Dharma Shop

Здесь описаны папки PHP-макетов сайта и то, какие из них выбираются в админке. Варианты не перечисляются вручную: имя каждого файла `.php` в папке слота автоматически появляется в соответствующем выпадающем списке. Например, файл `default.php` отображается как `default.php`, а в настройке хранится `default`.

## Правила

1. `administrator/components/com_dharmashop/tmpl` содержит экраны админки и никогда не используется как список витринных макетов.
2. Страницы лежат в `com_dharmashop/site/tmpl/` и устанавливаются в `/components/com_dharmashop/tmpl/`. Подключаемые карточки лежат в `files_dharmashop_layouts/layouts/` и устанавливаются в `/layouts/components/dharmashop/` (C32).
3. Для каждой записи показывается только `.php` из папки своего слота. Не нужно вручную добавлять название в XML формы или языковые файлы.
4. Пустой выбор товара использует общий выбор магазина. Пустой выбор категории наследуется от родителя, затем от общих настроек магазина.
5. Удалённый файл не сбрасывает уже сохранённый выбор: прежнее имя показывается с пометкой «файл не найден», пока администратор не выберет другой файл.
6. Папки и формы должны использовать собственные имена Dharma Shop. RadicalMart допускается только как визуальный ориентир по поведению админки; исходники и имена не копируются.

Товары бренда/бейджа будут переиспользовать оформление C33, самостоятельные файлы появятся при необходимости.

## Выбор раздела в пункте меню

### Принятое общее оформление товаров (C33)

Для товаров бренда и бейджа по умолчанию используются шаблон «Товары категории» (`category_layout`) и карточка товара (`product_card_layout`). По C34 подключена базовая страница `tmpl/category/default.php`; три карточки grid/list/table пока пустые. Переключатель «Использовать оформление списка товаров» для бренда/бейджа ещё впереди, по умолчанию он будет включён. При отключении раздел сможет использовать собственные файлы, начальное оформление которых берётся из нашего базового списка; эти файлы создаются при реализации, не копируются автоматически на каждом запросе.

Общий выбор файлов относится к оформлению; категория, бренд и бейдж сохраняют собственные товары, заголовок, тексты и SEO. Список самих категорий использует свои `categories_layout` и `category_card_layout`. Существующие заготовки списков брендов/бейджей не считаются реализацией этого решения; состав их экранов и моделей определяется отдельно.

### Поле выбора

В выборе раздела пункта меню `categories`, `category` и `brands` используется нативный список Joomla с поиском (`joomla.form.field.list-fancy-select`). Во всех трёх включён `show_root=true`: вариант «Корень» соответствует `id=0`, для товаров категории означает весь каталог. Бейджи плоские, выбора родителя в их меню нет. C34 подключил корень товаров категории; брендовый вид остаётся заготовкой.

## Каркас списка товаров C34 и ресурсы C35

`Site\Model\CategoryModel` наследует проверку категории, корня и прямых подкатегорий от CategoriesModel. `Site\View\Category\HtmlView` получает данные, параметры и SEO, `tmpl/category/default.php` выводит: h1 → изображение/интро → подкатегории → панель сортировки и вида → итоги (если включены) → контейнер товаров → переход порциями → полное описание. Четыре события Category сохранены вокруг заголовка и всего контента. Подкатегории подключают наш готовый category-card, их ссылки ведут на товары выбранной подкатегории внутри пункта меню.

`product_view=grid/list/table` выбирает соответствующий `components.dharmashop.product-card.<mode>`; все три файла намеренно пустые, поэтому данные товаров пока не видны. Для grid/list страница создаёт внешнюю `.col`, карточка позже должна вернуть собственный блок без `.col`; для table страница создаёт responsive-таблицу и tbody, карточка позже должна вернуть tr. Grid использует Grid::classes(params, category), list — row-cols-1. Старое значение настройки `default` читается как grid. Значение без посетительского выбора наследуется от меню/категории/родителей/магазина; новые глобальные настройки по умолчанию grid. Имена файлов по-прежнему сканируются автоматически, arbitrary безопасный файл настройки допускается, но посетительский переключатель содержит только три режима.

Панель — GET-форма с sort и product_view, текущими id и Itemid. Собственный `media/com_dharmashop/js/listing.js` зарегистрирован как `com_dharmashop.listing` в едином joomla.asset.json и включается видом через WebAssetManager. JS применяет выбор автоматически отправкой формы (с перезагрузкой страницы, не AJAX); без него есть «Применить». Переключение отправляет и сортировку, и режим вместе, произвольные пути не принимаются. Своих CSS/inline-скриптов нет. В меню добавлены наследуемые макеты, колонки/брейкпоинты и флаги списка.

Товары читаются порциями до 200, limit из настроек; after — ID граничного товара в текущем отборе, значение сортировки берётся из БД, далее сравнение (sort, id), без OFFSET. Доступен переход «Далее» и в начало; полного числового пагинатора и фильтров пока нет. Сортировки: ручная, название, цена вверх/вниз, новые; NULL цены остаётся NULL. Для конкретной категории используется product_categories (включая связи потомков), для корня — products без дублей; ручной порядок корня пока стабильный ID. Публикация и доступ основной категории/предков проверяются, итоговые цены берутся готовыми. Измерения скорости, особенно глобальной сортировки корня и проверки предков, ещё не выполнялись. SQL внутри layout нет.

SEO и социальные плагины работают через PageSeo. JSON-LD товарного ItemList/Product/Offer добавляется вместе с содержимым и маршрутами карточек, сейчас семантика фиктивных карточек не генерируется. Бренды, бейджи и страница товара остаются следующими отдельными задачами.

## Начальный вид товаров и изображения подкатегорий C36

В блоке настроек «Товары категории» добавлены `category_default_view` (grid/list/table, default grid) и `subcategory_show_image` (1/0, default 1). В категории и меню `view=category` поля имеют пустое наследуемое значение; приоритет menu → запись → родители → магазин. Эти поля исключаются из форм брендов/бейджей, пока их товарные виды не реализованы.

`Category HtmlView` передаёт карточке подкатегории `showImage`; false убирает весь медиаблок, включая резервную иконку, без пустой рамки. При отсутствии флага карточка показывает изображение как раньше, поэтому обычный список категорий не меняется. Настройка не влияет на большое изображение текущей категории.

Начальный `productView` определяется новым параметром; валидный GET `product_view` имеет приоритет. Режим отвечает за выбранную кнопку, сетку/список/таблицу, параметр перехода порциями и `displayData.mode`. Для стандартных файлов grid/list/table режим выбирает одноимённый файл. Без новой настройки старый выбор `product_card_layout` (default → grid, list/table → соответствующий вид) сохраняет поведение. Собственный безопасный файл `product_card_layout` остаётся общим renderer и получает mode, поэтому его автор должен вернуть блок для grid/list или tr для table. `cardLayout` (файл) и `productView` (режим) теперь отдельные свойства. Три штатных файла товара по-прежнему пустые по C34.

## Настройки записей C37 (2026-10-07)

Во вкладке «Отображение» формы используются нативные блоки:

| Тип | Блоки |
|---|---|
| Категория | Видимость; список категорий (`categories_*`, `category_card_*`); товары |
| Производитель | Видимость; список вложенных производителей (`brands_*`, `brand_card_*`); товары |
| Бейдж | Только товары; список не содержит дочерних записей |

Блок товаров общий: `category_layout`, `product_card_layout`, `category_default_view`, `category_breakpoints`, `category_columns` и XS–XXL, `product_card_intro`, `category_product_count`, `category_price_range`, `list_limit`, `list_ordering`. Пустые выборы наследуются, `list_limit=0` означает наследование как раньше. Новых ключей параметров и изменений схемы нет. `new_product_position` оставлен только у обычной категории.

`subcategory_show_image` у категории управляет изображениями подкатегорий; у производителя имеет подпись «Показывать изображения вложенных производителей» и предназначен для того же блока дочерних записей в будущем виде. У бейджа удалён. Свои параметры списка производителей наследуют глобальные `brands_*`/`brand_card_*`; товарные параметры — настройки «Товары категории» по C33. Изменение группировки XML сохраняет имена и уже сохранённые значения.

Категория уже применяет параметры в готовых видах C34/C36. Формы производителя и бейджа сохраняют переопределения, однако их товарные страницы ещё не реализованы; в админке об этом есть пояснение. Их будущие виды должны разрешать значения в порядке меню → запись → родители того же типа (для производителя) → магазин и применять Grid, режим и карточку так же, как Category HtmlView. Переключатель отдельного оформления C33 пока не реализован. Списки самих производителей/бейджей и их товарные страницы — разные слоты, их параметры не смешиваются.

## Минимальная карточка grid C38 (2026-10-07)

`product-card/grid.php` выводит Bootstrap card h-100 без внешней col: обложка 4:3 с object-fit-contain, название h3, текстовое интро по `showIntro`, итоговая цена/диапазон из `displayData.priceRange`. Цены форматируются общим MoneyFormatter в виде, SQL и расчётов в карточке нет. NULL цены — «Цена по запросу», нулевая цена остаётся числом. MediaUrl очищает путь обложки, cover_alt имеет запасной title, изображения lazy/async; текст и атрибуты экранируются. При отсутствии обложки медиаблок не выводится. Используются только Bootstrap-классы, без CSS/inline-стилей/JS.

Ссылка на товар и корзина пока отсутствуют: соответствующие фронтальные виды/действия ещё не реализованы. list.php/table.php остаются заготовками. Новый grid заменяет ранее описанное пустое содержимое только этого режима; выбор default по-прежнему разрешается в grid. Schema.org товарных карточек пока не добавлена, поскольку публичные маршруты товара ещё впереди.

## Как устроен автосканер

`Dharma\Component\DharmaShop\Administrator\Field\LayoutField` получает слот через XML-атрибут `layoutgroup` и сканирует только его установленную папку:

| `layoutgroup` | Папка на сайте |
|---|---|
| `product` | `components/com_dharmashop/tmpl/product/` |
| `category` | `components/com_dharmashop/tmpl/category/` |
| `categories` | `components/com_dharmashop/tmpl/categories/` |
| `brands` | `components/com_dharmashop/tmpl/brands/` |
| `badges` | `components/com_dharmashop/tmpl/badges/` |
| `category_card` | `layouts/components/dharmashop/category-card/` |
| `product_card` | `layouts/components/dharmashop/product-card/` |
| `brand_card` | `layouts/components/dharmashop/brand-card/` |
| `badge_card` | `layouts/components/dharmashop/badge-card/` |

Файлы административных форм и списков сюда не попадают. Имена без `.php` — значения, понятные Joomla при подключении view/layout; подпись в админке включает расширение, чтобы администратор видел точный файл. Скрытые файлы и имена с небезопасными символами пропускаются. `tmpl` устанавливается манифестом компонента, общая библиотека — манифестом файлового расширения `files_dharmashop_layouts`.

## Значения и наследование

- Настройки компонента: `product_layout`, `category_layout`, `product_card_layout`.
- `#__dharmashop_products.params`: `product_layout`.
- `#__categories.params` для обычных категорий: `category_layout`, `product_card_layout`.
- Защищённые пустые файлы сохраняются только для ещё не реализованных видов и трёх карточек товара C34. Страницы categories и category содержат разметку.
- Наличие PHP-файла делает его видимым в динамических выпадающих списках. Имена/данные применяются в готовых видах; для будущих видов это пока заготовки.

## Реализованный список категорий (2026-10-07, C27/C28)

Для `categories` предыдущие замечания о заглушках больше не действуют: `tmpl/categories/default.php` содержит страницу, `layouts/components/dharmashop/category-card/default.php` — независимую карточку через Joomla FileLayout. По C34 подключена также страница category; остальные виды остаются заготовками. SEO готовится общим сервисом до рендера; карточки не меняют head. Только классы Bootstrap, без своего CSS и inline-стилей.

Модель читает прямых детей родителя, отбирает published/access, проверяет доступ и публикацию его предков. Флаг «Показывать в списке» фильтруется в PHP; порядок — lft. Корень 0/1 берёт контент из `root_category`. Бренды и бейджи в этот список не попадают.

Макеты списка и карточки: пункт меню → текущая категория → ближайший предок с непустым выбором → магазин → default.php. Пустое значение наследуется. Удалённый или небезопасный файл при выводе заменяется default. По C30 сетка имеет простой режим (телефон — одна колонка, средний экран — до двух, большой — 1–6 по выбору) и режим настройки всех шести брейкпоинтов; подробнее ниже.

Переопределения страницы: `templates/<template>/html/com_dharmashop/categories/`; карточки: `templates/<template>/html/layouts/components/dharmashop/category-card/`. Поиск Joomla учитывает родительский шаблон. Для произвольного макета селектору нужен PHP-файл в соответствующем установленном слоте.

Карточки в `view=categories` пока ведут на дерево `view=categories`; при отсутствии детей выводится сообщение. Каркас товаров `view=category` уже подключён отдельным пунктом меню по C34, его карточки подкатегорий ведут на `view=category`.

## Настройки отображения C30 (2026-10-07)

В `config.xml` вкладка `display` содержит пять **вложенных нативных fieldset**: `display_categories`, `display_category`, `display_brands`, `display_badges`, `display_product`. Штатный шаблон com_config Joomla выводит их внутри одной вкладки. Своего рендера формы, JS/CSS и subform нет. Имена параметров остались плоскими; существующие макеты и `categories_columns` сохранены.

| Блок | Параметры |
|---|---|
| Список категорий | `categories_layout`, `category_card_layout`, сетка `categories_*`, `category_card_intro/count/prices` |
| Товары категории | `category_layout`, `product_card_layout`, сетка `category_*`, `product_card_intro`, `category_product_count`, `category_price_range` (итоги списка в будущей шапке) |
| Список брендов | `brands_layout`, `brand_card_layout`, сетка `brands_*`, `brand_card_intro/count/prices` |
| Список бейджей | `badges_layout`, `badge_card_layout`, сетка `badges_*`, `badge_card_intro/count/prices` |
| Страница товара | `product_layout`; сетка и количество товаров для отдельного товара не применимы |

Сетка каждого списка: `<prefix>_breakpoints` (по умолчанию 0), `<prefix>_columns` (3), `<prefix>_columns_xs/sm/md/lg/xl/xxl` (1/1/2/3/3/3). Колонки — 1–6. В режиме 0 простой выбор действует на LG и выше, XS/SM = 1, MD = min(2, выбранное число). В режиме 1 применяются все шесть значений. Нативный `showon` скрывает неактивные поля. `Site/Support/Grid` строит классы Bootstrap `row-cols-*`, `row-cols-sm-*`, …, `row-cols-xxl-*`, `g-4`.

Переключатели магазина: интро по умолчанию Да, количество и цены — Нет. Список категорий применяет параметры и отдаёт карточке `showIntro`, `showCount`, `showPrices`, `productCount`, `priceRange`. Карточка выводит количество (включая 0) и цены; одинаковые min/max — одно значение, отсутствие цен — без строки, NULL не заменяется нулём. Валюта и число знаков — через общий `MoneyFormatter`.

Переопределения обычной категории и меню списка категорий: «Наследовать / Да / Нет», пустые значения колонок. Приоритет: меню → текущая категория → родители → магазин → встроенные значения. Старое явное значение меню (например, `category_card_intro=1`) продолжает переопределять магазин; для общего управления выбрать «Наследовать». Параметры товаров категории в форме пока подготовлены для будущего вида. У брендов и бейджей поля другого типа удаляются из формы.

Статистика карточек: один групповой `CategoriesModel::getCardStats` по `product_categories` для ID доступных показанных категорий, `state=1`. PK `(catid, product_id)` исключает двойной счёт в категории; унаследованные связи включают подкатегории. Только при выводе цен присоединяется `products` по PK: min(`price_min`)/max(`price_max`) опубликованных товаров. Используются готовые итоговые цены вариантов; акции на просмотре не пересчитываются. При выключенных количестве и ценах запроса нет; в layout SQL нет. Время работы на больших каталогах не измерено.

Бренды, бейджи, товары категории и страница товара пока заготовки: настройки сопровождаются пояснением. Карточки бренда/бейджа получили защищённые пустые `default.php`; селектор читает файлы соответствующего слота. По C31 в страницах категории/товара позже расставлены точки плагинов, полноценного контента ещё нет.

## Точки расширения страниц C31 (2026-10-07)

В `tmpl/categories/default.php` четыре вызова `LayoutHooks::render`: `beforeTitle` перед условием вывода h1; `afterTitle` после условия; `beforeContent` перед изображением/интро/сеткой; `afterContent` после полного описания, перед закрытием section. Плагины группы `dharmashop` выводят собственные блоки в эти места. В карточках списка события не повторяются. Точки заголовка работают и при скрытом h1. Без обработчиков HTML не добавляется.

В `tmpl/category/default.php` и `tmpl/product/default.php` подготовлены те же четыре вызова с местом заголовка и контента. Для первого — события Category, для второго — Product. **Это пока заготовки:** будущий вид должен передать публичный `item` после проверок доступа/публикации, `params` (Registry), `items` (на категории), `seo` (PageMetadata), `showHeading`. Пока `item` отсутствует, макет возвращается без разметки и событий. Виды, запросы и контент этих страниц не реализованы.

Автор нового макета/переопределения должен сохранить вызовы в этих четырёх местах; без них соответствующие блоки плагинов не появятся. Пример `new LayoutHooks('category', 'categories', $this->parent, $this->params, $this->items, $this->seo)`. Для списка товаров использовать entity/category и view/category, для товара entity/product и view/product. Контракт события, полные имена и пример плагина — `SHORTCODES.md` §3.

### История: уточнение пути layouts для Joomla 6 (до C32)

Этот раздел фиксирует прежнее обсуждение; актуальные пути заданы C32 ниже.

Пользователь уточнил корректность `/components/com_dharmashop/layouts`. Сверен **код установленной Joomla 6**: `libraries/src/Layout/FileLayout.php::getDefaultIncludePaths()` добавляет `JPATH_SITE/components/<component>/layouts` при `client=0`. Перед ним идут `templates/<template>/html/layouts/<component>` и переопределение родительского шаблона. Наш вызов FileLayout задаёт `component=com_dharmashop`, `client=0`, basePath=null; стандартный порядок поиска сохраняется. Папка верна, перенос не выполнялся. В самой установке Joomla такие папки есть и у `com_contact`, `com_fields`, `com_menus`.

`tmpl/<view>/*.php` — макеты страниц MVC; `layouts/*` — независимые подключаемые фрагменты JLayout (карточки). Переопределение карточки: `templates/<template>/html/layouts/com_dharmashop/category-card/default.php`. Общий `/layouts` в корне Joomla — отдельный путь для общих макетов, не обязательное место макетов собственного компонента. [Документация Joomla о Layouts](https://manual.joomla.org/docs/4.4/general-concepts/layouts/) описывает тот же механизм; подтверждение для нашего Joomla 6 — его локальный исходный код.

### Общая библиотека layouts C32 (2026-10-07)

Пользователь указал на `/Volumes/Work/Server/www/nrk.steel/layouts/components/radicalmart`. Проверены только имена файлов и наличие каталогов, код RadicalMart не читался: общей библиотекой действительно служит этот путь, папки `components/com_radicalmart/layouts` нет. Это второй штатный вариант Joomla — общие JLayout. Он не опровергает поддержку локальной папки компонента, но показывает иной выбор организации файлов.

Пользователь принял перенос: общие фрагменты теперь в `/layouts/components/dharmashop/`, собственные слоты `category-card`, `product-card`, `brand-card`, `badge-card` сохранены. Страницы остаются в `/components/com_dharmashop/tmpl/<view>/`. ID карточки `components.dharmashop.category-card.default`; переопределение — `templates/<template>/html/layouts/components/dharmashop/category-card/default.php`. Вызов FileLayout использует стандартный поиск общих макетов (`component=none`, `client=0`, basePath=null): переопределение шаблона, родительский шаблон, общая библиотека. SQL, события, Bootstrap-разметка и содержимое четырёх файлов не менялись.

Селектор `LayoutField` и проверка наличия макета во frontend-виде читают новые пути относительно JPATH_ROOT. Значения параметров (`default` и другие имена без расширения) прежние, миграция БД не нужна. Исходники карточек вынесены в `files_dharmashop_layouts/layouts/`; нативное файловое расширение устанавливается первым вложенным ZIP пакета через `fileset` с `target` относительно JPATH_ROOT. Манифест перечисляет конкретные поставляемые файлы, а не владеет целой общей папкой.

При первом обновлении `script.php::preflight` сохраняет старую папку компонента в собственный случайный каталог `tmp_path/dharmashop-layouts-*`: Joomla удаляет её при сравнении старого и нового манифеста компонента. `postflight` переносит сохранённые файлы в общую библиотеку, включая дополнительные макеты и изменённые default.php. Если общая библиотека существовала до переноса, её файлы имеют приоритет; при различающихся версиях снимок остаётся для восстановления. При ошибке установки снимок также остаётся. Ссылки и специальные файлы останавливают перенос до удаления старой папки.

Переопределения каждого шаблона из `html/layouts/com_dharmashop/` копируются в `html/layouts/components/dharmashop/`, только если соответствующего нового файла нет; старые переопределения сохраняются. После успешного переноса без конфликтов временный снимок удаляется. Последующие обновления без старой папки используют обычное обновление файлов Joomla; пользовательские изменения поставляемых макетов следует держать в переопределениях. Первый переход выполнять установкой пакета, а не `dev/sync.sh`.
