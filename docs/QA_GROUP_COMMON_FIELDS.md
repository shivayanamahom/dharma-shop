# Общие поля группы: проверки 2026-10-11

## Реализовано

Нативные вкладки товарных полей в группе, исключение её осей, переключатель копирования и число сохранённых общих значений. Снимок создаётся только в новых товарах через ProductModel. Сохранение группы не обновляет характеристики существующих участников. Фронт читает обычные поля выбранного товара, без таблиц общих значений группы. Контракт — VARIANTS.md §14.14.

## Демогруппа

[Группа №13 в админке](https://test.test/administrator/index.php?option=com_dharmashop&view=productgroup&layout=edit&id=13), [категория](https://test.test/index.php/tovary-kategorii/smartfony?sort=new&product_view=grid).

Название: «Демо: общие поля и варианты 20261011-045634». Товары 291–296, 3 памяти × 2 цвета. Заполнены 15 общих полей всех 10 типов, две оси, тексты, галерея, категория/допкатегория, производитель и два бейджа. Общие значения включают PDF, дополнительные фото, ссылку видео, checkbox «Нет» и число 0. Товар 292 со скидкой 10% (17490 → 15741), у 296 нулевой остаток с включённым учётом и запрещённой продажей без остатка. Группа и шесть товаров опубликованы для приёмки. Медиа используют имеющиеся безопасные ссылки, файлы физически не дублировались.

## Проверки

- `check-group-generator.php`: 20 PASS, прежняя матрица/повторы/формула/алиасы/цена/состояние/наследование/ошибки/лимиты.
- `check-group-common-fields.php`: 29 PASS, все типы и нули, исключение осей, native form, шесть товаров/одно SKU, снимки и ручные правки, повтор, копирование выключено, вариативное поле вне осей, числовые границы, медиа, отсутствие остатка.
- `check-group-common-scope.php`: 14 PASS, две собственные категории и обязательное поле, сохранение пустой группы, отказ до создания первого товара, применимость другой категории, сохранность недоступных defaults, защита удаления используемого поля.
- Браузер: сохранение группы, вкладки полей/медиа, смена цвета при скрытой памяти, корректный выбранный товар 295 в корзине и удаление тестовой строки. Смена памяти на полной странице меняет URL/H1/цену. Слайдер переключил фото 1 → 2; PDF/две картинки видны, видео не создало iframe до запуска. Подтверждены «Нет в наличии» и отсутствие покупки у 296, скидка у 292.
- HTTP: grid/list/table, AJAX всех трёх макетов, все шесть вариантов, цены/скидка/покупка по наличию, скрытая ось, отказ поддельному контексту и подстановке скрытого поля. Ответ содержит только одну карточку; Cache-Control=no-store, X-Robots-Tag=noindex. 13 локальных ссылок медиа отвечают 200. SQL debugbar не содержит group_field_* на страницах категории/товара.

Всего **63 интеграционные проверки**, плюс браузерные/HTTP сценарии. Остальные собственные fixtures переведены в корзину штатными моделями; чужие записи/файлы не удалялись. Ошибки by-reference в сохранении привязок FieldModel и decode/encode видео исправлены по результатам проверки.

## Масштаб: 100 и 100000 товаров

Изолированные таблицы со случайным префиксом cgqa_, скопированы структура/справочники и значения полностью заполненного товара. 1,3 млн строк простых характеристик при 100 тыс. товаров, плюс тексты/медиа. Настоящий EntityFields::attach загружает 24 товара, 11 полей на товар. 20 измерений после прогрева. Собственные benchmark-таблицы удалены в finally; магазин и чужие bn_* не менялись.

| Сценарий | 100: p50 / p95, мс | 100000: p50 / p95, мс |
|---|---:|---:|
| Только характеристики 24 карточек | 1,74 / 1,92 | 2,43 / 3,50 |
| Список 24 товаров + данные карточек | 3,70 / 3,82 | 79,95 / 110,70 |

Загрузка полей делает 3 пакетных запроса независимо от каталога. EXPLAIN: idx_product/range, оценка 264 строк простых значений + 24 файлов; одинаково при 100 и 100000. До исправления MySQL выбирал idx_variant для NULL и характеристикам требовалось около 666 мс на 100000. Теперь EntityFields явно использует индекс владельца, включая category_id для категорий.

Второй сценарий включает существующую смешанную выборку CategoryModel/GroupListing с сортировкой new. Он остаётся дороже на большом каталоге; стоимость самих характеристик — 2,43 мс. Синтетические товары здесь без групп, фильтр пустой. Это не замер групповых фасетов, 100 тыс. сгруппированных вариантов или конкурентных посетителей; эти цифры нельзя выдавать за полную нагрузочную приёмку каталога.
