# SEO и разметка витрины

2026-10-07. **Принято пользователем (C28/C29). Общий сервис, социальный плагин и плагин Schema.org реализованы и подключены к списку категорий.**

## Что проверено

- В Dharma Shop есть `SeoSettings`, поля SEO у записей и шаблоны по типам страниц в `admin/config.xml`. Общий сервис применяет их на первом публичном виде категорий.
- В интерфейсе RadicalMart 3.0.27 на lndckz.test общие настройки SEO содержат переключатели OpenGraph, Twitter, Schema.org и хлебных крошек. Для категорий есть отдельные шаблоны title, description, robots, h1 и названия крошек с подстановками.
- В списке плагинов просмотренной установки поиск по SEO и Open не дал результатов; среди десяти плагинов с RadicalMart в названии отдельного SEO-плагина нет. Есть системный плагин RadicalMart без собственных полей настроек. **Это не устанавливает, где именно выполняется генерация тегов:** код не читался по правилу чистой комнаты. Наличие этой функции в другой версии или стороннем расширении не проверено.
- Официальная документация подтверждает хранение настроек в параметрах компонента и возможность расширения формы плагинами: [Добавление настроек RadicalMart](https://radicalmart.ru/baza-znanij/razrabotchikam/radicalmart-add-config). Используется только описание поведения, не код и не имена RM.

## Принятое разделение

| Часть | Ответственность |
|---|---|
| Общий SEO-сервис компонента | Разрешение полей записи и шаблонов магазина, подстановки, title, description, robots, canonical, h1 и название хлебных крошек |
| Плагин социальной разметки | Open Graph и Twitter Cards из уже разрешённых значений страницы; отключение плагина отключает только эту разметку |
| Плагин структурированных данных | Schema.org/JSON-LD из семантического контекста компонента; сейчас список категорий, товары и другие списки позднее. Хлебные крошки остаются за Joomla |
| Шаблон страницы | Заголовок, тексты и сетка Bootstrap; получает готовые значения, не вычисляет SEO и не печатает метатеги |
| Layout карточки | Изображение/иконка, название, ссылка и краткий текст категории; не меняет метаданные всей страницы |

Преимущество общего сервиса: настройки одинаково применяются к любому выбранному `default.php` или другому макету, без повторения SEO-логики. Базовые теги работают при отключённом дополнительном плагине. Смена дизайна не меняет метаданные.

## Настройки и данные

- Одна вкладка «SEO» магазина, без второй копии SEO-полей в настройках плагина. Существующие ключи сохранены, добавлены переключатели `seo_twitter` и `seo_structureddata`.
- Сначала явное поле записи, затем явно заполненное SEO-поле соответствующего меню, затем SEO-шаблон магазина и встроенное значение. Для корня использовать существующие `root_category` / `root_brand`, а не выдуманную категорию в БД. Меню не передаёт свои SEO-поля дочерним категориям.
- Изображение социальной карточки: SEO-изображение записи → основное изображение записи → общее SEO-изображение магазина. Иконку категории автоматически не назначать социальной картинкой.
- Плагин получает готовые title/description/image/url и тип страницы; повторных запросов каталога и второго движка подстановок не делает.
- Применять теги через документ Joomla до вывода head. Один владелец каждого тега, без дублей. Условия работы ограничить страницами Dharma Shop и HTML-документом; исключить админку и служебные ответы.
- Canonical строится из маршрута страницы и согласованной политики пагинации/фильтров. Не подставлять весь текущий URL с произвольными параметрами.
- Контракт `onDharmaShopMetadataReady` записан в `SHORTCODES.md` и `ARCHITECTURE.md`. Политику пустых ценовых подстановок определить вместе с ценовыми данными на фронте.

## Реализация и состояние

- `Site/Placeholder/Renderer.php`: один проход подстановок без повторной интерпретации значений. На категории работают title, parent, sitename и currency. Ценовые и числовые подстановки остаются планом; неизвестные коды сохраняются буквально.
- `Site/Seo/PageSeo.php`: разрешение значений, базовые теги через документ Joomla, событие для плагинов; `PageMetadata.php` — readonly-контекст.
- `onDharmaShopMetadataReady`: группа `dharmashop`, аргументы `page`, `document`, `settings`, `content` (семантический контекст списка или `null`). Плагины не делают запросов каталога.
- `plg_dharmashop_social`: services/provider и SubscriberInterface. Open Graph использует `property`, Twitter Cards — `name`; без изображения используется `summary`, с изображением — `summary_large_image`.
- Плагин включается при первом добавлении пакетом; обновление сохраняет прежнее отключение владельцем.
- Приоритет SEO: явное поле записи → явное поле соответствующего меню → шаблон магазина → встроенное значение. Поля меню применяются только при совпадении его страницы с текущей; не переносятся на дочерние категории. Это правило реализации можно уточнить по просьбе пользователя.
- Во вкладке SEO добавлен `seo_twitter` рядом с существующим `seo_opengraph`. Поля плагина не дублируются.
- Canonical категории строится по маршруту без произвольных параметров текущего запроса; главная — корень сайта. Политику фильтров и пагинации определить вместе с их реализацией.
- Подключено пока только к `view=categories`; другие виды не реализованы. Schema.org для этого списка добавлена по C29, см. ниже.

Браузерный просмотр test.test: корень каталога и «Столы» открываются, title/h1 и социальные теги соответствуют странице; у «Столы» абсолютный og:image из её изображения. Автоматические тесты и переключение плагина/настроек не выполнялись.

## Schema.org — принято 2026-10-07 (C29)

- Отдельный плагин структурированных данных группы `dharmashop`, вывод JSON-LD через документ Joomla. Данные не зависят от выбранного макета или карточки.
- Списки категорий, товаров, брендов и бейджей: `CollectionPage` и `ItemList` только с фактически показанными элементами и их маршрутами. Не выгружать весь каталог; учитывать текущую страницу пагинации при её реализации.
- Страница товара: `Product`, а при наличии действительной доступной покупателю цены — `Offer` с итоговой ценой, валютой и реальным статусом наличия. Цена «по запросу» не превращается в нулевую цену. Артикул, изображения и бренд брать из данных товара; отзывы и рейтинги выводить только при наличии настоящих данных. Варианты и `ProductGroup` — вместе с реализацией страницы вариантов.
- Данные продавца: `Organization` из заполненных настроек магазина, без фиктивного адреса, контактов или правил доставки/возврата.
- На корне каталога test.test уже найден один `BreadcrumbList`, созданный штатным `mod_breadcrumbs` Joomla (модуль 17). По умолчанию оставляем этого владельца. Собственные хлебные крошки плагина — только отдельный явно выбранный режим для сайтов без такой разметки; раннее событие SEO не гарантирует обнаружения схемы, которую модуль добавит позднее.
- Во вкладке SEO — общее включение Schema.org; реквизиты продавца — в настройках магазина. Не дублировать формы настроек компонента в плагине.
- Модель/вид готовит семантический контекст страницы из уже загруженных данных; плагин сериализует его один раз. Текущий `PageMetadata` содержит SEO/социальные значения, но не список записей, цепочку категорий, товар и предложение: контракт расширения определить при реализации. Не извлекать эти данные из HTML и не повторять запросы всего каталога.
- Порядок внедрения: работающий список категорий → список товаров → товар и предложения → организация из настоящих реквизитов. Первый шаг реализован, остальные ждут соответствующих страниц и данных.

### Реализованный первый шаг

- `plg_dharmashop_structureddata`: штатные manifest/services/provider/SubscriberInterface; один JSON-LD через WebAssetManager. Включается при первом добавлении пакетом, сохраняет отключение при обновлениях.
- «Настройки → SEO → Микроразметка Schema.org» (`seo_structureddata`, по умолчанию Да) управляет схемой магазина. Отключение самого плагина также убирает её. Схема штатного модуля хлебных крошек независима от этого переключателя.
- `CollectionMetadata` передаёт название списка и массив `name`/абсолютный `url` в порядке видимых карточек. Контекст собирается видом из уже загруженных published/access/show_in_list записей; маршруты строятся тем же методом, что у карточки. При выключенной настройке контекст не создаётся.
- В JSON-LD граф из `CollectionPage` (`@id`: canonical + `#webpage`) и `ItemList` (`@id`: canonical + `#itemlist`). `mainEntity` связывает страницу со списком; позиции с 1, `numberOfItems` равен числу показанных карточек. На пустой ветке массив пуст, фиктивных элементов нет.
- `PageSeo::apply` получил необязательный третий аргумент `CollectionMetadata`; событие — необязательный `content`. Базовые метатеги и социальный плагин продолжают работать без этого контекста.
- Имена актива и ID стабильны; JSON_HEX-флаги защищают границу script, некорректный UTF-8 заменяется. Дополнительный BreadcrumbList не создаётся. Макеты PHP не печатают Schema.org.
- Пакет `0.1.0` собран и установлен обновлением на test.test: установщик вернул `INSTALL OK`. Проверки поведения в браузере, переключателей и валидаторов Schema.org/Google в этой задаче не запускались. Product/Offer, Organization и остальные виды — не реализованы.

Источники: [Google: Product](https://developers.google.com/search/docs/appearance/structured-data/product), [Schema.org: CollectionPage](https://schema.org/CollectionPage), [Schema.org: ItemList](https://schema.org/ItemList).
