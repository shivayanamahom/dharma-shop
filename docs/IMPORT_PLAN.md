# Импорт Dharma Shop — план реализации

**Дата:** 2026-10-13. **Статус:** план принят пользователем; CSV встроен, XLSX reader plugin добавлен к реализации, проверка реального импорта ещё не выполнена. Детализация C91 и этапов E2–E4/E8 из [общего плана обмена](DATA_EXCHANGE_PLAN.md).

Прямые требования пользователя: сначала изучить реализацию и визуал экспорта, подготовить план, затем переходить к реализации; интерфейс импорта должен быть похож на экспорт с учётом специфики; использовать существующий файловый загрузчик; **обязательно скачивать с других серверов изображения и файлы**. Изучены собственные прежние реализации импорта; чужой код не использовался.

Пользователь разрешил реализацию. Полная поставка остаётся целевой границей; текущий участок — CSV категорий, брендов, бейджей и товаров, включая создание отсутствующих категорий/полей по отдельным настройкам. Реализованное и проверенное фиксируются отдельно в ROADMAP.md.

## 1. Что изучено и что из этого следует

### 1.1. Наш экспорт и реальный интерфейс

На `https://test.test` в Firefox просмотрены список экспорта и новая несохранённая форма профиля, включая вкладку колонок. Форма закрыта без сохранения; выгрузки и каталог при исследовании не изменялись.

Изучены `com_dharmashop_export/admin/forms/profile.xml`, `tmpl/profiles/default.php`, `tmpl/profile/edit.php`, `tmpl/preview/default.php`, `tmpl/job/default.php`, `src/Export/{Workflow,Catalog,Plan,Files,Cells,Access,FormatInterface}.php` и console-плагин экспорта.

- Сохраняем нативные toolbar, searchtools, таблицы, Joomla Form XML, `uitab`, `showon` и общий Bootstrap modal прогресса. Нового административного CSS не требуется.
- Формат выбирается на первой вкладке; его настройки появляются там же. Отдельные вкладки «Настройки CSV» / «Настройки XLSX» не нужны.
- Сопоставление импорта остаётся отдельной вкладкой. Используем доступный список полей с поиском; выпадающий список не должен обрезаться контейнером таблицы.
- В экспорте есть снимок профиля, порции, аренда шага, история и продолжение. Для импорта дополнительно нужны подготовленный план изменений, подтверждение и восстановление записи отдельной строки.
- Напрямую использовать экспортный Workflow нельзя: его курсор — ID читаемой записи, а импорт читает файл, разрешает связи и меняет каталог. Сохраняем знакомые правила работы, не связывая два компонента зависимостью друг от друга.

## 2. Граница первой законченной поставки

Один `com_dharmashop_import` для профилей, подготовки, применения, истории и отчётов. CSV — внутри него; XLSX — `plg_dharmashopimport_xlsx`. Задача Joomla Scheduler и CLI — отдельные плагины, по образцу экспорта. Названия являются предложением продолжения C91.

| Тип записей | Что входит | Основные особенности |
|---|---|---|
| Категории | Дерево, название, алиас, тексты, состояние, SEO, изображения, разрешённые настройки и поля категории | Родитель того же типа; произвольный порядок строк; обнаружение циклов и отсутствующих родителей |
| Бренды / производители | Дерево брендов, тексты, сайт, SEO, изображения | Отдельная секция категорий; у товара один бренд |
| Бейджи | Название, алиас, цвет, состояние и поддерживаемые параметры | Плоский справочник; у товара несколько бейджей |
| Группы полей | Алиас, название, назначение, вкладка, порядок | До определений полей; не менять назначение существующей группы произвольно |
| Поля | Тип, назначение, группа, применимость, настройки, опции, обязательность, порядок | Только зарегистрированные типы; неизменность типа/назначения существующего поля; сопоставление опций по алиасам |
| Товары | Карточка, артикул, таксономия, базовая цена/скидка, количество, габариты, поля, галерея и документы | Ровно один служебный SKU на обычный товар; варианты — самостоятельные товары |
| Группы товаров | Общие данные, таксономия, медиа, общие поля, оси и участники | 1–6 допустимых осей, уникальные сочетания, не более 500 участников; привязки после подготовки товаров |

Первый рабочий участок — CSV/XLSX категорий/брендов/бейджей; вся таблица выше — целевая граница следующей совместной поставки экспорта и импорта. Группы/определения полей завершают E8, а не объявляются готовыми вместе с первым простым импортом.

Чтение YML — возможный последующий формат-плагин, отдельно от имеющегося YML-писателя. Заказы, покупатели, настройки Joomla, акции и API маркетплейсов не входят в этот этап.

## 3. Интерфейс

### 3.1. Список профилей

Пункт **Dharma Shop → Импорт** рядом с экспортом. Штатная таблица: название, что загружать, формат, источник, состояние, действие, последний результат, планировщик, ID. Поиск и фильтры — нативные Joomla.

- В строке: **Проверить**, **Продолжить** при незавершённом запуске, **Результат** для последнего отчёта, **В планировщик** для пригодного постоянного источника.
- В toolbar: создать, состояние/разблокировка/удаление профилей, **История импорта**, переход в общие настройки магазина. Права компонента — штатные «Параметры».
- «Проверить» всегда сначала открывает подготовку, не пишет каталог. Нажатие на название открывает профиль.

### 3.2. Четыре вкладки профиля

| Вкладка | Поля и действия |
|---|---|
| **Профиль импорта** | Название, состояние, что загружать, формат; прямо под форматом его настройки. Ниже источник: компьютер / URL / файл из разрешённой папки; один загрузчик источника, имя, размер, дата, статус; для XLSX выбор листа |
| **Сопоставление** | После чтения образца: колонка файла с номером и примером → поле магазина с поиском → правило значения. Кнопка «Определить соответствия»; видимые неподтверждённые/неизвестные назначения |
| **Правила записи** | Источник внешних ключей, ключ поиска, создавать / обновлять, категория по умолчанию, создание справочников/опций, пустые значения, поведение при конфликте, лимиты изменений, разрешение регулярного применения |
| **Файлы и изображения** | Базовый адрес медиа источника, разрешённые домены, скачивание изображений и документов, добавлять / заменять медиасписок, политика ошибок, локальная папка медиа/архив при переносе. Папки хранения и глобальные лимиты наследуются из общих настроек |

У профиля один файл-образец/текущий источник. Не заставлять загружать одинаковый файл отдельно для сопоставления и отдельно для проверки. Новая загрузка создаёт новый снимок; предыдущий проверенный запуск продолжает ссылаться на свой файл.

Файл можно загрузить до первого сохранения профиля: сервер выдаёт случайный временный идентификатор, привязанный к сотруднику и сроку хранения. После сохранения профиль получает ссылку на подготовленный источник. Клиент не присылает произвольный путь к рабочему файлу.

Настройки формата не вынесены в отдельные вкладки. Смена типа записей/формата показывает предупреждение и требует заново проверить несовместимые назначения; их скрытое применение недопустимо. Без файла вкладка сопоставления показывает объяснение и переход к загрузчику, а не пустой раскрывающийся список.

Основные действия формы: **Сохранить**, **Сохранить и закрыть**, **Сохранить и проверить**, **Закрыть**. Применение появляется на странице проверенного запуска.

### 3.3. Проверка и результат

```mermaid
flowchart LR
    A[Файл или ссылка] --> B[Чтение и сопоставление]
    B --> C[Проверка строк и медиа]
    C --> D[Отчёт о будущих изменениях]
    D --> E[Применить]
    E --> F[Итоги и журнал]
```

В общем окне прогресса — текущая фаза и её счётчик: получение файла, чтение, проверка строк, скачивание медиа, применение. Общее время заранее не выдумывается; для неизвестного размера скачивания — неопределённый индикатор. Длительный процесс можно продолжить после закрытия вкладки.

На странице проверки: сколько создать, обновить, оставить без изменений, пропустить; ошибки и предупреждения; таблица **строка → ключ → действие → поле → было → станет** с пагинацией и фильтром по результату. Отдельно — список недоступных файлов и причины. Предпросмотр экранирует HTML, не исполняет содержимое ячеек и не загружает внешние картинки браузером сотрудника.

По умолчанию ошибки блокируют применение. Возможность «применить только корректные строки» — явное правило с видимыми исключениями; зависимые строки не считаются корректными при ошибках справочников. Кнопка **Применить** сообщает фактические числа изменений. После применения можно скачать отчёт CSV и файл ошибок, пригодный для исправления и повторной проверки.

## 4. Источник и чтение

### 4.1. Три способа получить файл

1. **Компьютер:** существующий drop/выбор с прогрессом и обычным file input как резервом. Только расширения активного читателя. Лимит браузерной загрузки — минимум PHP и настроек импорта.
2. **URL:** сервер скачивает источник потоком в закрытую папку, проверяет ответ и содержимое. URL может не содержать расширения; HTML-страница входа/ошибки не считается CSV/XLSX.
3. **На сервере:** выбор внутри настроенной папки входящих файлов; исходник только читается и копируется в снимок запуска. Нельзя читать произвольные серверные файлы, следовать symlink или менять исходный прайс поставщика.

У запуска неизменяемый источник: SHA-256, размер, исходное имя, дата получения, способ получения, формат, кодировка/лист/разделители. Применение читает **тот же** снимок, который проверялся; повторно скачивать URL между проверкой и записью нельзя.

### 4.2. CSV

- UTF-8 с BOM/без BOM; Windows-1251 по выбору; BOM UTF-16 распознаётся с потоковым преобразованием. Невалидная кодировка вызывает понятную ошибку, символы не заменяются молча.
- `;`, `,`, TAB и явный разделитель; автоопределение по нескольким логическим строкам с учётом кавычек. Если выбор неоднозначен, требуется указать разделитель.
- Поддержать многострочные ячейки, удвоенные кавычки, CRLF/LF, пустые строки, последнюю строку без перевода, несоответствие количества колонок.
- Первая строка — заголовки по умолчанию; без заголовков показывать «Колонка 1», «Колонка 2» и примеры. Дубликаты названий различаются номером, а не перезаписываются словарём.
- Не приводить артикулы/внешние ключи к числу: `00015`, `1E10`, кириллица и знаки — строки. Нельзя восстановить уже потерянные Excel нули догадкой.
- Курсор — позиция в нормализованном потоке и номер логической строки. После сбоя не перечитывать весь файл до текущей строки на каждом шаге.

### 4.3. XLSX-плагин

В исходниках добавлен `plg_dharmashopimport_xlsx`. Он перечисляет листы книги, показывает образец выбранного листа и потоково нормализует ячейки в UTF-8 CSV для общего пайплайна. Текущая реализация нормализует книгу целиком при старте задания; многошаговое возобновление самой фазы нормализации ещё не реализовано и требует отдельного этапа до обещания поддержки больших книг.

Потоковое чтение нужного листа, отдельное разрешение shared strings с ограничением памяти, сохранение пустых колонок и реальных номеров строк. В интерфейсе выбирается лист; форматирование ячейки не превращается в значение произвольно. Формулы не вычисляются; ячейки с формулами по умолчанию требуют выгрузить значения, чтобы не использовать устаревший кеш результата.

Общая подготовка переводит вход в последовательность нормализованных строк с устойчивыми номерами/курсорами. Проверка и применение работают уже с ней. Для XLSX отдельно доказать возобновляемое чтение фаз shared strings/листа: повторный проход от первой строки на каждой веб-порции запрещён, иначе большой файл будет обрабатываться квадратично. Форматный курсор включает фазу и собственное состояние чтения; он не обязан быть простым номером строки CSV.

Проверять ZIP-структуру, предел распакованного объёма, число записей, размер XML/ячейки, запрет внешних сущностей и ссылок. Макросы, шифрованные файлы и старый бинарный XLS в первую поставку не входят; сообщение объясняет, что нужно сохранить XLSX или CSV.

## 5. Сопоставление и значения

Схема назначений импорта самостоятельная: она использует общие определения полей, но не считает каждую экспортируемую колонку доступной для записи.

- Автосопоставление: устойчивые машинные ключи, затем точные известные RU/EN-подписи. Пользователь видит результат; неоднозначные подписи не выбираются случайно. Переименованный заголовок экспортного файла можно сопоставить вручную.
- Неизвестная колонка — «Не импортировать». Обязательные назначения и ключ проверяются до полного анализа. Повтор назначения одному скалярному полю — ошибка; объединение нескольких колонок в список возможно только явным правилом.
- Сохраняются номер и название исходной колонки; каждый новый файл проверяется на изменение структуры. Переставленные уникальные заголовки можно восстановить по имени, а конфликтующие — перепроверить вручную.
- Значения по умолчанию применяются к новым записям. Отсутствующая колонка и неподключённое назначение **не меняют** существующее значение.
- Пустая ячейка по умолчанию означает «не менять» существующее значение; `0` и `false` не пустые. Очистка — явная политика поля/маркер `__CLEAR__`; буквальное совпадение с маркером можно экранировать. Обязательное поле очистить нельзя.
- Деньги/количество разбираются строго по выбранным правилам дробной/тысячной части и передаются десятичными строками. Даты имеют понятный входной часовой пояс и сохраняются в UTC. «Да/Нет», `true/false`, `1/0` — явный ограниченный набор, а не произвольное PHP-приведение.
- Множественные значения: выбранный разделитель (совместимый с экспортом по умолчанию ` | `); JSON-массив для сложных значений. У диапазона — две границы, у media — `url/path`, `alt`, `title`, у документа также исходное имя. Текст не дробится автоматически по всем запятым/точкам с запятой.
- Типы полей обрабатываются через существующий контракт нормализации/encode. Опции сопоставляются по алиасу внутри поля; подпись допустима только при единственном совпадении. Чужой option ID разрешается через соответствия, не используется как ID при переносе на другой сайт.
- Неизвестный пользовательский тип требует обработчика; его нельзя молча записать как текст. Список, checkbox, color, range, text, editor, gallery, files и поддерживаемые video-значения получают явные адаптеры.
- HTML проходит штатные фильтры Joomla согласно правам сотрудника; параметры и JSON имеют список разрешённых ключей. `asset_id`, ACL rules, `checked_out`, `lft/rgt`, служебные курсоры и вычисленные индексы не импортируются из файла.
- Апостроф защиты формул снимается только в явном режиме «файл Dharma Export» для реально экранированной опасной строки. Обычные апострофы стороннего CSV не удаляются.

## 6. Идентификация и связи

Профиль имеет стабильный **код источника** (поставщик/старый магазин), независимый от имени профиля. Внешние ключи разных поставщиков не смешиваются. Новые внутренние ID выдаются целевой системой; сохранение исходного ID в `external_ids` позволяет переносить связанные файлы в несколько проходов.

Для товара: внешний ключ → явно разрешённое сопоставление по артикулу; внутренний ID — для правки того же магазина. Алиас товара уникален только внутри основной категории. Для категорий — внешний ключ или путь алиасов в своей секции; одно название без родителя недостаточно. Для групп/полей/групп полей использовать их действительные правила уникальности. Поиск по названию только явно и с отказом при нескольких совпадениях.

Дубли ключей внутри файла обнаруживаются на проверке; по умолчанию блокируются, «последняя строка победила» не применяется. Противоречие внешнего соответствия и артикула — конфликт. Существующие ссылки на удалённую запись не переназначаются случайному товару.

Порядок полной загрузки: **группы полей → поля/опции → категории/бренды/бейджи → заготовки групп → товары → состав и проверка групп**. Категории могут идти в файле не по порядку: подготовка сначала строит связи и проверяет цикл, затем применяет родителей до детей. Поздняя ссылка не решается молчаливым созданием неправильного корня.

Автосоздание категорий и опций — отдельные настройки, по умолчанию выключены; будущие записи видны в проверке. Несуществующее определение поля не создаётся из любого заголовка CSV: для него есть явный импорт определений. Несколько производителей из внешних систем нельзя автоматически превратить в единственный бренд Dharma Shop.

Группы применяются с проверкой версии; повторение сочетаний осей, отсутствие обязательного значения или превышение лимита блокирует изменение состава. Режимы состава/галереи/списков: добавить без дублей либо заменить явно. Замена состава отвязывает отсутствующих участников, но не удаляет товары. Изменение осей существующей группы требует проверки всего текущего состава.

## 7. Скачивание изображений и файлов — обязательная часть

### 7.1. Поведение

- Поддержать внешние картинки обложки/галереи, картинки категорий/брендов/бейджей и опций; документы в типизированных файловых полях товаров, категорий и групп.
- Ссылка может содержать query string, кириллицу, пробелы в закодированном виде или не иметь расширения. Имя берётся из безопасно разобранного `Content-Disposition` (`filename*` / `filename`), затем из URL; тип определяется по содержимому и сопоставляется с расширением.
- Относительная ссылка на старый сервер разрешается относительно **базового адреса медиа источника**. Она не подменяется путём целевого сайта по догадке. Существующие локальные файлы целевого сайта используются после проверки реального пути и типа.
- URL целевого сайта переводится в локальный путь только при совпадении действительного origin и базового пути. Совпадение названия хоста без учёта порта/пути недостаточно.
- Подготовка скачивает файлы потоком в закрытое временное хранилище, вычисляет хэш, проверяет размер/тип и записывает результат. До применения файлы не становятся вложениями каталога и не попадают в публичную папку медиа.
- Применение переносит подготовленные картинки через `ImageUploader`, документы через доверенный вход `FileStorage`; затем штатная запись прикрепляет их к сущности. Совместимость с преобразованием картинок и политикой имён магазина сохраняется.
- У документов сохраняются безопасное исходное имя, подпись, размер/MIME и порядок; у изображений — alt/title и порядок. Новые пути не перезаписывают чужой файл с таким же именем.
- Один URL внутри запуска скачивается один раз; общая подготовленная копия может использоваться для разных строк. Совпадение имени файла не означает равенство содержимого. При новом запуске проверяется свежесть источника; постоянный кеш по одному URL без проверки запрещён.
- Ошибка загрузки не очищает старую галерею/поле. По умолчанию строка блокируется; «пропустить проблемное вложение» допускается отдельным правилом для необязательных файлов и отражается в отчёте. Замена списка выполняется после успешной подготовки всего нужного списка.

### 7.2. Транспорт

Отдельная служба импорта для получения исходного прайса и медиа. Она не использует видео-загрузчик с фиксированными YouTube/VK/Rutube-хостами и не обходит проверки `FileStorage` поддельным `$_FILES`.

- HTTPS по умолчанию; необходимость HTTP задаётся явно для конкретного источника. Разрешённые домены прайса и медиа видны в профиле; CDN-домены добавляются явно, список неожиданных хостов виден в проверке.
- Проверка DNS/IP для IPv4 и IPv6, включая mapped-адреса; отказ от loopback, частных/служебных диапазонов и облачных metadata адресов; закрепление проверенного адреса на соединение. Одна проверка строки URL не защищает от смены DNS.
- Предлагаем разрешить до трёх переходов с повторной проверкой схемы/домена/IP/лимитов каждого адреса; запрещены переходы HTTPS → HTTP без разрешения и передача авторизации другому origin. Это уточнение первоначального строгого запрета редиректов из общего плана, пока остаётся предложением.
- Проверка TLS включена; лимиты соединения, полного запроса и объёма, даже без `Content-Length`; запись небольшими блоками на диск; ограничение параллелизма, повторов и общего дискового бюджета.
- Настройки типа и лимиты файловых полей продолжают действовать; HTML ответа, исполняемый файл, поддельное расширение, пустой ответ и ZIP вместо картинки не принимаются.
- Секреты авторизации не пишутся в открытые параметры профиля/отчёт. Если поставщик требует авторизацию, профиль ссылается на защищённую конфигурацию подключения; query-токены в журналах маскируются.

Файлы из ZIP медиа можно использовать при переносе: отдельный архив с локальной структурой, проверка числа/размера файлов, путей, symlink и степени сжатия; извлечение потоком, без «распаковать всё куда указано в архиве». Подготовленный архив имеет собственный хэш и связь с запуском.

## 8. Запуск, применение и возобновление

### 8.1. Разделение фаз

`receiving → reading → checking → checked → applying → done`; ошибки/пауза/отмена — отдельные состояния. Скачивание медиа — подфаза проверки со своим прогрессом. `checked` означает, что известен настоящий состав изменений и подготовлены требуемые файлы.

Проверка может писать служебные таблицы/закрытые временные файлы, но не меняет карточки, справочники, цены, остатки и внешние соответствия каталога. Все будущие создания справочников хранятся в плане. Обработчики форматов не выполняют запись сущностей.

Применение привязано к SHA-256 файла, снимку профиля/схемы сопоставления и версии подготовленного плана. Новый файл, изменение назначений или типов полей требует новой проверки. Редактирование профиля не меняет уже выполняющийся запуск; неприменённый отчёт помечается устаревшим при существенном изменении правил.

### 8.2. Частичная запись и параллельные изменения

До первого применения добавить и проверить штатную операцию частичного изменения в ядре. Импорт передаёт набор намерений: «изменить цену», «изменить количество», «заменить галерею»; неподключённые блоки вообще не записываются. Проверки и пересчёты используют те же службы, что ручная карточка. Нельзя ограничиться чтением полной карточки и последующим сохранением: за это время заказ может изменить остаток, и старая копия его затрёт.

Для существующей записи перед записью сравнивать её актуальные значения с проверенным снимком в изменяемых блоках. Группа учитывает `revision`, карточка — доступные признаки изменения и контрольный хэш. Активная блокировка редактирования сотрудника не отбирается. Окончательная запись должна иметь проверяемую защиту от гонки; способ блокировки/сравнения согласуется с границами служб ядра на этапе I0, а не считается решённым одной проверкой до вызова модели.

Цена меняется без вызова установки количества, если количество не сопоставлено. Резерв не меняется от импорта. Применение обновляет затронутые индексы, поисковый текст, группу и кеш; широкая пересборка всего каталога после каждой строки недопустима.

### 8.3. Долговечный журнал записи

Один активный запуск на профиль; дополнительно сериализовать запись одного внешнего ключа/целевой сущности между разными профилями. Аренда шага не должна истечь раньше максимальной разрешённой операции; долгие сетевые запросы вынесены в подготовку.

До изменения строки сохранить намерение, найденный target ID или устойчивую планируемую идентичность новой записи, ожидаемые значения и ключ повторения. После записи сохранить итоговый ID, внешнее соответствие и состояние строки. Если процесс погиб между этими шагами, продолжение сначала сверяет намерение с действительным состоянием; не начинает создание заново.

Для новой записи без артикула нужно доказать восстановление через зарезервированный ключ и уникальное назначение алиаса/родителя либо через расширение штатной службы записи. Простого `row_hash` после `save()` недостаточно: до фиксации журнала уже мог появиться новый товар. Неоднозначный результат восстановления останавливает строку для проверки, не создаёт ещё одну запись.

У продукта `Table::store()`/assets и последующая транзакция связей имеют разные границы. Поэтому внешняя транзакция вокруг порции не обещает полного отката. Отказ после частичной записи фиксируется как требующий восстановления, а не как «каталог не менялся». На I0 обязательны искусственные сбои после сохранения карточки, перед/после связей, перед фиксацией внешнего соответствия и перед отметкой строки выполненной.

Повтор завершённой строки сверяет и желаемые, и текущие значения; неизменившаяся строка не создаёт повторного движения остатков и повторных файлов. Отмена оставляет уже успешно применённые строки и отчёт о них. Полный откат импорта не входит в обещания первой поставки.

## 9. Хранилище, настройки и история

Разделение ответственности самостоятельной реализации:

| Слой | Что делает | Чего не решает |
|---|---|---|
| Получение источника | Браузерная загрузка, разрешённый локальный файл, URL, неизменяемый закрытый снимок | Не записывает каталог |
| Читатель формата | Заголовки, строки/типы ячеек, исходные номера и устойчивый курсор; потоковая нормализация | Не знает таблиц товаров/категорий |
| Схема назначений и преобразование | Разрешённые поля, типы, списки/числа/даты, простые выбранные преобразования без PHP/eval | Не считает произвольный экспортный столбец записываемым |
| Подготовка и сравнение | Ключи, связи, зависимости, будущие записи, изменения/ошибки, задания медиа | Не меняет каталог при проверке |
| Выполнение | Подтверждённые намерения, текущие права/конфликты, штатная частичная запись ядра, восстановление | Не дублирует бизнес-логику цены/остатков/индексов |
| Хранилище/журнал | Снимки, подготовленные строки/файлы, индексы, аренда и долговечные отметки | Не делает весь процесс одной общей транзакцией |
| UI, CLI, Scheduler | Входы в один протокол проверки/применения | Не содержат независимых алгоритмов импорта |

Регистрация дополнительных читателей — событие компонента импорта и группа плагинов `dharmashopimport`; обработчики типов/значений — отдельная явная точка расширения. Их точные имена, типы результата, поведение ошибки/снимка и контракт курсора фиксируются в I0 и затем одновременно в `TRIGGERS.md`/`ARCHITECTURE.md`.

Предлагаемые служебные таблицы:

| Таблица | Назначение |
|---|---|
| `#__dharmashop_import_profiles` | Название, состояние, тип записей, формат, источник/код источника, сопоставления и правила, checkout |
| `#__dharmashop_import_jobs` | Снимок профиля/схемы, источник и хэши, фаза/состояние, курсоры, счётчики, исполнитель, аренда, подтверждение и сроки |
| `#__dharmashop_import_rows` | Порядок строк, ключи, нормализованное намерение/изменения, найденный ID, состояния проверки/записи и восстановление |
| `#__dharmashop_import_files` | Закрытые источники, подготовленные медиа/архивы, хэши, метаданные, владельцы и связи с запусками |

Конкретные SQL-столбцы/индексы фиксируются на I0 после проверки протокола восстановления. Уникальность ключей, чтение страниц истории по индексу и порционная работа обязательны. Полный файл и все строки в одном JSON-поле профиля не хранятся. Существующая `external_ids` остаётся общей таблицей соответствий каталога.

Настройки в той же вкладке **Настройки магазина → Экспорт / импорт**: разрешённая папка входящих файлов, закрытое хранилище/срок хранения, предел источника/архива/строки, размер порции, время шага, сетевые лимиты, политика очистки. Видимые папки картинок и документов продолжают подчиняться настройкам своих хранилищ.

Входные прайсы, снимки и отчёты — закрытые данные. Нельзя защищать сырой CSV только `.htaccess`, который не работает на nginx. Если хранилище внутри webroot, файлы сохраняются как защищённые контейнеры без прямого доступа, читатель получает поток полезного содержимого; временный сырой XLSX для ZIP-чтения создаётся вне обслуживаемой папки с ограниченными правами. Не полагаться на то, что Joomla `tmp_path` всегда вне webroot.

История показывает сотрудника, профиль, источник без секретов, дату, фазу и числа созданных/обновлённых/неизменённых/ошибочных строк. Отчёт хранит номер строки, ключ, поле, причину и достаточный контекст; длинные тексты и секретные URL не дублируются во всех логах. Отчёт CSV защищён от формул.

Очистка не удаляет активные запуски, источники ожидающего подтверждения и вложения уже прикреплённых сущностей. Рабочие сироты очищаются по связям/сроку, а публичные медиа — только штатной проверкой использования, без удаления чужих файлов.

## 10. Права, CLI и расписание

Предлагаемые отдельные действия компонента: проверять импорт, применять импорт, видеть общую историю/отчёты; стандартные core-права на управление профилями. У каждого действия проверяются ACL и CSRF; доступ к исходнику/отчёту по владельцу или праву общего отчёта. Чужой `job_id`/file token не даёт доступ.

Право «применять импорт» не отменяет права ядра на создание/редактирование конкретной сущности. Для товара/категории учитывается ресурс записи/родителя; для полей и групп — специальные действия C90. Нельзя рассчитывать, что прямой вызов `Model::save()` автоматически повторит все проверки контроллера.

CLI предусматривается с начала проектирования: отдельные операции проверки и применения по ID подготовленного запуска, продолжение, ненулевые коды ошибок/блокировок и машинный отчёт. Новая команда не должна обходить подтверждённый план. Конкретные аргументы фиксируются при реализации; ожидаемый интерфейс — `dharmashop:import check <profile>` и `dharmashop:import apply <job>` с явным исполнителем для штатной записи.

Scheduler: источники только URL/папка, проверка перед каждым применением. Автоматическое применение включается владельцем после успешной ручной проверки профиля; сохраняется состав одобренных настроек и пользователь-исполнитель. Изменение схемы, доменов, ключей, прав пользователя, превышение лимита абсолютного числа/доли обновлений или ошибки переводят запуск в ожидание проверки, а не в безусловную запись. Отсутствующие записи не удаляются/не снимаются с публикации.

Результат задачи отправляется существующим механизмом уведомлений Joomla/магазина без отдельного SMTP-конфига и без рассылок покупателям. Настройка адресата/включения отчёта — в профиле/задаче. Для профиля с ручной загрузкой кнопка «В планировщик» объясняет необходимость постоянного источника.

## 11. Совместимость с нашим экспортом: закрыть реальные пробелы

Наличие CSV/XLSX экспорта ещё не доказывает полностью обратимый перенос. Исследование показало:

1. **CLI `--output`:** `Files::stream()` уже проверяет и пропускает защитный заголовок. `ExportCommand::copyArtifact()` читает его повторно, поэтому успешное копирование заканчивалось ошибкой. Повторное чтение заголовка устранено в исходниках и на test.test; успешное копирование ещё не проверялось; ранее проверялись регистрация/справка/ошибка отсутствующего профиля, а не этот успешный сценарий.
2. **Цена:** экспортный `price` — `price_final`, `base_price` — исходная цена. Импорт базовой цены со скидкой должен использовать `base_price`; импорт только итоговой цены со старой скидкой повторно применил бы скидку. Вычисленные `discount_amount`, min/max групп не записываются как исходные.
3. **Количество:** экспортный `stock` — `stock_total` (доступное количество с учётом резерва), а обычная запись `stock_qty` задаёт исходное количество основного места хранения. При резерве эти величины различаются. Добавить явную колонку исходного количества для обратимого обмена либо запретить автоматическое назначение агрегата; склады выдачи `warehouses` не путать с `stock_locations`.
4. **Медиа:** текущий экспорт основной/полевой галереи отдаёт пути, но не весь набор alt/title/подписей/метаданных. Для полного переноса добавить явные структурированные колонки, сохранив обычные понятные колонки для таблиц.
5. **Наследование:** текст/обложка могут быть уже разрешёнными значениями группы. Восстановление `inherit_*` требует отличать собственные значения от отображаемых; не материализовать наследование без правила.
6. **Внешние ID:** числовые ID категорий/полей/участников из другого сайта нужно переводить через источник/соответствия. Добавить устойчивые алиасы/внешние ссылки в совместимый профиль обмена, где их недостаточно.
7. **Потеря данных представлением:** режимы plain/yesno/emptyzero и переименованные подписи могут быть необратимыми; для профиля переноса использовать исходные значения и устойчивые ключи. Разделитель внутри значения требует структурированного варианта.

Расширения экспортного контракта оформляются как отдельная задача совместимости до проверки «выгрузил → загрузил → сохранилось то же состояние». Старые пользовательские профили экспорта не меняются скрыто.

## 13. Проверки готового импорта

1. **UI:** тот же визуальный язык Joomla/экспорта, RU/EN, светлая/тёмная тема; drop и обычный выбор; рабочий поиск назначений, CSV/XLSX настройки на первой вкладке; понятные нулевые состояния и ошибки, доступность с клавиатуры.
2. **Данные:** все сущности/типы полей; одинаковые названия в разных ветках; родители после детей; дубли/циклы/пустые обязательные значения; артикулы с нулями; скидки по датам; ноль и очистка; несопоставленные связи остаются.
3. **Частичные операции:** только цена, только количество, только описание, только один файл. Проверить, что остальные блоки, резерв и ручные изменения сотрудника сохраняются. Ошибки модели после частичной записи отображаются и восстанавливаются.
4. **Медиа:** картинки/документы с отдельного сервера, относительные ссылки старого сайта, CDN, HTTP по явному правилу, имена из `Content-Disposition`, кириллица/пробелы, URL без расширения, дубликаты имён с разным содержимым, повреждённый/слишком большой файл, HTML вместо PDF; повтор и сохранение alt/title/подписей/порядка.
5. **Источник:** скачивание, замена/исчезновение файла поставщика после проверки; применяем проверенный снимок. Разные кодировки, многострочный CSV, переставленные/повторяющиеся заголовки; sparse XLSX, shared strings, формулы, большой ZIP/XML.
6. **Возобновление:** обрыв на каждой границе §8, два запроса/планировщик одновременно, два профиля на одну запись, устаревшая проверка, ошибка в середине, повтор уже успешной строки, отмена. Без двойных товаров, движений и вложений.
7. **Защита:** отдельные права проверки/применения/сущностей/отчётов, чужой file token/job ID, CSRF, пути/symlink, внутренние IPv4/IPv6 и редиректы/DNS, архивные бомбы, исполняемые файлы, вредный HTML/формулы отчёта. Тестовые сетевые фикстуры не ослабляют правила обычного профиля.
8. **Круговой перенос:** экспорт в совместимом наборе → чистая отдельная база → импорт → сравнение карточек, дерева, полей/опций, групп, базовых цен/скидок, количества/резерва и реальных файлов. Известные преобразования изображения сравнивать по содержанию/метаданным, а не требовать прежний путь файла.
9. **Масштаб:** 100 тыс. товаров и большой файл; память зависит от порции/строки, а не каталога; источники/файлы не читаются целиком. Время импорта измерить отдельно от экспорта: сохранение, проверки и скачивание существенно дороже чтения.
10. **Установка/обновление:** пакет поверх существующего магазина сохраняет данные и настройки; нет деинсталляции ради новых таблиц. Состав manifest/build совпадает, справка встроена; тестирование только в разрешённой среде `test.test`/изолированных таблицах, без правок соседних сайтов.

## 14. Предлагаемые исходные настройки

Чтобы реализация начиналась с определённого поведения: CSV и строка заголовков по умолчанию; внешний ключ источника/артикул вместо догадки по названию; создавать и обновлять как два явных разрешения профиля; новые записи без заданного состояния — неопубликованные; пустая ячейка сохраняет существующее значение; отсутствующие записи не меняются; автосоздание категорий/опций выключено; ошибка блокирует применение; замена списков только явно; скачивание внешних файлов доступно в первой поставке, домены/политика включаются в профиле; Scheduler сначала проверяет, автоматическое применение требует одобренного профиля.

Открытые решения перед I0: окончательная форма ядровой частичной записи/восстановления, лимиты источников/сети/архивов, безопасные редиректы/HTTP, формат структурированных колонок для обратимого переноса, механизм хранения авторизации поставщика и исполнитель CLI/Scheduler. Они не препятствуют подготовке интерфейса/читателя, но должны быть зафиксированы до записи реального каталога.
