# Импорт каталога

Импорт поддерживает CSV и отдельный плагин Excel XLSX для категорий, брендов/производителей, бейджей и товаров.
Определения полей, группы полей, группы товаров, CLI и планировщик импорта пока не подключены.
Пользовательская приёмка открыта.

Импорт устроен как экспорт: запуск и окно прогресса — прямо из списка профилей, у каждого профиля в списке видны состояние и результат последнего запуска, а история запусков удаляется поштучно или целиком.

## Подготовка профиля

1. Откройте **Dharma Shop → Импорт → Создать**.
2. Выберите тип записей, разделитель, кодировку, наличие заголовков и, если над заголовком есть служебные строки, их число («Строк до заголовка»). Поддерживаются UTF-8 и Windows-1251.
3. Выберите CSV или Excel (XLSX), загрузите файл знакомым загрузчиком, укажите HTTPS URL или путь внутри разрешённой папки `files/import/inbox`. Для XLSX после сохранения выберите лист.
4. Нажмите **Сохранить и продолжить**. В сопоставлении появятся номера колонок, заголовки и примеры. Выберите назначения; остальные оставьте «Не импортировать».
5. Укажите постоянный код источника и ключ поиска. Внешний ключ запоминается в таблице соответствий. Внутренний ID используется только для существующих записей; артикул — только для товаров. Неоднозначный алиас отклоняется.
6. Разрешите создание/обновление. Новые записи по умолчанию не публикуются. Новому товару нужна категория из CSV или профиля.

При смене заголовков или типа записей сопоставление определяется заново.
Ограничения: источник 64 MiB, строка 1 MiB, 200 колонок. Входящую папку создаёт владелец сайта.

## Проверка и применение

В списке профилей у каждого профиля есть кнопка **Проверить**. Она открывает общее окно прогресса магазина: файл читается порциями, строки проверяются, медиа скачиваются в закрытое хранилище. Каталог на этих стадиях не меняется.

Когда проверка закончится, окно показывает сводку: сколько записей **будет создано**, **обновлено**, останется **без изменений** и сколько строк **с ошибками**. Дальше:

- **Подтвердить применение** — запись в каталог тем же окном и теми же порциями; по завершении сводка показывает, сколько создано и обновлено.
- **Скачать ошибки (CSV)** — номер строки файла, ключ, причина и исходные ячейки; исправьте файл и запустите проверку заново.
- **Продолжить обработку** — если окно закрыли или запуск остановился, кнопка в списке (или на странице запуска) продолжает с того места, где он прервался; обработанное не повторяется.
- **Проверить заново** — заменяет непринятый запуск новым с текущим файлом.

Ошибка одной строки не останавливает запуск: строка помечается ошибкой и пропускается, если в профиле включён пропуск ошибочных строк. Сбои базы данных и ошибки кода останавливают запуск целиком.
Колонка **Результат** в списке показывает состояние и итоги последнего запуска; ссылка ведёт на страницу запуска со строками и изменениями «было → стало» и фильтром «Только ошибки / будут созданы / обновлены / без изменений».

Повторный импорт того же файла ничего не меняет: числа, медиа и пустые значения сравниваются по смыслу (`0.000` и `0`, лишние ключи в описании картинки не считаются изменением).

XLSX сохраняется как неизменяемый источник; выбранный лист нормализуется в защищённом хранилище перед общим проходом. Формулы не вычисляются: замените их значениями. Файлы с макросами, внешними ссылками, старым XLS или размером распаковки сверх лимита не принимаются.
Каталог на этих стадиях не меняется.

В результате показаны ключ, действие, ошибки и изменения строки. Отчёт листается по 100 строк.
После проверки доступно **Подтвердить применение**, затем **Продолжить обработку**.
Ошибки по умолчанию запрещают применение; специальная опция профиля разрешает применить только корректные строки.

Изменяются только сопоставленные поля. Пустая ячейка сохраняет прежнее значение;
`__CLEAR__` явно очищает его, `\__CLEAR__` передаёт буквальный текст. `0` является значением.
Несколько значений разделяются ` | ` (настраивается) либо передаются JSON-массивом.
Медиасписок заменяет выбранную галерею; добавление к существующей галерее пока отсутствует.

Повтор внешнего ключа обновляет соответствующую запись. Строки с одинаковым ключом и одинаковым содержимым объединяются, строки с одним ключом и разными данными отклоняются как дубли.
Исчезнувшие из файла записи не удаляются. Если выбранные значения изменены после проверки, применение останавливается.
Сбой строки не откатывает ранее завершённые строки. При неоднозначном восстановлении сверьте уже записанные данные перед новым запуском.

## Цены, количество и связи

Базовая цена — цена до скидки. Итоговую цену экспорта нельзя автоматически импортировать как базовую.
Физическое количество — количество до вычитания резерва; доступный остаток экспорта не является его заменой.
Резерв заказа не импортируется. Обновление цены не записывает старый снимок количества.

Категория товара — внутренний ID или существующий путь из алиасов.
Дополнительные категории/бейджи — списки ID; бренд — один ID.
По умолчанию справочники и опции полей должны существовать.
Поля товаров/категорий доступны по `field.<алиас>`; опции ищутся по алиасу или однозначному названию.

### Создание отсутствующих объектов

На вкладке «Правила записи» есть три независимых переключателя, по умолчанию выключенных:

- **Создавать отсутствующие категории** — для пути категории товара. Разделитель уровней по умолчанию `/`, его можно заменить, например, на `->`. Часть пути допускает `Название|||алиас`. Поиск идёт внутри конкретного родителя; создаются только недостающие уровни. Состояние новых категорий берётся из правила публикации новых записей.
- **Создавать отсутствующие поля** — в сопоставлении выберите «Новое поле», укажите название, алиас и тип. Доступны текст, редактор, число, диапазон, флажок и список с несколькими значениями. Новое поле относится к товарам либо категориям согласно типу профиля, доступно во всех категориях этого назначения, не является обязательным. Алиас с несовместимыми названием/типом/назначением либо выключенное поле вызывает конфликт. Повторные строки используют уже созданное поле.
- **Создавать отсутствующие значения списков** — добавляет варианты к существующему полю типа «Список», сохраняя прежние варианты и их ID. Варианты цветов автоматически не создаются. Для нового поля-списка варианты берутся из его ячеек.

Создания видны в отчёте проверки и выполняются только после подтверждения.
При остановке уже созданные категории, поля и варианты не откатываются; повтор использует их при совпадении с проверенным планом.
Для определения полей нужны права управления полями, создания/редактирования и публикации определений.

У категорий/брендов родитель задаётся внутренним ID либо внешним ключом того же источника.
Второй вариант требует режима внешнего ключа; родитель может идти ниже дочерней строки.
Циклы и отсутствующие родители отклоняются. Бейджи остаются плоскими.

## Внешние файлы и изображения

Укажите точные разрешённые домены, включая CDN и домены перенаправлений.
HTTPS используется по умолчанию, HTTP включается явно в профиле.
Локальная сеть, loopback, служебные IP и URL с логином/паролем запрещены.
Медиа ограничены 16 MiB, тремя перенаправлениями и 25 секундами на скачивание.
В общих настройках обмена задаются также предел числа скачиваний и общего размера медиа за запуск: по умолчанию 5000 файлов и 512 MiB.

Пути `images/...` ссылаются на существующие файлы этого сайта.
Остальные относительные пути при заданном базовом URL разрешаются относительно него.
Для переноса на другой сервер нужны полные URL исходного публичного сайта и разрешение его домена.

Изображения проходят штатные проверки загрузчика магазина. Документы полей проверяются по расширению, MIME, размеру и структуре офисных контейнеров.
Имена из Content-Disposition используются после проверки.
JSON медиа допускает объекты `{"url":"https://example.ru/photo.jpg","alt":"Описание","title":"Подпись"}`.

Подготовленные файлы сохраняются в закрытые PHP-контейнеры.
Папка подготовки и разрешённая входящая папка задаются в **Настройки → Экспорт / импорт**.
Смена папки подготовки не переносит старые файлы: каждый файл сохраняет свой путь.
История запусков: **История импорта** в панели списка профилей. Выбранные запуски удаляются кнопкой «Удалить», завершённые и отменённые — кнопкой «Очистить историю»; вместе с запуском удаляются его строки и подготовительные файлы (исходный файл профиля сохраняется). Уже внесённые в каталог изменения остаются, выполняющиеся запуски не удаляются. Удаление требует права удаления компонента. Автоматическая очистка по расписанию пока не подключена.

## Права

Раздельные права: доступ к компоненту, профили, проверка/загрузка, применение и просмотр чужих отчётов.
При записи проверяются также права создания/редактирования и изменения состояния самих записей каталога.
Чужие открытые карточки не разблокируются. Ошибки записываются в журнал Joomla `com_dharmashop_import.log.php`.

## Импорт файла стороннего магазина

Типичный прайс стороннего магазина — одна таблица со многими колонками. Достаточно сопоставить нужные: внешний код, артикул, название, алиас, путь категории, цену — остальное оставьте «Не импортировать». Пути категорий вида `Название|||алиас///Название|||алиас` разбираются с разделителем уровней «///»; при включённом «Создавать отсутствующие категории» недостающие уровни создаются. Если алиас не задан, он формируется из названия, при совпадении добавляется `-2`, `-3`…
Если колонки с одним названием повторяются (например, несколько `category`), сопоставьте нужную, остальные пропустите.

## Круговой обмен «экспорт → импорт»

Файл, выгруженный экспортом магазина, можно импортировать обратно: подписи и ключи колонок распознаются автоматически. Для точного переноса в экспорт добавляют колонки: `stock_qty` (физическое количество), `gallery_json` и `field.<алиас>@json` (картинки и файлы с подписями), `category_paths_extra` (дополнительные категории). Файлы и картинки по ссылкам скачиваются, если домен разрешён в профиле.
Сценарий проверки: `dev/scenario/roundtrip.py` (копии товаров, правки цен, остатка, галереи, повторный импорт) и `dev/scenario/benarmo.py` (прайс стороннего магазина).
