# Определение покупателя по контактам

2026-10-08. Правило согласовано пользователем: гостевые заказы относятся к одному покупателю, если одновременно совпадают email и телефон. Разное имя получателя сохраняется в конкретном заказе; непустое имя карточки покупателя автоматически не заменяется. При отличии одного контакта — другой покупатель. Если один из контактов отсутствует, автоматического объединения нет. Аккаунты Joomla сопоставляются только по user_id, гостевые данные не объединяются с аккаунтами.

Причина бага C73: customer_id сохранялся в гостевой корзине и затем использовался без проверки новых контактов. Все три заказа 000001–000003 из cart_id=17 связались с customer_id=1, контакты карточки были заменены последним заказом. В снимках заказов сохранились три разные пары email/телефон.

## Реализация

`Customer\ContactKey` нормализует email (trim + нижний регистр), телефон (цифры) и рассчитывает SHA-256 пары с разделителем NUL. `customers.contact_key` nullable char(64), UNIQUE uq_guest_contact: только гости с обоими контактами. Хеш нужен для точного индексируемого сопоставления и атомарной защиты от параллельных первых заказов; это не ключ доступа и не публикуется. Несколько NULL разрешены.

`CustomerService::forOrder` не определяет покупателя по корзине. Зарегистрированный — UNIQUE user_id; гость с полной парой — атомарный INSERT/ON DUPLICATE по contact_key; без полной пары — отдельная запись. Непустое имя существующего покупателя сохраняется. Снимок заказа всегда содержит введённое имя. Изменение контактов в админке пересчитывает contact_key; совпадение с другим гостем отклоняется, автоматического слияния нет.

`CustomerStorage::upgrade` аддитивно добавляет столбец/индекс, заполняет ключи существующих гостевых записей партиями без OFFSET. Исторические дубли не удаляются/не объединяются: первую запись индексирует, конфликтующие оставляет с NULL. Установщик пакета запускает обновление после установки компонента. Повторное выполнение безопасно.

Сопоставление CRM не даёт доступ к старым заказам: клиентские проверки по orders.user_id и серверным разрешениям гостевой сессии остаются прежними. customer_id не используется для авторизации.
