# Безопасность: что защищаем и как проверяем

Проверка выполняется повторяемо: `dev/security-upload.sh` (после входа `dev/web-login.sh`) — атаки на загрузчик изображений, ожидание «OK» у каждой строки. Любая новая точка входа (загрузка, AJAX, действие из списка, консольная команда) получает здесь запись и проверку.

## Загрузчик изображений (`MediaController::upload`, `ImageUploader`)

| Угроза | Защита | Проверено |
|---|---|---|
| CSRF | токен формы Joomla только в теле POST (`Session::checkToken('post')`); GET-запросы отклоняются; ответ `no-store`, `nosniff` | без токена, токен в адресе, чужой токен, GET — отказ |
| Доступ без прав | вход в админку (иначе 403), `core.create` или `core.edit` компонента | гость — 403 |
| Подмена типа (PHP под видом картинки) | расширение из белого списка (настройки «Медиа» ∩ наш список), содержимое проверяется `finfo` и `getimagesize` | текст PHP как `.png`, файл `.php` — отказ |
| «Полиглот» (валидный PNG + PHP в конце) | файл с `<?php` отклоняется; расширение после сохранения только из белого списка; в папке загрузок `.htaccess` запрещает исполнение скриптов | PNG с хвостом — отказ |
| Обход путей | имя файла — транслит `[a-z0-9-]`, расширение приводится к нижнему регистру; папка — только из списка (`categories`, `icons`, `seo`, `products`, `gallery`, `common`, иное → `common`); корневая папка настроек очищается от `..`, кириллицы, пустых сегментов | `../../evil.png`, папка `../../../tmp` |
| SVG (скрипты, события, внешние ссылки) | штатный санитайзер Joomla (`enshrined/svg-sanitize`, внешние ссылки убираются), отказ при `@import`/внешнем `url()`, `<!ENTITY`; SVG записывается уже очищенным; при прямом открытии — `Content-Security-Policy: sandbox` | `onload` через `/`, `javascript:` в виде HTML-сущности, `@import` |
| Гонка имён | имя занимается атомарно (`fopen` в режиме `x`) | — |
| Огромные изображения | площадь не более 80 млн пикселей, размер — меньший из «Медиа» и PHP | — |
| Конвертация WebP | При включённом `image_convert_webp` JPEG/PNG/AVIF преобразуются через `Joomla\CMS\Image\Image`; расширение назначается `.webp` только после проверки MIME и исходных размеров. SVG, GIF (анимация) и BMP не конвертируются; сбой обработки отклоняет загрузку. | Реализация добавлена; поведенческий сценарий загрузки ещё не прогонялся |
| Переход старых ссылок на WebP | Команда в списке товаров требует CSRF-токен и `core.manage`, обрабатывает ссылки порциями, ограничивает файлы корнем сайта, проверяет MIME/размер и не перезаписывает оригиналы или существующие WebP. Обновляет обложки, галереи, SEO-картинки, параметры категорий и корневых страниц; неподдерживаемые форматы оставляет без изменений. | На test.test команда завершилась успешно: последняя порция перевела 1 ссылку, ошибок 0; WebP проверен по MIME, исходный JPEG сохранён |
| Подстановка пути в форму | фильтр `ImageUploader::filterPath` у всех полей `imageupload`: только `images/…` с допустимым расширением, без `..`, схем (`javascript:`, `http:`), кавычек | `javascript:`, `images/../configuration.php`, `http://…`, `.php`, кавычки — обнуляются; допустимые пути сохраняются |
| Удаление чужого | `ImageCleaner` удаляет только файлы внутри папки загрузок и только если на них не ссылается другая запись | — |
| Утечка внутренних сообщений | непредвиденные ошибки — в журнал, пользователю общий текст | — |

Ограничения и задел: WebP включается отдельно для новых JPEG/PNG/AVIF; ранее загруженные ссылки меняются только при ручном запуске команды. SVG остаётся векторным, GIF сохраняет анимацию, BMP и неподдерживаемые Joomla форматы остаются исходными. Нарезка изображений и удаление скрытых метаданных пока не реализованы; на nginx `.htaccess` не действует — нужен запрет исполнения скриптов в `images/` в настройках сервера.

## Прочие точки входа

Действия списков и команды обслуживания (`rebuild`, `cmdIndex`, `cmdProducts`, `cmdSales`, пакетная обработка, избранное) проверяют токен и права (`core.manage`, `core.edit`/`core.create`); проверено чтением кода, в `dev/security-upload.sh` не входит.

## Поиск и подсказки (`SearchController::suggest`, адрес поиска `filter[search]`)

| Угроза | Защита | Проверено |
|---|---|---|
| Внедрение SQL через запрос | запрос очищается (управляющие символы, длина ≤ 100), слова нормализуются до букв и цифр, значения только параметрами (`bind`), в булев FULLTEXT-запрос попадают только буквы и цифры; артикул — экранирование `% _ \` | запросы `'<script>`, `%`, `a\0b`, `a'b` — без ошибок и совпадений |
| Синонимы и варианты слов | правила синонимов из настроек (доступ только администратору) разбираются и нормализуются до букв и цифр, варианты (раскладка, транслитерация) строятся только из букв; число вариантов слова ≤ 8, слов запроса ≤ 8; все значения — параметрами | — |
| Перегрузка | предел числа подсказок (≤ 20), задержка и отмена запроса на клиенте, минимум символов | — |
| Скрытые товары | запрос присоединяется к обычному запросу каталога: опубликованные товары в опубликованных и доступных категориях | — |
| XSS в подсказках | скрипт подставляет значения через `textContent`, подсветка — DOM-узлами (`mark`), `innerHTML` не используется; ссылки и картинки — из ответа сервера (экранированные адреса) | запрос с разметкой выводится текстом |
| Кэш и индексация | ответ `no-store`, `X-Robots-Tag: noindex`; страницы списка с `filter[search]` — `noindex, follow` | — |

## Привязка гостевых заказов к аккаунту (`OrdersModel::claimGuestOrders`)

| Угроза | Защита | Проверено |
|---|---|---|
| Захват чужих заказов регистрацией с чужой почтой | по умолчанию привязка только при подтверждённой почте (активация по письму включена и пройдена, пользователь не заблокирован); режим «по любому совпадению» помечен небезопасным | при «Активации: нет» заказ не привязывается; режим «любой» привязал заказ с совпавшим e-mail (после проверки возвращён) |
| Лишние запросы | один индексированный `UPDATE` (по `contact_email`) раз за сессию | — |

## Мои заказы (`Site\Model\OrdersModel`, вид `orders`)

| Угроза | Защита | Проверено |
|---|---|---|
| Чужие заказы | запрос ограничен `orders.user_id` = номер вошедшего пользователя (привязка параметром), гость получает пустой список и приглашение войти; состав и контакты в списке не читаются; просмотр заказа — прежняя проверка `OrderModel` | пользователь видит свои заказы и открывает их; чужой заказ — 404; гость на странице — перенос на вход |
| Кэш | страница `no-store`, `private`, `noindex, nofollow` | — |

## Корзина (`CartController`: cart.add / update / remove / clear)

| Угроза | Защита | Проверено |
|---|---|---|
| CSRF | только POST и токен формы Joomla (`Session::checkToken('post')`); GET и чужой токен — отказ (JSON `success: false`) | запрос без токена, GET с токеном, чужой токен — отказ |
| Внедрение через идентификаторы и числа | `product_id`, `variant_id`, `item_id` приводятся к целым, все запросы — с привязкой параметров (`bind`); количество — число, округление до 3 знаков, проверка минимума/шага/максимума/остатка | `product_id=205' OR 1=1--` → 205 (целое), отрицательный id — «товар недоступен», `qty=abc` — «меньше минимального», `qty=1e9` — «нет в наличии» |
| Чужая корзина | корзина определяется токеном cookie (32 hex, `HttpOnly`, `SameSite=Lax`, `Secure` на HTTPS) или `user_id`; строки другой корзины недоступны (`cart_id` в каждом запросе) | — |
| Режим каталога | при `catalog_mode = 1` все действия отклоняются, страница корзины — 404, модуль и скрипты корзины не подключаются | проверяет владелец (настройки через базу не меняются) |
| Скрытые товары | добавить можно только опубликованный товар в опубликованных и доступных категориях (как на странице товара) | снятый и несуществующий товар — «недоступен» |
| Фрагмент мини-корзины (`format=raw`) | показ определяют настройки модуля, читаемые из базы по номеру `mid` (только опубликованный модуль `mod_dharmashop_cart` сайта; параметры показа через адрес не принимаются); классы кнопок очищаются (буквы, цифры, «-», «_») и экранируются; данные корзины — те же, что у страницы (по токену cookie) | запрос с чужим `mid` — значения по умолчанию; класс с кавычкой — вычищается |
| Окно выбора товара (`products&layout=modal`) | админка, доступ как к списку товаров (`core.manage`), токен в адресе поля, значения выводятся через `escape` | запрос без входа — форма входа |
