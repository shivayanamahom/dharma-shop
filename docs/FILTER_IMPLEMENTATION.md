# Фильтр F4–F8: реализация и проверки

Актуально на 2026-10-12. Дополняет исторический план FILTER.md; при расхождениях этот документ описывает текущий код.

## Настройки и единицы выдачи

В config.xml вкладка «Фильтр»: enabled, независимый каскад, counts off/base/live, count_cap (10001), live_limit (20000 кандидатов), query_ms (1500), cache_minutes (10), max_fields (12), max_values (50), canonical category/self, noindex и nofollow. Пределы дополнительно ограничены сервером.

Модуль `filtered_listing=inherit|groups|products` действует при непустом валидном фильтре. Без фильтра используется category_listing_mode магазина. Инициатор filter_module проверяется через ModuleHelper: публикация, ACL, назначение меню. Модуль не передаёт SQL. Все условия должны совпасть **на одном товаре** группы. Таксономия группы определяет её место; товарные поля/бренд/бейдж/цена — соответствие участника. DISTINCT положительный product_id / отрицательный group_id даёт единицы выдачи, total и фасетов. ROW_NUMBER выбирает подходящего участника по сортировке до LIMIT. AJAX-карточка показывает его данные и бейджи; все карточки вариантов заранее не передаются.

## Каскад и числа

`cascade=inherit|on|off` наследует filter_cascade магазина. Каскад учитывает состояние даже при counts=off. Off скрывает числа; base выводит базовые, live — текущие. OR-фасет исключает собственное поле из условий; AND сохраняет, чтобы добавление значения учитывало прежний выбор. Системные справочники и цена согласованы с этой семантикой. Нули hide/disable/show согласно empty_options; выбранное остаётся доступным для снятия. Прямая несовместимая ссылка честно показывает пустой результат.

В режиме «Сразу» список и форма обновляются одним обычным запросом страницы. В режиме кнопки filter-cascade.js вызывает read-only `task=filter.refresh&format=json`: только HTML формы, без карточек. Debounce/AbortController отбрасывают старые ответы. Filter.js сохраняет фокус, раскрытие, URL/history и SEO head. При смене конфигурации/позиции модуля выполняется обычная навигация. Сброс/последнее снятое значение удаляют filter_module; прямой пустой URL нормализуется 301 также без JS.

## Хранение и бюджет

On_sale — индексируемый столбец products, сопровождается ProductRebuilder/SaleScheduler. FilterStorage выполняет аддитивную миграцию столбца/индекса. FacetIndexer меняет категорию/поле транзакционно; полный пересчёт порционный, старые данные доступны до фиксации порции. Записи товаров, групп, таксономии, полей и акций сбрасывают кэш.

ScopedFacets использует тот же запрос кандидатов, что список. Ключи включают префикс БД, контекст, доступ, политику и состояние. Предрасчёт одиночных товаров применяется при проверенной полной доступности категорий; группы/ограниченный ACL считаются по фактическому составу. Проверка полной доступности кэшируется и инвалидируется категориями.

Live ограничен числом кандидатов и общим временем фасетов. MAX_EXECUTION_TIME получает оставшийся бюджет; это ограничение SQL, не жёсткий таймер HTTP. При превышении — базовые данные с отметкой ≈. Если доступность неизвестна, числа скрываются, значения остаются выбираемыми: неизвестность не становится ложным нулём. Fallback кэшируется на обычный TTL до записи каталога/истечения. В этом случае каскад не гарантирует исключения всех пустых сочетаний. Порог защищает нагрузку, не обещает точный live на любом объёме.

## Поля, макеты, ресурсы

Нативный блок поля «Фильтр»: OR/AND, control, сортировка, лимит, поиск, раскрытие. FilterSettings валидирует значения. Логика строки модуля переопределяет поле также в SQL. Optional `Fields\FilterTypeInterface::filterKind(): ?string` возвращает option/number/range/null и соответствует store(). Старые провайдеры продолжают работать по типизированному store; SQL от плагина не принимается.

Controls: checkboxes/radio/select/buttons/swatches/images, range с отдельными range-slider/range-inputs, switch. Поиск/«ещё» подключаются при необходимости; без JS видны все значения и доступны числовые поля. В горизонтальном dropdown число выбранных значений заменяет галочку, изменяется сразу; диапазон считается одним условием. Образцы используют контексты field.color.filter/field.option.filter. Переопределения — LAYOUTS.md.

Dispatcher подключает filter.js при ajax/instant, cascade.js при каскаде, slider.js и узкий filter-range.css при слайдере, values.js при длинных/ограниченных списках или dropdown, sticky.js при липкости. Bootstrap dropdown/collapse/offcanvas — по виду. Сторонней библиотеки слайдера нет. Sticky применяется к обёртке модуля, учитывает desktop/mobile и отступ 0–300 px; всегда выдвижной фильтр не приклеивается.

System plugin dharmashoppositions добавляет позиции в штатный выбор Joomla: dharmashop-products-top под подкатегориями, -left/-right рядом с товарами. CatalogModules выводит модули на HTML-страницах category/brand/badge/search. Явная ширина основной колонки Bootstrap 12/9/6 устраняет перенос товаров из-за intrinsic width Swiper при первом открытии.

## Быстрые интервалы цены

Одна строка — один интервал: `подпись = минимум-максимум`. Подпись произвольная, числа без пробелов и валюты. Пустая граница снимает соответствующее ограничение:

```text
До 50 000 = 0-50000
50 000–100 000 = 50000-100000
От 100 000 = 100000-
```

На сайте это ссылки под ценой, сохраняющие остальные условия. Дробная часть через точку или запятую. В форме модуля добавлена постоянная видимая подсказка с примерами.

## Проверки и границы

71 проверка dev/filter-final-checks.php: состав/total двух scopes, 5 сортировок, пустое/бренд/поле, OR/AND модуля, акция, несовместимость, мусор/числовые пределы, стабильный ключ, native maintenance facets+verify. Браузер: первоначальные колонки/reset/uncheck, каскад hide/disable/counts off, button mode, dropdown, sticky24, клавиатурный дробный шаг. Search/more/цвет — отдельный fixture реальных layouts. Замеры реального CategoryModel на изолированных таблицах 100/10000/100000 — BENCHMARKS_NOTES.md и JSON evidence.

Не проверены конкурентные записи, вся матрица ACL/шаблонов, физический touch и производственный сервер. Большая групповая категория не достигла исходной цели ≤80 мс; оптимизация ещё возможна. Fdemo-* нужны для воспроизведения, удаление отложено до окончания приёмки. Пользовательские данные не удаляются.
