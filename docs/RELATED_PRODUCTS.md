# Связанные товары

Запрос пользователя 2026-10-09: отдельная вкладка настроек с нативным повторяемым subform; включение, заголовок, точка вывода товара, ручной/автоматический подбор, количество, grid/list, карточки компонента или собственные переопределяемые макеты плагина. Для нескольких полей пользователь подтвердил И между полями; внутри одного поля достаточно общего значения.

Реализация: системный плагин `plg_system_dharmashoprelated`, чтобы штатное `onContentPrepareForm` Joomla работало и в `com_config`, и в редакторе товара без зависимости от плагина административного меню. Собственное включение выключено по умолчанию. Используются существующие события `onDharmaShopProductBefore/After…`, новых событий нет. Для взаимных связей добавлен восстанавливаемый индекс плагина, описанный ниже.

Блоки находятся в параметрах компонента `related_blocks`, включение — `related_enabled`. Постоянный случайный `alias` создаётся при первом сохранении, не зависит от заголовка и порядка. Ручные связи — `products.params.related_<alias>`, массив строк с `product_id`; запросы JSON не используются, IDs читаются из уже загруженной карточки. Параметры отсутствующих вкладок сохраняются при редактировании товара.

Общий пикер компонента уже существует: `type="modal_product"`, prefix `Dharma\Component\DharmaShop\Administrator\Field`, список `products/modal`. Общая повторяемая форма `administrator/components/com_dharmashop/forms/product_selection.xml` доступна любому плагину через `type="subform"`, `multiple="true"`, `validate="Subform"`, `formsource="administrator/components/com_dharmashop/forms/product_selection.xml"` (путь относительно корня сайта). Поле строки — `product_id`. Стандартный модальный пикер работает с поиском, фильтрами и пагинацией.

Авто по категориям: выбранные категории объединяются через ИЛИ, индекс включает их подкатегории. Пункт «Текущая категория товара» (`current`) выбран по умолчанию и использует основной `products.catid`. Его можно сочетать с явными категориями через ИЛИ; пустой выбор также означает текущую основную категорию. Явно сохранённые ID категорий сохраняются. Авто по полям: `fields_operator=and` (по умолчанию) требует совпадения всех выбранных опубликованных доступных полей; `fields_operator=or` — хотя бы одного выбранного поля. Варианты значений одного поля в обоих режимах — ИЛИ. Строки/числа/диапазоны сравниваются точно; списки — по option_id. Пустое или недоступное поле не превращает условие в подбор всего каталога. Поля типа text/media исключены: их значения не подходят для индексируемого равенства. Для вариантных полей все совпадения относятся к одному опубликованному варианту кандидата. Сам товар исключён во всех режимах; ручные дубли удаляются, порядок сохраняется. Неопубликованные товары и товары в закрытых категориях/ветках не выводятся.

Карточки получают данные пакетно через `CategoryModel::attachCardData`; нет запросов на каждый товар. Общий `Site\Support\ProductCardRenderer` готовит данные цены/скидки/полей/изображений/корзины для компонентов и плагинов. Изображения связанных товаров используют контексты `product.related.grid/list`. Карточки компонента учитывают его настройки и переопределения. В собственных карточках плагина можно менять разметку целиком.

Переопределения:
- Обёртка: `templates/<шаблон>/html/plg_system_dharmashoprelated/default.php`.
- Обёртка слайдера: `templates/<шаблон>/html/plg_system_dharmashoprelated/slider.php`.
- Карточки плагина: `templates/<шаблон>/html/layouts/plugins/system/dharmashoprelated/grid.php` и `list.php`.
- Карточки компонента: существующие `html/layouts/components/dharmashop/product-card/{grid,list}.php` и общие части.

Редактор товара выводит сторонние fieldset с префиксом `extension_` через общий `administrator/layouts/extension-tabs.php`; название вкладки берётся из label fieldset. Другие плагины могут пользоваться этим механизмом.

## Взаимные ручные связи (запрос пользователя 2026-10-09)

В каждом ручном блоке — `reciprocal`, по умолчанию 0. При включении явное назначение А → Б даёт встречный показ Б → А в том же блоке. Прямые назначения остаются исходными данными в `products.params`; встречные вычисляются и не записываются в чужой список ручного выбора. Отключение настройки скрывает встречные связи; удаление назначения снимает обратную связь. Независимое явное назначение Б → А сохраняется. Дубли и сам товар исключены, транзитивного расширения А → Б → В нет. Прямой ручной порядок имеет приоритет, затем встречные по ID; общий лимит блока применяется после проверки доступности. В редакторе встречные связи показаны нативной информационной заметкой (первые 20), отдельно от редактируемого выбора.

Для поиска обратного направления без сканирования JSON используется производный индекс плагина `#__dharmashop_related_products`: `source_id`, `block_alias`, `target_id`, PK `(source_id, block_alias, target_id)`, обратный индекс `(block_alias, target_id, source_id)` и индекс удаления по `target_id`. Создаётся аддитивно скриптом установки; первое добавление заполняется из существующих params курсорными порциями по 200. `onContentAfterSave` обновляет исходящие связи сохранённого товара, `onContentAfterDelete` очищает обе стороны. При обновлении индекса строка исходного товара читается под блокировкой: источник истины — последнее сохранённое значение params. Витрина соединяется с индексируемой выборкой кандидатов, без JSON_* и запросов на карточку. Таблица содержит только восстанавливаемый индекс; при удалении плагина она удаляется, ручные назначения в товарах остаются.

Прямые изменения params через SQL или импорт в обход стандартных событий требуют пересборки `(new Support\Relations($db))->rebuild()`; обычное сохранение товара индексирует связи даже при выключенном собственном `related_enabled`, пока системный плагин включён.

## Слайдер связанных товаров

Макеты блока: `grid`, `list`, `slider`. Слайдер использует карточки `grid` выбранного источника (компонент или плагин) и прежний контекст `product.related.grid`; настройки числа товаров и подбора общие. Отдельный `tmpl/slider.php` подключает общий preset `dharmashop.swiper` через WAM и собственный инициализатор `plg_system_dharmashoprelated.slider` с явной зависимостью от библиотеки. Повторной копии Swiper нет. При недоступном preset остаётся обычная сетка.

Нативные XML-поля появляются только при выборе слайдера: `slider_columns_xs/sm/md/lg/xl/xxl` (1–6, default 1/2/2/3/4/4), `slider_gap` (0–64 px, default 16), `slider_speed` (0–3000 мс, default 400), `slider_arrows/pagination` (default 1), `slider_loop/autoplay` (default 0), `slider_delay` (1000–60000 мс, default 5000, виден при autoplay). Количество колонок задаёт ширину карточки и при одном товаре. Автопрокрутка использует заданный интервал; системная настройка уменьшения анимации её не отключает. При наведении автопрокрутка ставится на паузу, после взаимодействия останавливается. Сервер ограничивает диапазоны. Сохраняемые настройки находятся в той же строке `related_blocks`.

Каждый экземпляр получает свои элементы управления, DOM-поиск ограничен обёрткой. Вложенные карусели картинок и элементы покупки исключены из перетаскивания внешнего слайдера. Учитываются скрытые UITab-панели, изменение размера, `joomla:updated` и `dharmashop:updated`; повторная инициализация исключена. Стрелки и пагинация оформлены штатными классами Bootstrap, без CSS плагина. При недостаточном количестве товаров управление скрывается; loop включается только когда товаров больше максимального числа видимых карточек, без пустых слайдов. Autoplay ставится на паузу при наведении и останавливается после взаимодействия/клавиатурного фокуса; системное уменьшение анимации отключает автопрокрутку. Ручное перелистывание использует заданную длительность перехода.
