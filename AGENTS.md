# AGENTS.md — вход для ИИ-ассистентов

Проект **Dharma Shop**: универсальный лёгкий e-commerce для Joomla 6+ (базовый компонент `com_dharmashop` + плагины, модули, отдельные компоненты). Пользователь говорит по-русски — **отвечайте по-русски**, документацию ведите по-русски.

## Что читать, в каком порядке

1. `docs/ROADMAP.md` — где мы сейчас, что делать дальше, журнал. **Начинайте отсюда.**
2. `docs/DECISIONS.md` — что решено (ПРИНЯТО не переспрашивать), что открыто.
3. `docs/ARCHITECTURE.md` — модель, схема БД, события, структура пакета, критерии скорости.
4. `docs/LAYOUTS.md` — единый реестр слотов и вариантов макетов витрины; согласуйте новые ID с ним.
5. `START_HERE.md` — исходное задание (часть сведений устарела, приоритет у DECISIONS.md: например, PHP ≥ 8.3, не 8.1).
6. `docs/SHORTCODES.md` — реестр подстановок `{область.имя}`, шорткодов и триггеров (событий); новое — сначала сюда.
7. `docs/DEVELOPMENT.md` — стенд, сборка, проверки; `docs/BENCHMARKS_NOTES.md` — результаты замеров скорости.

## Жёсткие правила

- **Самостоятельная реализация.** Не копируйте код, структуру файлов и имена RadicalMart. Уточнение пользователя 2026-10-07: разрешено читать его реализацию как справку, в том числе компонент полей и стандартный плагин; соседние сайты остаются только для чтения. Наша модель, схема, структура и события разрабатываются самостоятельно (`Dharma…`, `onDharmaShop*`, `#__dharmashop_*`). Исследование полей и предложение — `docs/FIELDS.md`; это не готовая реализация.
- **Админка — 100 % нативная Joomla:** Form XML (`subform`, `showon`, `uitab`, `searchtools`), штатные тулбар и сообщения; **своего JS/CSS в админке нет, кроме одобренных пользователем исключений — загрузчика изображений (C13: `media/com_dharmashop/js/uploader.js`, `css/uploader.css`) и поиска по настройкам магазина (C72: `media/com_dharmashop/js/settings-search.js`, только JS; оформление штатными классами Bootstrap, без CSS)**. Сайт — только классы Bootstrap 5, без отдельного CSS компонента и собственных inline-стилей (уточнение пользователя 2026-10-07); **исключение, одобренное пользователем (2026-10-08, C67): оформление боковой мини-корзины модуля — `mod_dharmashop_cart/media/css/minicart.css` (отключаемый, на переменных Bootstrap, классы `dharmaMiniCart*`);** переопределения в шаблоне `dharma_starter`, минимум JS.
- **Скорость:** цена, остаток, значения полей — в индексируемых столбцах, не в JSON; никаких `JSON_*`, `LIKE '%…%'`, `SELECT *` и больших `OFFSET` на путях витрины. Размер каталога не должен иметь значения (100 и 100 000+ товаров).
- **Одноязычный магазин:** столбца `language` нет; переводятся только языковые файлы.
- **Расширяемость:** не нужное каждому магазину — в плагины; в ядре события.
- **Макеты (C32):** страницы — `com_dharmashop/site/tmpl`, карточки — `files_dharmashop_layouts/layouts`, на сайте `layouts/components/dharmashop`; переопределения `html/layouts/components/dharmashop`. Первый переход устанавливать пакетом, чтобы сохранить старые макеты и зарегистрировать нативное файловое расширение. Подробнее `docs/LAYOUTS.md`.
- **Контейнер страницы.** Каждая страница сайта целиком оборачивается в `<div id="dharma_shop" class="dharma<Страница>">` (`dharmaCategory`, `dharmaBrand`, `dharmaProduct`…), блоки внутри — постоянные классы (`dharmaIntro`, `dharmaFulltext`); список — в `docs/LAYOUTS.md`.
- **Версия не меняется** (`0.1.0`) до релиза; не вводите автобампы версий.
- **Тестовый сайт — только https://test.test** (`/Volumes/Work/Server/www/test`, `DHARMA_SITE`). `dharmatest.test` — только чтение; массовые данные на нём не оставлять (замеры — на отдельной копии базы). Другие сайты не трогать.
- **Секреты** (логины, пароли, токены) — только переменные окружения, в репозиторий и документы не писать; в `configuration.php` Joomla напрямую не лезть (консольный запуск читает сам).
- **Внешние действия** (создание репозиториев, публикация, отправка) — только по прямому разрешению пользователя.
- Перед крупными шагами согласовывайте с пользователем; этап закрывает только он.

## Подводные камни Joomla 6 (из прошлых проектов)

- Joomla выводит `$option` из пространства имён — задавайте `protected $option` явно; у `HtmlView` 6.1 нет `getApplication()`.
- В CLI `live_site` попадает в маршруты (`/set/by/console/application`) — адрес берите из настроек.
- Пакет — только из вложенных zip, иначе тип не определится; пустые папки в манифесте ломают установку.
- `$query->from($table, $alias)` — второй параметр только для подзапросов; псевдоним: `->from($db->quoteName('#__t', 'a'))`.
- У драйвера БД нет `bind()`: параметры привязываются к объекту запроса (`$db->createQuery()`; для готового SQL — `Dharma\Component\DharmaShop\Administrator\Support\Sql`). Значения для `bind()` — переменные, не `readonly`-свойства и не выражения.
- `Table::store()` берёт `LOCK TABLES` (права/вложенные таблицы) → неявная фиксация: не оборачивайте сохранение карточки в транзакцию, проверяйте заранее и компенсируйте (см. ARCHITECTURE.md §5.13).
- Штатные макеты `joomla.edit.*` читают свойство `fields` вида; не оставляйте его заполненным насовсем (задавайте на время вывода блока).
- Не удаляйте строки из БД тестового сайта, пока пользователь может держать открытыми формы этих записей; чистите через интерфейс или предупредите.
- **Файлы в `images/` тестового сайта.** Пользователь параллельно загружает свои изображения. Удаляйте только файлы, созданные вами, по точным путям (из ответа загрузчика); никогда `rm -rf` по папке, `find … -delete` и подобное. Перед любой чисткой посмотрите список и сверьте с базой (`field_media`, `products.cover`, `params` категорий).
- Папка из манифеста должна быть и в пакете: проверяйте `ls administrator/components/com_dharmashop/` после **установки пакета**, а не после `dev/sync.sh` (он копирует всё и скрывает пропажи в манифесте).
- В правках файлов скриптами всегда проверяйте, что замена сработала (`assert`/сравнение), иначе правка молча не применится.
- Деинсталляция пакета удаляет категории компонента (всех типов) и таблицы; тестовые данные после переустановки создавайте заново.
- Проверка интерфейса во встроенном браузере: подставить серверную сессию из `curl` нельзя (куки HttpOnly), войдите через форму логина тестовым пользователем из `dev/.env` (разрешено для тестового сайта; пароль не повторять в ответах); после проверки сбросить размер окна (`resize_window` → `desktop`).
- Apache (Kettle) перезапускать после создания виртуального хоста; управление средой — через инструменты/скилл Kettle.
